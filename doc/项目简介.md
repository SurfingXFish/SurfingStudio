# SurfingStudio 项目简介

> 一个用 Rust 编写的、以 MIDI 为核心的音乐工作站（DAW）。
> 内置合成器与鼓机开箱即用，同时支持 VST3 / VST2 / VST1 插件、音频片段、自动化与实时渲染播放。

---

## 1. 项目定位

SurfingStudio 面向「快速写出并听到想法」的场景：

- **轻量**：单个原生可执行文件，不依赖 Electron、浏览器或外部音频服务。
- **以 MIDI 为中心**：编曲、钢琴卷帘、控制器自动化是主路径，音频片段作为补充。
- **开箱即用**：内置复音合成器与鼓机，新建工程即可开始写作，即使没有安装任何插件也能发声。
- **专业能力不打折**：支持 VST3 原生编辑器、VST2、插件状态持久化、实时渲染、离线导出 WAV。

项目当前版本为 `1.1.0a`，主要面向 Windows 桌面，自本版起可在安卓平板/手机上运行（NativeActivity + OpenGL ES，单窗口模式）；代码中对 macOS / Linux 也保留了 cpal 与 vst3-host 的跨平台路径。

---

## 2. 主要功能

### 2.1 编曲与轨道

- 多轨道编曲视图，轨道可展开为「控制器子轨 + 效果器链子轨」。
- 工程级输出布局可选择立体声（2.0）、环绕声（5.1）或 7.1；每条轨道可单独路由到前左/前右、中置/低频、环绕左/环绕右或后左/后右通道对。
- 轨道颜色、名称、音量、声像、静音、独奏、256 色片段调色板。
- 主输出（Master）固定置顶：主音量自动化、主效果器、独立高度拖拽。
- 时间标尺、循环区间（起/止小旗）、播放头、自动停止（内容结束后 2 小节）。
- 单击只选中，双击才进入编辑；避免误操作打断正在编辑的卷帘。

### 2.2 MIDI 编辑

- 钢琴卷帘：音高键盘、音阶高亮（13 种调式）、网格吸附、音符绘制/移动/缩放/框选/切割、量化、力度编辑。
- 每个轨道独立保存卷帘的缩放与滚动位置，切换轨道不会改变已打开卷帘的视图。
- **力度控制器**：钢琴卷帘右上角开关控制是否在底部显示；竖线对应音符起始位置、圆点高度即力度，圆点右侧还有一条与音符等长的横线，力度视图下也能直接看出音符时值；可直接在控制器内拖动修改并选中音符；左侧显示「力度」与当前读数。
- 顶部小节标尺可直接点击或拖动切换播放位置；工具条不再提供「删除音符」，删除音符使用 `Delete` / `Backspace`。
- 控制器卷帘：音量、声像、延音、弯音四类自动化；画笔、直线、平滑、擦除四种工具。力度不再作为自动化子轨。
- 延音为阶梯值，其余控制器为线性插值；音量以 50% 为 100%，100% 为 200%。

### 2.3 音频片段

- 拖入音频文件即在轨道上创建音频片段；支持 WAV、MP3、FLAC、AAC/M4A、OGG Vorbis、AIFF、CAF、ALAC，以及 MKV / WebM 容器中的音频轨；多声道素材按标准系数下混为立体声后进入轨道。拖到空白处自动新建音频轨道。
- 波形缩略图、片段裁剪/移动、跨轨拖动（带类型冲突保护）。
- 音频片段支持音量、声像与**弯音子轨动态变调**（弯音作为播放速率倍率，实时生效）。
- 同一轨道禁止混放 MIDI 与音频片段，避免子轨有效性歧义；不支持的子轨显示灰色并划掉。

### 2.4 插件

- **VST3**：扫描标准目录、读取 `moduleinfo.json`、原生编辑器窗口、参数面板、状态块持久化。
- **VST1 / VST2**：扫描 64 位 `.dll`、音频/MIDI 处理、通用参数面板、**独立原生编辑器窗口**、参数快照持久化。
- 插件浏览器支持按乐器/效果器过滤、厂商分组、名称搜索、自定义目录扫描；扫描先立即列出文件、再在后台识别单文件 `.vst3` 的名称、CID 与分类，乐器与效果器严格区分，无法识别的插件单独归入“未知”，扫描过程不再因加载插件而长时间卡顿。
- 主页插件页按**品牌**分组并默认展开：品牌标题显示乐器/效果器/未知数量，品牌内固定“乐器在上、效果器在下”；每条插件带类型、格式（VST3 / VST2）、分类与 MIDI/GUI 标签，右侧“详情”可展开路径、厂商、分类、能力与标识。
- 每次启动自动在后台做一次增量扫描：读取上次保存的插件记录与文件指纹，文件未变化就直接复用，只识别新增或变化的插件；缓存默认写入 `%LOCALAPPDATA%\SurfingStudio\plugin-cache.json`（可在设置 → 存储中更改缓存位置，不可写时回退 `%APPDATA%` 与系统临时目录），不需要每次启动重新加载全部插件。
- 内置常见 VST 厂商与插件资料库：扫描结果缺少厂商、分类或类型时离线补全（如 Serum、Kontakt、Pro-Q、Valhalla 等），不覆盖插件自带的元数据。
- 效果器链卷帘：横向卡片、拖拽排序、卡片主体直接显示 VST3 原生 GUI（自动内嵌并按卡片大小等比缩放），双击卡片顶部栏任意位置在独立窗口打开；指针在卷帘内（包括卡片顶部栏）时滚轮或 `Shift+滚轮` 左右滑动卡片；工具栏不再提供「添加效果器」，点击末尾「+」卡片直接打开选择窗；浮动卷帘与 VST2 仍使用独立编辑器窗口。
- 效果器选择窗口与乐器窗口同款布局：无系统标题栏，顶部为搜索与关闭图标；左侧种类为全部、收藏、EQ、动态、混响、延时、失真、调制、其他，右侧按厂商分组显示内置效果器与 VST 效果器，带「效果器 / 格式 / MIDI / GUI」徽章与「选择」按钮，可收藏。
- 每张效果器卡片右上角有启用开关：关闭时该效果器被旁路（实例、参数与状态保留），卡片显示“已停用”并隐藏内嵌界面，重新打开立即恢复处理；开关随工程保存。
- 内嵌 GUI 使用主窗口拥有的无边框顶层窗口覆盖在卡片上（不是 `WS_CHILD`），因此不会被 OpenGL 主窗口擦除；滚动、收起卷帘时按可见区域裁剪或隐藏。
- 大界面插件（如 Auto-Tune Pro，1140×680）默认缩放到卡片大小：支持内容缩放的插件按比例缩小，不支持时交给插件 `onSize` 自行贴合；打开时不再预先创建临时视图，减少卡顿。
- 选择插件时先停止后台类型识别（释放加载器锁），实例在 UI 线程创建：VST3 编辑器视图必须与实例同线程，否则 Auto-Tune 等插件打开 GUI 会死锁。打开已有工程时，VST 乐器实例由 UI 线程创建；后台线程创建的效果器实例会在首次打开 GUI 前、以及开始播放前在 UI 线程重建并保留状态。
- 插件窗口支持最小化/最大化/关闭；遇到会自行放大 GUI 的插件（如 Serum 2）会自动归一化到其声明的默认尺寸。
- 加载工程时，效果器运行时在常驻后台线程构建，界面保持响应并持续显示加载提示；VST 乐器实例则回到 UI 线程创建，但按 120 ms 时间片**分帧补载**：每帧只实例化少量插件，加载提示显示「正在加载插件…（已完成/总数）」，因此 Kontakt、Serum、VOCALOID 等重型插件工程也不会出现一次同步阻塞十余秒的「未响应」。补载期间乐器的实例、GUI 与析构始终在同一线程，VOCALOID 6 等插件不会因跨线程重建窗口而无法打开或崩溃。该线程同时维护插件创建的窗口与定时器（Pro-Q 动态 GUI 等）。
- 单文件 `.vst3`（没有 `moduleinfo.json`，如 Kontakt 8）不再因为可选的兼容映射查询失败而拒绝加载：`IPluginCompatibility::getCompatibilityJSON` 只把负返回码视为错误，返回 `0x1` 或空流时按「没有兼容映射」继续加载。
- 插件界面在附加到窗口之前不再强制读取尺寸：Kontakt 8 这类只允许 attach 后查询尺寸的插件可以正常打开 GUI（旧实现会卡住约 26 秒后报“Failed to get view size”）；窗口先以占位大小创建，附加后按插件尺寸调整，打开前也不再创建一次多余的临时视图，重型插件打开更快。
- 独立插件 GUI 以工程窗口为所有者创建：关闭工程窗口时插件界面随系统一起销毁，不会再留下单独停留的 GUI 窗口（浮动卷帘与内嵌卡片同样随工程关闭）。
- 默认在效果器卡片内显示厂商原生界面，也保留独立编辑器窗口（浮动卷帘、VST2、内嵌失败时自动回退）：Pro-Q、FabFilter 等插件的实时频谱/音高分析可以持续刷新；编辑器打开期间宿主持续把处理器参数反馈回写控制器。独立 VST3 编辑器每帧请求一次子窗口重绘，主窗口获得焦点时插件 GUI 仍持续变化。
- 正常关闭工程窗口时先按插件生命周期 detach 编辑器视图再销毁窗口，避免 VOCALOID 6 等 WPF 编辑器在实例释放阶段触发 `OnClosing` 的 `NullReferenceException`。
- 独立编辑器窗口打开后立即激活，并支持拖动窗口边框缩放：宿主把新的客户区尺寸转发给插件原生视图（如 FabFilter 的自适应界面），固定尺寸插件保持自身声明尺寸。
- VST1/VST2 编辑器使用标准子窗口承载，修复 VST1 空白。

### 2.5 内置乐器与原生效果器

- 内置乐器开箱即用，覆盖合成器、架子鼓与九种原生乐器：钢琴、木吉他、电吉他、失真电吉他、贝斯、小提琴、弦乐断奏、弦乐拨奏、弦乐联奏。
- 原生乐器全部支持工程内的四类自动化（音量、声像、延音与弯音），并按音符力度发声；延音踏板可挂住 Note Off，弯音连续改变音高。
- 音色实现参考网络上的物理建模与经典鼓机资料重建：
  - 拨弦类使用 Karplus-Strong 延迟线，加入拨弦位置梳状激励、按音高变化的环路低通、按基频换算的 T60 衰减，以及琴箱/拾音器共振（木吉他 105/205/410 Hz、电吉他 160/900/2800 Hz、失真吉他 110/700/3200 Hz、贝斯 62/125/400 Hz）。
  - 钢琴使用 6 个非谐分音（非谐系数随音高从约 3e-4 增长到 3e-2），叠加击弦噪声、同音群拍频与音板共振。
  - 弓弦类使用 3 个轻微失谐锯齿、5.2 Hz 颤音（0.35 秒渐入）、体腔共振（300/700/1600 Hz）与弓毛摩擦噪声。
  - 鼓机参考 808/909：底鼓为 160→50 Hz 连续相位扫频 + 高频点击；军鼓为 185/330 Hz 双音调 + 高通噪声；踩镲为六个非整数比方波合成的金属噪声；拍手为三段噪声爆发。
- 项目不内置第三方采样库：受许可证与体积限制，原生乐器采用无外部依赖的实时 DSP；需要更真实的采样音色时，可在乐器窗口加载 VST 乐器（如采样钢琴、Kontakt 等）。
- 检查器可切换原生乐器类型并调整音量、音色、起音、释放、延音、驱动与颤音。
- 效果器链同时支持 VST 插件与八种内置效果器：过载、失真、法兹、合唱、相位、延时、混响、压缩；两者可自由混排与排序。
- 内置效果器参数直接显示在效果器卡片中（ms / Hz / dB / 百分比），与插件效果共用启用开关与旁路行为。

### 2.6 工作流

- **多窗口工作区**：启动即打开主页窗口。从主页新建或打开工程时，主页窗口关闭并显示该工程的窗口；再次新建 / 打开会创建新的独立工程窗口，因此可以同时打开并编辑多个工程。再次打开同一个工程文件时只跳转（置前）已有窗口，不会重复打开。工程窗口中点击软件图标或“文件 → 主页”会打开独立的主页窗口，工程窗口保持打开并继续播放。
- **主页界面**：左侧为软件图标 + 名称 + 版本、分隔线、项目 / 模板 / 插件 / 提示菜单，最下方为设置图标；右侧按菜单显示内容。项目页展示**全部打开/保存过的工程**（不再只显示最近 12 条），按文件最近保存时间从新到旧排序，文件已删除的条目会自动移除；顶部搜索栏可快速过滤，右上角提供新建项目、打开项目与继续当前工程。每条项目右侧有下拉箭头，可展开查看工程信息（路径、大小、最近保存时间、BPM、拍号、轨道/片段/音符/插件数量）与历史版本，历史版本可直接打开查看。模板页展示 19 种主流音乐风格模板（流行、摇滚、嘻哈、Trap、House、Techno、Lo-fi、R&B、爵士、管弦、乡村、雷鬼、金属、民谣、蓝调、拉丁/Bossa、Synthwave、Ambient、Funk），支持搜索与家族筛选，单击卡片即可创建预填充工程；页面底部还列出 6 个 16 小节范例工程，对应的 `.sfsd` 文件位于 `examples/`。插件页按品牌分组（默认展开，乐器在上、效果器在下），可展开每条插件的详情。提示页汇总常用操作与快捷键。
- **独立设置窗口**：主页侧栏的设置图标打开独立的全局设置窗口，采用与工程窗口一致的深色自绘标题栏和左右两栏布局，左侧为 **界面、存储、音频、渲染、控制器、插件、快捷键、软件信息** 八类：界面调整全局缩放与 GPU 渲染加速（图形 API 可选自动 / DirectX 12 / Vulkan / OpenGL，重启后生效）；存储设置自动保存间隔、缓存位置、默认存储地址、自动备份开关与保留数量；音频选择音频系统（系统默认 / WASAPI / ASIO）、驱动或输出设备、采样率、缓冲、输出声道（跟随设备 / 立体声 / 5.1 / 7.1）与启用的输入设备；渲染选择是否使用 GPU 加速音频渲染与实时播放，并可选择 GPU、驱动与图形 API；控制器设置延迟偏移与启用的 MIDI 输入/输出设备；插件管理扫描目录并查看插件列表；快捷键可逐条录制、清除、重置或全部恢复默认；软件信息为只读汇总。设置保存在用户配置目录（Windows 为 `%APPDATA%\SurfingStudio\settings.json`），下次启动自动恢复；修改会立即同步到所有已打开的工程窗口。
- **GPU 加速**：界面渲染可选 wgpu（DirectX 12 / Vulkan）后端，启用时启动阶段自动确认该 API 有可用 GPU，失败会回退 OpenGL；音频侧可在设置 → 渲染中启用 GPU 加速。离线导出由所选 GPU 执行主总线软限幅；开启「实时播放使用 GPU 软限幅」后，实时播放也由 GPU 处理主总线终段，每块最多等待 1 ms，显卡未及时返回或设备不可用时立即回退 CPU 并在状态栏说明。
- **ASIO 支持**：音频页可直接选择本机注册的 ASIO 驱动（如 ASIO4ALL、声卡自带 ASIO），绕过 Windows 音频栈获得更低延迟；驱动不接受请求采样率时沿用其当前速率，启动失败会自动回退系统默认设备并在设置页显示原因。
- **历史版本**：开启自动备份后，每次保存前会把现有工程复制到工程目录的 `Backups` 文件夹（两次备份至少间隔 5 分钟），并按保留数量清理最旧版本；主页项目下拉即可查看并打开这些版本。
- **VST 插件设置**：在设置 → 插件中添加默认目录之外的插件文件夹；文件夹对话框在后台打开、不阻塞界面，添加后会立即重新扫描并入库；移除路径时同时清理该目录下的插件缓存记录。
- 多独立卷帘窗口：每个轨道最多一个，可同时打开多个；再次双击同一轨道只置顶，不重复创建。独立窗口带 8 点外边距，工具条标题与键盘不再贴住窗口边缘；窗口聚焦时 `Space` 可直接播放/暂停（不会与主窗口重复触发）。
- 长按并拖动卷帘空白处，或拖动工具条空白区域，可把卷帘「拖出」为独立窗口，窗口跟随鼠标。
- 撤销 / 重做（最多 64 步，按手势聚合）。
- 剪贴板：片段、音符、控制器点位、整条控制器子轨、单个效果器、整条效果器链。
- 工程保存为 `.sfsd`（SFS2 分块二进制容器，MessagePack 清单 + 独立插件状态块 + 波形峰值缓存），插件状态随工程保存。
- **独立导出窗口**：`Ctrl+E` / 文件菜单打开独立的「导出音频」窗口，可选择 WAV / AIFF、16/24-bit PCM 或 32-bit 浮点、44.1k ~ 192k 采样率、立体声 / 5.1 / 7.1（或跟随工程）、整个工程 / 循环区间、尾音长度、是否使用 GPU，并可输入或选择导出路径；渲染与写盘在后台线程完成，窗口显示进度与结果，不阻塞编辑。
- **自动保存**：工程已有文件路径且存在未保存修改时，按设置中的间隔（默认每分钟）自动写回原文件（不弹对话框），状态栏显示「已自动保存」；间隔可关闭，尚未保存过的工程不会自动创建文件。
- **崩溃恢复**：每个工程窗口都有一个独立的备份线程，持续把最新工程快照写入恢复文件。已保存的工程写在同目录 `<名称>.autosave.sfsd`；从未保存过的工程写在系统临时目录 `SurfingStudio\<工程名>-<窗口编号>.sfsd`，状态栏会提示一次。工程保存成功或关闭时选择「不保存」后，恢复文件会自动删除。
- **关闭前确认**：窗口中有未保存修改时，关闭窗口会弹出确认框，可选择「保存并关闭」「不保存」或「取消」；点击遮罩或按 Esc 视为取消。
- 关闭应用（在主页且没有工程窗口时关闭窗口）直接结束进程，跳过插件与音频设备的析构，避免退出卡死；关闭单个工程窗口时仍会关闭插件编辑器并限时等待后台保存（最多 3 秒）。插件抛出的未处理异常会直接终止进程，不再把进程留在 Windows 错误报告对话框里。
- **关闭工程窗口**：界面立即回到主页，不等待插件销毁。若工程含 VST 插件，插件实例会保留在内存中直到退出软件——VOCALOID VSTi、ACE Bridge 等插件在析构时会等待 UI 消息循环，直接销毁会卡死或崩溃；纯内置乐器的工程仍正常释放。日志中对应 `window.drop` 的 `phase=engine_retained`。
- **诊断日志**：每次启动都会在 `%LOCALAPPDATA%\SurfingStudio\logs` 写一个二进制 `.sflog`（v2 格式），记录启动、工程加载/保存、插件扫描/加载、工程同步、UI 卡顿、帧耗时聚合、进程内存/CPU/句柄/线程与退出原因；每 5 秒采样一次资源，便于分析卡死、崩溃与泄漏。日志可用 `surfing-studio.exe --decode-log <文件>` 解码为同名 `.txt`；只保留最近 20 个文件，格式与读法见 [日志规范](./日志规范.md)。
- **打开工程过程中关闭**：若工程仍在解析或插件仍在加载，窗口会取消本次关闭、显示“正在停止加载…”，等后台工作结束后自动关闭；还没开始的加载会直接放弃；超过 5 秒仍未结束则强制关闭，避免插件加载卡死窗口。这样不会在 VOCALOID 等插件初始化到一半时析构窗口，避免 `NullReferenceException` 与卡死。
- **播放中打开插件 GUI**：后台线程创建的效果器实例会在开始播放前预先重建到 UI 线程，插件处理缓冲也会复用；播放中打开 VST 乐器 / 效果器界面不再造成音频欠载或颗粒化输出。
- 兼容导入 SoundBug 工程（`.sndp` + `comp.dat`）：读取轨道、MIDI / 音频片段、速度、拍号与插件引用，并转换为本软件工程；导入后只能另存为 `.sfsd`，不会回写原格式。
- **可自定义快捷键**：所有快捷键都可在 设置 → 快捷键 中点击后按下新组合键修改，支持单条重置与全部恢复默认，冲突时会提示并拒绝；配置保存在 `%APPDATA%\SurfingStudio\settings.json`。默认包括：Space（当前工程窗口、插件编辑器与浮动卷帘均可播放/暂停）、Home/End、Ctrl+S/O/N/E、Ctrl+Z / Ctrl+Shift+Z / Ctrl+Y / Ctrl+Shift+V、Ctrl+C/V、Delete/Backspace、Esc、F1/F7/F8/F9、1/2/3 切换鼠标工具。
- **滑动快捷键**：方向键水平/垂直滑动当前编辑视图（编曲区、控制器或钢琴卷帘）；水平为 1 小节，垂直为 60 点或 2 个半音。效果器链仍支持滚轮 / Shift+滚轮左右滑动。
- **画笔快捷键**：控制器卷帘中按 4 循环切换画笔 → 直线 → 平滑 → 擦除，Ctrl+1 ~ Ctrl+4 可直接选择；1/2/3 仍用于选择/绘制/切割鼠标工具。
- **宿主窗口**：主页窗口与每个工程窗口都是自绘无边框窗口（不显示系统标题栏），采用 IntelliJ IDEA New UI 风格。工程窗口上层应用栏从左到右为软件图标、隐藏下拉栏、项目栏（工程名 + 未保存圆点，下拉可打开/新建工程），右侧从右到左为关闭、最大化、最小化；点击下拉栏后软件图标保留，左上角依次显示主页、文件、编辑、VST 插件（管理 VST 插件）、帮助与设置，下拉按钮与项目栏隐藏，点击其他区域或按 Esc 自动收起。主页按钮直接切到主页窗口，设置按钮直接打开设置窗口。主页视图下，应用栏左侧只显示软件图标与小字「欢迎使用SurfingStudio（当前系统用户名）」，不显示下拉栏和项目列表。工具栏只放走带、BPM/拍号、循环与鼠标模式，不再提供加轨按钮。拖动应用栏可移动窗口；窗口最大化时拖动应用栏会先还原再跟随鼠标移动；双击应用栏切换最大化，窗口四边与四角可缩放。关闭工程窗口只关闭该工程；关闭最后一个工程窗口会回到主页。
- **乐器窗口**：单击轨道列表中的乐器名称打开。窗口不显示系统标题栏，首行即顶栏（标题、搜索与关闭图标）。左侧为乐器种类（全部、收藏、钢琴、木吉他、电吉他、弦乐、桥接器、其他），右侧按厂商列出内置乐器与 VST 乐器插件，每行显示名称、描述、乐器 / 格式 / MIDI / GUI 徽章与“选择”按钮；可收藏乐器，选择后立即替换该轨道乐器。桥接器专门收纳 ACE Studio、VOCALOID、XStudio 等外部合成软件的桥接插件；木吉他/电吉他按插件型号区分。
- **轨道列表**：末尾固定一行「+ 添加 MIDI 轨道」，点击后直接创建默认 MIDI 合成器轨道，不再询问轨道类型。
- 全局界面统一为 IDEA New UI 风格：编曲区、钢琴卷帘、控制器、检查器、效果器链、插件浏览器、帮助与对话框共用中性灰表面、单一蓝色强调色、细边框与圆角控件；播放头与选中项使用 IDEA 蓝。

### 2.7 安卓（平板 / 手机）

- 同一套 Rust 代码通过**平台运行时**（类 JVM：统一内部 API + 各系统后端）在安卓上运行：界面、引擎、内置乐器与效果器、工程读写完全复用，安卓只是换了一套底层实现。
- 入口为 NativeActivity（`android_main`），渲染走 OpenGL ES（eframe `glow`），音频走系统 AAudio / OpenSL ES（cpal），MIDI 走 Android AMidi（USB / BLE MIDI 设备）。
- **单窗口模式**：没有第二个 OS 窗口，主页与工程都画在同一个窗口里；点击软件图标打开主页，工程继续在后台播放，「继续当前工程」即可返回。
- 浮动卷帘自动改为底部编辑区；设置改为窗口内模态面板；应用栏不再拖动窗口。
- **保存不需要文件对话框**：点「文件 → 保存」直接写入应用私有目录 `files/Projects/<工程名>.sfsd`，状态栏显示完整路径；导出 WAV 同样落在该目录。主页项目列表可再次打开这些工程。
- **与公共目录互转用系统文件选择器（SAF）**：「打开项目…」弹出系统文件选择器，选中后复制到 `files/Imported/` 再打开；「工程副本保存到公共目录…」「WAV 导出到公共目录…」让你在下载/文档等公共目录里另存一份，可被其他应用读取。
- **触屏手势**：编曲区与钢琴卷帘支持双指捏合缩放（以捏合中心为锚点，捏合期间暂停单指拖动）。
- 配置文件、插件缓存与诊断日志都写在应用沙箱内（`/data/user/0/<包名>/files`），不需要存储权限。
- 安卓不加载 VST 插件（移动端没有 VST 生态），因此「VST 插件」菜单、主页插件页与设置里的插件分类都不显示；内置乐器与内置效果器不受影响。
- 构建与安装：`platforms/android/build.ps1`（默认 `arm64-v8a`，`-Abi x86_64` 用于模拟器）会交叉编译、编译 `MainActivity`（`javac` + `d8`）并用 aapt2/zipalign/apksigner 打包到 `target/android/SurfingStudio-<abi>.apk`；加 `-Install` / `-Run` 可直接安装并启动。

## 3. 技术优势

### 3.1 实时渲染：编辑即生效

项目不再生成任何片段预渲染缓存，播放时由音频回调直接运行乐器与效果器：

- **单一渲染路径**：MIDI 音符 → 内置乐器 / VST 乐器 → 音频片段 → 插入效果器 → 音量/声像 → 工程输出通道对 → 主效果器 → 主音量 → 软限幅。
- **音符事件预计算**：工程同步时把每条轨道的音符展开成按 beat 排序的 Note On / Note Off 事件；音频回调只推进游标，不再每个 block 扫描全部片段与音符。
- **事件表按需重建**：只有片段时间、长度或音符内容变化（由片段 revision 与片段签名判定）才重新排序音符事件；拖动音量、声像或修改插件参数不会触发排序。
- **零分包等待**：播放从当前播放头立即开始，不存在「缓存未就绪」的暂停与恢复，也不需要等待任何后台渲染线程。
- **编辑实时生效**：修改音符、控制器、乐器或效果器参数后，下一次工程同步即可听到变化；插件 GUI 中的参数改动本身就在实时实例上生效。
- **音频片段实时流式读取**：按源偏移与弯音倍率推进源游标，因此弯音可以连续改变播放速率。
- **离线导出独立**：导出音频时使用独立的实时渲染引擎，关闭循环与自动停止，按所选范围（整个工程 / 循环区间）与尾音长度渲染；可选择立体声或环绕声布局与 16/24-bit PCM、32-bit 浮点。可在导出窗口或设置 → 渲染中启用 GPU 加速，由所选 GPU 执行主总线软限幅（失败自动回退 CPU）。

### 3.2 插件兼容性处理

- VST3 与 VST2 统一封装为 `PluginRuntime`，引擎层无需关心格式差异。
- VST3 扫描优先只读元数据（`Contents` 或 `Contents/Resources` 下的 `moduleinfo.json`）；只有缺少元数据（含 Windows 单文件 `.vst3`）时才读取模块的工厂类元数据，不创建插件实例，避免触发授权/启动窗口。
- 本地 patch 了 `vst3-host`：修正插件编辑器内容缩放与窗口尺寸；对 Serum 2 这类「附加后把 GUI 放大 4 倍」的插件，按插件自己声明的默认尺寸做归一化（实测 1190×740 → 4748×2952 → 1189×739）；编辑器窗口打开后立即激活，并把拖动边框产生的新尺寸转发给插件（`IPlugView::onSize`），FabFilter 等自适应界面可以正常缩放。
- 插件 GUI 参数变化会被轮询检测（拖动手势日志 + 停止时全量对比）；实时渲染下参数直接发声，仅用于更新界面显示与保存状态。
- 独立编辑器打开期间主窗口保持 16 ms 重绘，并有独立的 UI 心跳线程每 16 ms 唤醒消息循环：即使主窗口被编辑器覆盖或未获得焦点，Pro-Q / FabFilter 的频谱也会持续刷新，不会停在最后一帧。

### 3.3 实时安全与低卡顿

- 音频回调统一使用 `try_lock`：UI 线程繁忙时宁可在回调内做短淡出/淡入，也不阻塞音频线程，减少爆音与破音。
- **试听不漏音**：键盘、虚拟键盘与 MIDI 触发的试听音符先进入待发送队列，引擎锁被音频回调（尤其是重型 VST 插件）占用时会在下一帧按顺序补发；同一音高连续触发会先补 Note Off 再发 Note On，既不会漏掉连续音符，也不会留下挂音。
- UI 的传输/电平状态每帧只做一次 `try_lock`，统一缓存到 `ui_*` 快照；编曲区、状态栏等读取这些状态的面板不再分别抢引擎锁。插件参数面板只在需要时短暂加锁。
- 音频回调内的轨道运行时按工程顺序与 `Project::tracks` 索引对齐，避免在每个 block 里按 id 线性查找（原实现的 O(n²) 热点）。
- 工程同步时预计算 `any_solo`、自动停止位置、每轨 `has_audio_clips` 与音符事件表，播放回调不再反复扫描工程。
- 播放中限制工程同步频率（约 60 ms），参数轮询限制为 5 Hz。
- 音频回调内复用 scratch buffer，音符事件游标只做顺序推进，减少实时线程分配与扫描。
- 主输出使用软限幅（0.95 以下完全线性），只在播放输出阶段应用一次。
- **实时 GPU 加速**：设置 → 渲染可开启实时 GPU 软限幅；宿主用常驻设备与管线处理主总线终段，每块最多等待 1 ms，超时立即改用 CPU，音频线程不会无限期等待显卡。

### 3.4 交互细节

- 卷帘工具条「整条可拖、控件除外」：只排除按钮、滑块、下拉框等真实控件矩形，其余空白区域都能拖出窗口。
- 独立卷帘窗口是真正的 OS 多视口（egui viewport），支持多窗口、置顶、最小化/最大化、跨屏移动。
- 音频与 MIDI 的类型互斥、子轨有效性提示、粘贴覆盖确认等规则，减少「看起来能点但实际无效」的状态。

### 3.5 工程可维护性

- 采用标准的 Rust「库 + 薄二进制」结构：`src/lib.rs` 声明全部模块，`src/main.rs` 只负责创建 eframe 窗口，逻辑可在测试中直接引用 `surfing_studio` 库。
- 数据模型与 UI 解耦：`core/model/*` 只描述工程，`audio` 负责发声与实时渲染，`plugin` 负责宿主适配，`ui` 负责绘制与交互。
- 应用状态机按职责拆分为 `app/{state,history,transport,edit,files,plugins,rolls,input,panels,dialog}.rs`；各子模块通过 `impl SurfingApp` 追加方法，保持单一所有权模型。
- 引擎按职责拆分为 `audio/engine/{mod,plugins,render}.rs`；内置乐器拆分为 `audio/synth/{poly,drums,modeled}.rs`；GPU 渲染拆分为 `audio/gpu/{mod,backends/wgpu_compute}.rs`。
- 音乐模板与范例工程集中在 `core/model/template.rs`：模板是纯数据（调性、BPM、和弦进行、鼓组格子、Bass/和声/主旋律动机），展开为 `Project` 后可直接播放与保存。
- 多实现领域统一采用「运行时 + 后端」：工程格式 `ProjectRuntime`、插件格式 `PluginHost`、音频文件 `AudioRuntime`、GPU 渲染 `GpuRuntime`；应用层只调用运行时，格式后端独立成文件夹。
- 插件宿主拆分为 `plugin/{backend,host,runtime,scan}.rs` 与 `plugin/backends/{vst3,vst2}.rs`。
- 工程文件是 SFS2 分块容器：清单用 MessagePack 存储，插件状态与波形峰值分别放在独立二进制块中，支持校验与按需读取。
- 诊断日志独立成 `diag` 模块：`.sflog` v2 二进制帧（固定 32 字节记录头 + 变长负载 + CRC32）、里程碑耗时区间、进程资源采样、UI 卡死/慢帧看门狗与崩溃记录，分析卡死不需要调试器；退出统一走 `diag::request_exit`，写尾帧后直接终止进程。
- 关键路径有单元测试（工程序列化、实时渲染、音符事件预计算、自动停止、WAV 导出、传输位置格式化等）。

## 5. 快速开始

### 5.1 环境要求

- Rust stable 工具链（edition 2021）。
- Windows 10/11（主要验证平台）；需要可用的音频输出设备。
- 可选：已安装的 VST3 / VST2 插件，用于插件功能。

### 5.2 运行

```bash
cargo run
```

启动后进入主页窗口；点击“新建项目”或“打开项目”会打开一个独立的工程窗口（主页自动隐藏），按空格即可播放。再次点击“新建项目”可继续打开新的工程窗口，各工程之间互不影响。

打开工程（`Ctrl+O`）支持 `.sfsd` 与本软件兼容导入的 SoundBug `.sndp`。SoundBug 工程导入后不会保留原路径，首次保存会要求另存为 `.sfsd`。

```bash
cargo build --release
cargo test
```

需要真实插件的测试默认被 `#[ignore]` 标记，可用：

```bash
cargo test -- --ignored
```

VST2 测试需要一个本地 fixture DLL：

### 5.4 插件目录

- VST3：`C:\Program Files\Common Files\VST3`、`C:\Program Files (x86)\Common Files\VST3`、`%LOCALAPPDATA%\Programs\Common\VST3` 等。
- VST2：`VSTPlugins`、`Steinberg\VstPlugins`、`VST`、`Common Files\VST2` 等常见目录，也可在插件浏览器中手动选择文件夹或单个 DLL。

### 5.5 安卓构建与安装

需要 Rust 安卓目标（`rustup target add aarch64-linux-android`）、Android NDK 与一个带 `javac` 的 JDK（`JAVA_HOME`，脚本另会在 `C:\Program Files\Zulu\zulu-21` 兜底）；脚本会自行设置 NDK 的 clang 链接器：

```powershell
$env:JAVA_HOME = 'C:\Program Files\Java\jdk-21'   # javac / d8 与 apksigner 都需要 JDK
powershell -ExecutionPolicy Bypass -File platforms\android\build.ps1 -Abi arm64-v8a -Install -Run
```

- 打包分六步：`cargo build` → `aapt2 link` → `javac` + `d8`（编译 `MainActivity`，负责 SAF 结果回传）→ 写入 `.so` 与 `classes.dex` → `zipalign` → `apksigner`。
- 模拟器（x86_64）用 `-Abi x86_64`。
- 产物在 `target/android/SurfingStudio-<abi>.apk`，用调试签名（`~/.android/debug.keystore`）。
- 部分国产系统（MIUI / HyperOS）默认禁止 `adb install`，需要在 开发者选项 里打开「USB 调试（安全设置）」/「USB 安装」，否则会返回 `INSTALL_FAILED_USER_RESTRICTED`。
- SAF 排障：`adb logcat -s SurfingStudioSaf` 会打印「请求已发起 / 回调已入队 / 打开 fd / 复制完成」各阶段。

## 7. 已知限制

- 音频导入支持 WAV / MP3 / FLAC / AAC·M4A / OGG Vorbis / AIFF / CAF / ALAC 与 MKV/WebM 音频轨；WMA、APE、Opus 等尚未接入，需要先转码。多声道素材导入时按标准系数下混为立体声，片段内部仍为立体声。
- 内置原生乐器为实时 DSP 建模，不附带第三方采样库；需要采样级真实度时请加载 VST 乐器。模板与范例工程同样只使用内置乐器，因此不需要安装任何插件即可播放。
- 原生 GUI 内嵌仅支持 Windows 与 VST3；浮动效果器卷帘、VST1/VST2 仍使用独立编辑器窗口。内嵌窗口由宿主卡片决定尺寸，固定尺寸插件会在卡片内留出空白。
- 工程支持立体声 / 5.1 / 7.1 输出与每轨通道对路由；主效果器固定 2 in / 2 out，环绕声布局下只处理前左/前右，其余通道直通。侧链与逐声道独立效果链尚未提供；设备声道数不足时自动按 ITU 系数下混为立体声。
- ASIO 仅支持 Windows；驱动采样格式支持 16/24/32 位整数、32/64 位浮点与 32 位容器左对齐（Int32LSB16/18/20/24），其它格式会回退系统默认设备；ASIO 输入通道与音频输入设备尚未接入录音，输入设备选择只记录启用状态。
- 控制器延迟偏移与 MIDI 输出端口目前只做持久化记录，尚未参与录音补偿或外部同步。
- 插件参数自动化写入 DAW 自动化轨尚未实现；当前自动化面向音量、声像、延音、弯音四类内置控制器（力度按音符在钢琴卷帘中编辑）。
- GPU 音频加速用于离线导出与实时主总线终段；实时路径每块最多等待 1 ms，超时或设备不可用时自动回退 CPU，状态栏会说明一次。实时 GPU 只覆盖主总线软限幅，乐器与效果器仍由 CPU 渲染。
- GPU 界面渲染（wgpu / DirectX 12 / Vulkan）为实验性路径，修改后需重启软件；驱动缺失时保持 OpenGL。
- 主要验证平台为 Windows；macOS / Linux 具备代码路径但未做完整产品级验证。
- 安卓为单窗口：同时只能打开一个工程（再开会被拒绝并提示）；浮动卷帘、独立设置窗口、拖出卷帘手势不可用，分别改用底部编辑区、窗口内模态面板与不响应。
- 安卓保存与导出默认写入应用私有目录 `files/Projects`；与公共目录（下载/文档）互转通过系统文件选择器（SAF）：导入复制到 `files/Imported/` 后打开，导出在你选定的目录新建文件。
- 安卓导入按 MIME 过滤：工程文件没有注册的 MIME，选择器会接受全部文件，再由加载器校验格式。
- 安卓不加载 VST3 / VST2 插件（移动端无对应生态），「VST 插件」菜单、插件页与插件相关设置都不显示；内置乐器与内置效果器完整可用。
- 安卓界面为桌面布局，触控可完成基本操作（编曲区与钢琴卷帘支持双指捏合缩放），但尚未针对手机做紧凑布局与更完整的手势适配。
- 关闭含 VST 插件的工程窗口后，该工程的插件实例保留到退出软件（避免插件析构死锁/崩溃），内存不会立即释放；反复打开并关闭同一重插件工程会累积占用。
- SoundBug 工程导入会保留插件状态块（VST3 可在加载后恢复），但不还原内置混响等 SoundBug 专属效果；插件缺失时会回退到内置乐器并给出提示，音频片段按原媒体路径引用。

## 8. 适合谁

- 想用 Rust 学习/实践「实时音频 + 插件宿主 + 即时模式 GUI」的开发者。
- 需要一个小巧、启动快、以 MIDI 写作为主的个人工作站。
- 希望在源码层面定制音轨、卷帘、插件窗口行为的研究者或爱好者。
