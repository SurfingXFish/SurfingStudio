# SurfingStudio 日志规范

> 本文档说明 `.sflog` **v2 二进制日志**的文件布局、记录编码、事件目录与判读方法。
> 日志优先保证信息密度与写入效率：固定头 + 变长负载 + 每记录 CRC32，不做文本排版。
> 格式的唯一事实来源是 `src/diag/`（`mod.rs` / `format.rs` / `decode.rs`）；本文档必须与代码同步。

相关文档：[技术文档](./技术文档.md) · [关键常量](./关键常量.md) · [框架工作流](./框架工作流.md) · [代码规范](./代码规范.md)

---

## 1. 用途与位置

- 每次启动新建一个日志文件，记录启动、工程加载/保存、插件扫描/加载、引擎同步、UI 卡顿、帧耗时聚合、进程资源与退出。
- 只由 UI 线程、后台工作线程与看门狗线程写入；**实时音频回调内禁止写日志**（见 [代码规范](./代码规范.md) 5.2）。
- 默认目录：

| 平台 | 目录 |
| --- | --- |
| Windows | `%LOCALAPPDATA%\SurfingStudio\logs` |
| 其他 | 系统临时目录下的 `SurfingStudio/logs` |

- 文件名：`surfing-YYYYMMDD-HHmmss-p<PID>.sflog`（本地时间）。
- 启动时只保留**最近 20 个**日志文件。
- 文件是**二进制**，不能直接用记事本阅读；用内置解码器导出文本（见第 6 节）。
- 所有整数均为**小端序**（little-endian）。

## 2. 文件布局

```text
┌──────────────────────────────┐
│ 文件头固定前缀（24 字节）      │
├──────────────────────────────┤
│ 文件头文本（UTF-8，长度由前缀给出）│
├──────────────────────────────┤
│ 记录 1（32 字节头 + 负载）     │
│ 记录 2 …                      │
└──────────────────────────────┘
```

### 2.1 文件头固定前缀（24 字节）

| 偏移 | 长度 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | 4 | `magic` | `0x474C4653`，小端字节为 `SFLG` |
| 4 | 2 | `version` | 当前为 `2` |
| 6 | 2 | `flags` | bit0 = 小端序（当前恒为 `1`） |
| 8 | 4 | `header_len` | 紧随其后的头文本字节数 |
| 12 | 4 | `pid` | 进程 id |
| 16 | 8 | `start_unix_us` | 进程启动的 Unix 时间（微秒） |
| 24 | `header_len` | `header_text` | `key=value` 行，UTF-8，`\n` 分隔 |

`header_text` 当前包含：`app_version`、`os`、`arch`、`build`、`started`（本地时间）、`log_path`。

### 2.2 记录头（32 字节）

| 偏移 | 长度 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | 1 | `kind` | 记录类型：`1` 事件、`2` 尾帧、`3` 资源采样 |
| 1 | 1 | `level` | `0` TRACE、`1` DEBUG、`2` INFO、`3` WARN、`4` ERROR、`5` FATAL |
| 2 | 2 | `flags` | 保留，当前为 0 |
| 4 | 4 | `seq` | 记录序号，从 1 开始递增；缺号说明写入失败 |
| 8 | 4 | `thread_id` | 写入线程的 Win32 线程 id |
| 12 | 8 | `t_us` | 相对进程启动的微秒数 |
| 20 | 4 | `frame` | 写入时的 UI 帧计数（0 表示尚无帧） |
| 24 | 4 | `payload_len` | 负载字节数 |
| 28 | 4 | `crc32` | 负载的 CRC32（IEEE，`crc32fast`） |

- 记录之间无填充、无对齐要求。
- `crc32` 只覆盖负载，不覆盖记录头；读取工具应校验并标记损坏记录。

## 3. 编码原语

### 3.1 变长整数（LEB128）

- 无符号 64 位，7 位一组，低位在前；最高位为 1 表示后续还有字节。
- 值 `0..=127` 占 1 字节，`128..=16383` 占 2 字节，依此类推，最大 10 字节。
- 用于字符串长度、字段数量、事件耗时。

### 3.2 字符串

```text
varint(len) + len 个 UTF-8 字节
```

- 不写结尾 `\0`，不做转义；任意 UTF-8（含中文、换行）都可直接存储。
- 解码时长度非法或 UTF-8 无效应视为记录损坏。

### 3.3 特殊值

- 事件耗时缺省：写入 `u64::MAX`（即 `18446744073709551615`）。
- 资源采样缺省：整条记录不写（采样失败时）。

## 4. 负载布局

### 4.1 `kind = 1` 事件

```text
str    scope          例：app.project
str    event          例：project.load
varint dur_us         u64::MAX 表示无耗时
varint field_count
repeat field_count:
    str     key
    u8      value_type   （当前只有 3 = UTF-8 字符串）
    str     value        （value_type = 3 时）
```

- 字段顺序即写入顺序；同一 key 可重复。
- 新增值类型时递增 `FORMAT_VERSION` 并更新本文档；解码器遇到未知类型应跳过或标记。

### 4.2 `kind = 2` 尾帧

```text
str reason
```

- 正常退出写 `home_closed` / `on_exit` / `run_native_returned`；崩溃写 `unhandled_exception` / `exit_timeout`。
- **尾帧之后不再有任何记录**。文件缺少尾帧或记录在末尾截断，即表示非正常退出。

### 4.3 `kind = 3` 进程资源采样（40 字节）

| 偏移 | 长度 | 字段 | 单位 | 说明 |
| --- | --- | --- | --- | --- |
| 0 | 8 | `working_set` | 字节 | 当前工作集 |
| 8 | 8 | `peak_working_set` | 字节 | 峰值工作集 |
| 16 | 8 | `private_bytes` | 字节 | 提交/私有字节（`PagefileUsage`） |
| 24 | 8 | `cpu_100ns` | 100 ns | 进程累计 CPU（内核 + 用户） |
| 32 | 4 | `handles` | 个 | 句柄数 |
| 36 | 4 | `threads` | 个 | 线程数 |

- 默认每 5 秒采样一次（见 [关键常量](./关键常量.md)），卡死上报时额外采样一次。

## 5. 记录内容一览

每条记录自动带有：`seq`、`level`、`thread_id`、`t_us`、`frame`、`crc32`。事件负载再带 `scope` / `event` / 可选 `dur_us` / 键值字段。

### 5.1 `app.boot`（启动）

| 事件 | 级别 | 字段 | 含义 |
| --- | --- | --- | --- |
| `process.start` | INFO | `pid` `version` `os` `arch` `build` | 进程与版本信息 |
| `log.ready` | INFO | `path` | 日志文件已就绪 |
| `settings.load` | INFO | `dur_us` | 读取 `settings.json` 的耗时 |
| `plugin_cache.load` | INFO | `plugins` `dur_us` | 读取插件缓存的耗时与条数 |
| `audio.open` | INFO | `phase` `status` `detail` | 打开音频设备：`status=ok/failed` |
| `shared.init` | INFO | `status` `dur_us` | 共享服务（设置+缓存+音频+MIDI）整体耗时 |

### 5.2 `app.shell` / `app.window`（窗口与退出）

| 事件 | 级别 | 字段 | 含义 |
| --- | --- | --- | --- |
| `window.root.create` | INFO | `phase` `status` `dur_us` | 根窗口创建 |
| `window.create` | INFO | `id` `role` `title` | 每个 `SurfingApp` 窗口创建；`role=home/studio` |
| `window.close.request` | INFO | `root` `projects` | 收到关闭请求 |
| `window.close.project` | INFO | `home_viewport` `projects` | 关闭根工程并回到主页 |
| `window.promote_project` | INFO | `window_id` `remaining` | 把工程提升为根窗口 |
| `window.exit` | INFO | `reason` | 进入退出流程 |
| `window.drop` | INFO / WARN | `phase` `id` `plugin_instruments` `plugin_effects` `strong_count` `waited_ms` `editors` `plugins` `reason` `body_ms` | 窗口析构分阶段记录；`phase=engine_retained` 表示工程含插件实例、引擎保留至进程结束 |
| `process.exit` | INFO | `reason` `uptime_ms` | 写尾帧前最后一条事件 |
| `process.exit.timeout` | FATAL | `reason` `phase` | 已请求退出但进程仍存活，看门狗强制结束 |

（`thread_id` 已在每条记录头中，`window.drop` 不重复写 `tid`。）

### 5.3 `app.project`（工程）

| 事件 | 级别 | 字段 | 含义 |
| --- | --- | --- | --- |
| `project.load` | INFO | `phase=begin` `path` | 发起后台加载 |
| `project.plugins` | INFO | `count` `list` | 工程插件实例清单（名称 + 路径） |
| `project.load.worker` | INFO | `status` `path` `error` `dur_us` | 后台解析耗时 |
| `project.apply` | INFO | `phase` `path` `imported` `tracks` `clips` `warnings` `dur_us` | UI 线程应用工程会话 |
| `project.save.worker` | INFO | `status` `path` `autosave` `error` `dur_us` | 后台写盘耗时 |
| `project.backup` | INFO | `status` `error` `dur_us` | 历史版本复制耗时 |
| `project.export_wav` | INFO | `path` `status` `warning` `error` `dur_us` | 同步离线导出耗时 |
| `project.export_window` | INFO | `path` `status` `error` `dur_us` | 独立导出窗口的逐帧渲染耗时；`project.export_window.write` 为随后的编码写盘耗时 |

### 5.4 `app.plugin`（插件）

| 事件 | 级别 | 字段 | 含义 |
| --- | --- | --- | --- |
| `plugin.scan` | INFO | `phase=begin` `mode` `cached` | 发起扫描 |
| `plugin.scan.worker` | INFO | `status` `mode` `plugins` `reused` `error` `dur_us` | 后台扫描耗时与结果 |
| `plugin.apply` | INFO | `phase` `target` `format` `name` `path` `status` | 插件写入槽位 |
| `plugin.editor.open` | INFO | `format` `track_id` `status` `size` `error` `dur_us` | 创建原生编辑器耗时；`size` 为打开后插件报告的编辑器尺寸（物理像素，未知为 `unknown`） |
| `plugin.shutdown` | WARN | `status` `error` | 模块 `plugin.runtime`；关闭工程时 `IComponent::terminate` 失败（外部应用窗口可能残留） |

### 5.5 `app.engine`（引擎同步）

| 事件 | 级别 | 字段 | 含义 |
| --- | --- | --- | --- |
| `engine.sync` | WARN | `status` `tracks` `warnings` `dur_us` | UI 线程同步超过阈值时才记录 |
| `engine.sync.background` | INFO | `phase` `tracks` `status` `warnings` `wait_ms` `dur_us` | 后台同步线程：`dur_us` 为真实同步耗时，`wait_ms` 为 UI 等待 |
| `engine.sync.instruments` | INFO | `phase` `plugins` `warnings` `dur_us` | 加载工程后分帧补载 VST 乐器：`phase=begin` 记录总数，`phase=end` 记录总数、警告数与整体耗时 |

### 5.6 `app.ui`（UI 健康）

| 事件 | 级别 | 字段 | 含义 |
| --- | --- | --- | --- |
| `ui.frames` | INFO | `frames` `avg_us` `max_us` `phase` | 每 600 帧一次的帧耗时聚合 |
| `ui.frame.slow` | WARN | `dur_ms` `phase` `frames` | 单帧 ≥ 120 ms（1 秒最多一条） |
| `ui.stall` | WARN | `stall_ms` `phase` `frames` | UI 线程 ≥ 3 s 无新帧（15 秒内不重复） |
| `ui.resume` | INFO | `stall_ms` `phase` | 卡死恢复 |

`phase` 取值：`boot`、`ui.frame`、`ui.poll`、`ui.paint`、`plugin.editors`、`plugin.editor`、`engine.sync`、`project.export`。

### 5.7 崩溃

| 事件 | 级别 | 字段 | 含义 |
| --- | --- | --- | --- |
| `panic` | FATAL | `message` `location` | Rust panic（`文件:行:列`） |
| `unhandled_exception` | FATAL | `exception_code` `phase` | Windows 未处理异常，随后进程结束 |

除上表事件外，还有 `resource` 记录（第 4.3 节）与尾帧（第 4.2 节）。

## 6. 解码与阅读

日志是二进制，使用内置解码器导出文本：

```powershell
# 在日志同目录生成 <同名>.txt（成功退出码 0，失败 2）
surfing-studio.exe --decode-log "C:\Users\<用户>\AppData\Local\SurfingStudio\logs\surfing-20261024-224046-p27000.sflog"
```

解码文本示例：

```text
# SFLG v2 pid=27000 start_unix_us=1792852846489511
# app_version=0.1.0
# build=debug
000001        0.783ms INFO  tid=15472  frame=0       app.boot/process.start  pid=27000  version=0.1.0
000002       26.316ms INFO  tid=15472  frame=0       resource ws=9.5MiB peak=9.5MiB private=1.9MiB cpu=0.062s handles=136 threads=4
000013      991.847ms INFO  tid=15472  frame=0       app.shell/window.root.create  dur=370.420ms  status=ok  phase=end
000019     7900.359ms INFO  tid=15472  frame=118     # end reason=home_closed
```

- 第一列序号、第二列相对时间、第三列级别，随后是 `tid` 与 `frame`。
- 事件行格式为 `scope/event`，其后是 `dur=`（若有）与键值字段。
- 资源行以 `resource` 开头；尾帧以 `# end reason=` 开头。
- 出现 `!crc` 表示该记录负载校验失败；出现 `# 截断的…` 表示文件尾部不完整。

其它工具可直接按第 2~4 节读取二进制；`src/diag/decode.rs` 是一份完整参考实现。

## 7. 卡死与崩溃分析流程

1. **先解码**：`--decode-log` 生成 `.txt`。
2. **确认是否正常结束**：最后一行是否为 `# end reason=…`；没有则按崩溃/强制结束处理。
3. **找最后一条事件**：它就是卡死/崩溃前执行的最后一步。
4. **看级别**：`FATAL` → `ERROR` → `WARN`。
5. **看 `ui.stall` / `ui.frame.slow` 的 `phase`**：
   - `plugin.editor`：插件创建界面卡住；
   - `engine.sync`：同步/乐器插件实例化卡住；
   - `project.export`：离线导出卡住；
   - `ui.paint`：绘制阶段卡住。
6. **找没有配对 `phase=end` 的 `phase=begin`**：区间停在那里。
7. **对比 `resource` 记录**：内存持续增长（泄漏）、句柄/线程数暴涨（插件创建后未释放）。
8. **按 `dur_us` 排序**：定位最慢的区间。

### 7.1 常见现象对照

| 现象 | 日志特征 | 常见原因 |
| --- | --- | --- |
| 启动很慢 | `window.root.create` / `audio.open` 的 `dur` 很大 | ASIO 驱动初始化慢、插件目录扫描 |
| 打开工程卡住 | `project.load.worker` 有 begin 无 end | 工程文件损坏/过大、解码阻塞 |
| 打开工程后界面不响应 | `engine.sync.background` 的 `wait_ms` 很大；或 `engine.sync.instruments` 整体 `dur_us` 很大但 `ui.stall` 很少 | 插件多或某个插件实例化慢；乐器已改为分帧补载，单帧只处理一个时间片 |
| 补载乐器时单个插件很久 | `ui.frame.slow` 紧邻 `engine.sync.instruments` 的时间段 | 该插件自身实例化慢（Kontakt/Serum 首次加载采样库），与宿主逻辑无关 |
| 播放卡顿/爆音 | `engine.sync` WARN 频繁、`ui.frame.slow` 的 `phase=ui.paint` | 同步持锁过久、单帧工作量过大 |
| 关闭工程卡死或崩溃 | `window.drop` 最后一条停在 `phase=engine_drop_next` 且不再推进 | 内置乐器析构异常 |
| 关闭含插件的工程 | `window.drop` 出现 `phase=engine_retained;reason=plugin_teardown` | 正常：插件实例保留至进程结束，避免析构死锁/崩溃 |
| 关闭软件后进程仍在 | 有 `# end`，但 PID 仍被列出且 `Threads=0` | 已退出，外部句柄未释放（见 7.2） |
| 内存/句柄持续上涨 | `resource` 记录单调上升 | 泄漏或插件未释放 |
| 崩溃 | 最后是 FATAL `panic` / `unhandled_exception` | 见 `location` / `exception_code` |

### 7.2 退出后 `taskkill` 报“拒绝访问”

`# end` 说明应用已执行终止。此后 `Get-Process` 仍列出该 PID、但 `Threads=0` / `CPU=0` / 工作集为 0 时，它是**已被外部句柄保留的已退出进程对象**（启动器/调试器/监控工具尚未关闭句柄），`taskkill /f` 无法结束这类对象属于 Windows 预期行为。

## 8. 限制与约定

- 日志是里程碑级 + 周期采样，不是逐帧全量追踪；帧耗时以 600 帧为窗口聚合。
- `t_us` 相对进程启动；绝对时间用文件头 `start_unix_us` 换算。
- 日志包含工程路径、插件路径与设备名等本机信息，**分享前请自行脱敏**。
- 版本升级时若布局变化，必须递增 `FORMAT_VERSION` 并同步本文档与解码器。

---

## 9. 维护规则

1. 新增/修改事件时，更新第 5 节事件目录（scope、event、字段、级别）。
2. 新增阈值/间隔常量时，同步更新 [关键常量](./关键常量.md) 的“诊断日志”一节。
3. 修改文件头、记录头或负载布局时：递增 `FORMAT_VERSION`，同步 `decode.rs` 与本文档，并补解码测试。
4. 只有 `src/diag/` 可以写日志文件；其他模块只调用 `diag::info` / `warn` / `error` / `Span`。
5. 实时音频回调、音频高优先级线程内禁止调用 `diag`。
