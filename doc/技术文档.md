# SurfingStudio 技术文档

本文档描述 SurfingStudio 的整体架构、关键数据流、实时音频策略、插件宿主实现与 UI 交互模型，面向需要阅读、维护或扩展源码的开发者。

## 1. 总览

### 1.1 分层架构

```text

                │ 每帧一次 try_lock → ui_* 快照         │ 编辑 Project
```

### 1.3 统一模块框架（运行时 + 后端）

项目对所有存在多种实现或文件格式的领域采用同一结构，详细规则见 [代码规范](./代码规范.md) 1.5：

```text
应用层 / 引擎
  └─ XxxRuntime / XxxHost        ← 唯一入口：注册、分派、生命周期
       ├─ XxxBackend / XxxCodec  ← 后端接口：能力描述 + 转译/加载
       └─ backends/*             ← 具体格式实现，不感知 UI
```

| 领域 | 运行时 | 后端 | 会话/结果 |
| --- | --- | --- | --- |
| 工程格式 | `ProjectRuntime` | `ProjectCodec`（sfsd / soundbug） | `ProjectSession` |
| 插件格式 | `PluginHost` | `PluginBackend`（vst3 / vst2） | `PluginRuntime` |
| 音频文件 | `AudioRuntime` | `AudioCodec`（wav / symphonia / aiff） | `AudioFile` |
| 实时乐器 | `InstrumentRuntime`（封闭枚举） | `PolySynth` / `DrumKit` / `ModeledInstrument` / `PluginRuntime` | 音频缓冲 |
| 实时效果 | `EffectRuntime`（封闭枚举） | `NativeEffectProcessor` / `PluginRuntime` | 音频缓冲 |
| GPU 渲染 | `GpuRuntime` | `GpuBackend`（wgpu 计算） | `GpuDeviceInfo` / 主总线缓冲 / `GpuRealtimeLimiter` |
| 平台能力 | `PlatformRuntime` | `PlatformBackend`（desktop / android） | `PlatformInfo` / `PlatformCaps` / `FileRequest` |

- 应用层只调用运行时；后端模块不对外暴露为应用依赖。
- 运行时按扩展名/格式分派，未知扩展名可按注册顺序探测。
- 实时音频回调内不使用 `dyn` 后端分派或堆分配；实时 DSP 使用封闭枚举。

### 1.4 平台运行时（类 JVM 的跨端适配）

平台差异不在业务代码里写 `cfg` 分支，而是收敛到一个内部 API 与若干系统后端：

```text
app / ui / diag / main
  └─ platform::PlatformRuntime::standard()   ← 唯一入口（LazyLock 静态实例）
       └─ dyn PlatformBackend
            ├─ backends::desktop              ← Windows / macOS / Linux
            └─ backends::android              ← Android（NativeActivity）
```

| API | 说明 | 桌面 | 安卓 |
| --- | --- | --- | --- |
| `info` / `caps` | 后端标识与能力位 | 全功能 | 单窗口、无系统对话框、无插件宿主、固定系统音频 |
| `config_dir` / `cache_dir` / `data_dir` | 设置、插件缓存、应用数据 | `%APPDATA%` / `%LOCALAPPDATA%` / XDG | NativeActivity 的 `internal_data_path` 与其同级 `cache` |
| `log_dir` / `temp_dir` | 诊断日志与临时文件 | 本地应用数据 / 系统临时目录 | 数据目录下的 `logs` / `TMPDIR` |
| `pick_file` / `pick_folder` / `save_file` | 原生文件对话框 | rfd（以主窗口为父窗口） | 返回 `None`（无系统对话框） |
| `import_file` | 打开用户选定的外部文件并落到可读路径 | 默认实现复用 `pick_file` | SAF `ACTION_OPEN_DOCUMENT`，复制到 `<数据>/Imported/` |
| `export_copy` | 把沙箱文件另存到用户选定位置 | 默认实现复用 `save_file` + `fs::copy` | SAF `ACTION_CREATE_DOCUMENT`，按 `detachFd` 写入 |
| `exit_process` | 确定性退出 | `TerminateProcess`（跳过插件卸载） | `std::process::exit` |

能力位对应用层的实际影响：

- `multi_window = false`：`WindowHost` 进入单窗口模式，主页与工程都画在根窗口；打开新工程时若已有工程则拒绝并提示；浮动卷帘改为底部编辑区；设置改为根窗口内的模态面板（`egui::Modal`）。
- `native_file_dialog = false`：保存工程/导出 WAV 直接写入应用数据目录下的 `Projects`，保证移动端始终能保存；文件菜单额外出现「工程副本保存到公共目录…」「WAV 导出到公共目录…」，走 `PlatformRuntime::export_copy`（SAF）；「打开项目…」走 `PlatformRuntime::import_file`（SAF）。
- `plugin_hosting = false`：插件扫描目录为空，主页插件页不产生条目；应用栏的「VST 插件」菜单整体隐藏；主页侧栏与设置页都不列出插件分类（设置页在已选中插件分类时回落到「界面」）。
- `window_drag = false`：自绘应用栏不再发送 `StartDrag`。

安卓启动路径：`android_main`（`platforms/android/src/lib.rs`）先调用 `platform::install_storage` 把应用私有目录交给平台后端，再调用 `platform::install_activity` 把 `JavaVM` 与 `Activity` 交给 SAF 桥，然后初始化诊断日志，最后用 `eframe::NativeOptions { android_app: Some(app), .. }` 创建根窗口。桌面 `main.rs` 的 `#[cfg(target_os = "android")] fn main() {}` 只是占位，真正的入口由 cdylib 导出。

SAF 桥（`platform/backends/android_saf.rs`）的约定：

- 发起选择用 `startActivityForResult`，结果由 `MainActivity.onActivityResult` 经 `nativeOnActivityResult` 回传，放进进程内 `(请求码, uri, 显示名)` 队列；**等待必须在工作线程**，因为 UI 线程就是 Android 主线程，阻塞它结果永远回不来。
- 字节复制不逐字节过 JNI：`ContentResolver.openFileDescriptor` 后取 `ParcelFileDescriptor.detachFd`，再以 `File::from_raw_fd` 交给 Rust 读写。
- `MainActivity` 的静态初始化显式 `System.loadLibrary("surfing_studio_android")`：NativeActivity 只 `dlopen` 库，JVM 不会自动登记原生方法。
- jni-rs 只把 Java 异常变成 `Err`、**不清除挂起异常**，因此每个失败分支都要调用 `clear_exception`，否则下一次 JNI 调用或线程 detach 会让进程 abort。

## 2. 运行时与线程模型

### 2.1 线程

| 线程 | 职责 | 关键约束 |
| --- | --- | --- |
| 主线程（UI） | 全部窗口的 egui 绘制、工程编辑、插件 GUI | 不长时间阻塞；绘制期间对引擎使用 `try_lock` |
| 音频回调线程（cpal） | 按 `AudioRouter` 渲染当前激活窗口的 `Engine::process` 并输出 | 使用 `try_lock`；禁止分配与阻塞；路由锁只做一次非阻塞尝试 |
| ASIO 驱动回调线程 | 驱动在双缓冲切换时调用宿主 `bufferSwitch`，渲染当前激活窗口并写入 ASIO 输出缓冲 | 与 cpal 回调相同的实时约束；`ASIOSTop` 返回后才释放上下文；直接加载注册表中的 ASIO 驱动 |
| 扫描线程 | VST3 元数据 / VST2 探测 | 结果通过 mpsc 回传，写回共享插件缓存 |
| 工程加载线程 | 每个工程窗口读取并解析 `.sfsd`（SFS2） | 结果回传后延迟一帧应用，保证加载提示可见 |
| 后台插件同步线程（每个工程窗口 1 个，常驻） | 加载工程时构建该窗口的效果器运行时 | STA + 消息泵；插件加载时创建的窗口与定时器随线程存活；只持有引擎 `Weak`，窗口关闭后不延长引擎寿命；VST 乐器延后到 UI 线程实例化 |
| 音频解码线程 | 后台解码音频文件并写回引擎 | 只持有引擎 `Weak`；窗口关闭后立即退出，不延长引擎寿命 |
| 文件对话框线程 | rfd 原生工程 / 文件夹对话框 | 以所属窗口为 parent，保持模态 |
| 崩溃恢复线程（每个工程窗口 1 个，常驻） | 持有最新工程快照，按间隔写恢复文件 | 只写盘、不接触 UI/引擎；工程从未保存时写临时目录；窗口关闭时收到 `Shutdown` 退出 |
| 工程对象释放线程 | 丢弃旧工程 / 撤销栈 | 避免大对象析构卡住 UI 帧 |
| 诊断看门狗线程（全进程 1 个，常驻） | 每 250 ms 检查 UI 帧心跳与退出截止时间 | 只读原子变量并写日志；UI 超过 3 s 无帧记 `ui.stall`，退出超过 3 s 再次强制终止 |

### 2.2 锁策略

`Engine` 被 `Arc<Mutex<Engine>>` 共享（每个工程窗口一个）：

- **音频回调**：`engine.try_lock()`。失败时用最后样本做短淡出，恢复时淡入（`audio/backend.rs`）。
- **音频路由**：`AudioRouter` 持有所有窗口引擎的弱引用与“当前激活引擎”。音频回调每块只对路由锁做一次 `try_lock`，失败时沿用上一次的引擎，绝不在实时线程等待。窗口播放/试听时调用 `activate`，同时暂停其他仍在播放的工程。
- **UI 读取**：每帧由 `SurfingApp::refresh_engine_snapshot` 做**一次** `try_lock`，把播放头、播放状态、电平、CPU、自动停止状态统一写入 `ui_*` 字段。顶部工具条、状态栏、编曲区、检查器和控制器卷帘只读这些字段，不再各自抢锁。插件参数/编辑器列表仍按需短暂加锁，并额外有 200 ms 缓存。
- **UI 写入**：同步工程、设置参数、打开编辑器等需要 `lock()`，但通过节流避免每帧持锁；加载工程期间的后台同步会长期持有引擎锁，因此绘制路径统一使用 `try_lock` 并回退到缓存/空数据。
- **试听写入**：`audition_on` / `audition_off` / `release_held_notes` 不直接抢锁丢弃事件，而是先进入 `pending_auditions` 队列并尝试 `try_lock` 补发；锁被音频回调（尤其是重型 VST 插件）占用时，事件保留到下一帧 `flush_pending_auditions` 按顺序发送。同一音高重复触发会先补一条 Note Off 再发 Note On，保证插件重新起音且不留下挂音。
- **共享设置 / 插件缓存**：由 `SharedServices` 内的 `Mutex` 保护，并带 generation；各窗口每帧只在 generation 变化时复制，避免每帧克隆插件列表。
- **音频回调**：先自旋等待引擎锁最多 2 ms，再退化为短淡出；后台同步的短暂持锁不会变成可听见的掉音。
- **实时缓冲复用**：VST3 的 `AudioBuffers` 与 VST2 的输入/输出通道缓冲保存在 `PluginRuntime` 内，只有块大小或声道数变化时才重新分配；音频回调不再每个 block 为新插件分配缓冲，避免插件 GUI 操作后出现持续掉音/颗粒化输出。
- **引擎所有权**：后台同步线程与音频解码线程只持有 `Weak<Mutex<Engine>>`。窗口关闭时先 `AudioRouter::deactivate` 取消输出目标并暂停，`SurfingApp::drop` 最多等待 `ENGINE_RELEASE_WAIT` 让临时引用释放，使引擎（及其插件实例）最终在 UI 线程析构，与乐器插件的实例化线程一致。

### 2.3 同步节流

- 工程变更通过 `needs_sync` 标记；播放中最多每 60 ms 同步一次。
- 每帧只刷新一次 UI 遥测快照；播放状态和电平不会因多个面板重复读取而反复加锁。
- 插件编辑器打开期间所属工程窗口保持 16 ms 重绘节奏，`app/heartbeat.rs` 同时每 16 ms 向 UI 线程投递空消息并请求 egui 重绘；Win32 的低优先级 `WM_TIMER` 不会唤醒空闲的消息等待，心跳确保插件 GUI 的定时器与重绘持续被处理。
- 插件编辑器打开期间每帧转发处理器输出参数反馈；插件 GUI 的定时器、重绘与 VST2 `idle` 依赖这条消息循环持续运行。
- 插件参数轮询 5 Hz（`poll_parameter_changes`），每次只轮询一条轨道（游标轮转）；UI 参数列表缓存 200 ms。一次扫描全部轨道的所有参数会在 20+ 插件工程中卡住 UI 数百毫秒。
- 插件参数直接作用于实时实例，不需要停播或重新渲染。
- UI 重绘：播放中或插件编辑器打开时 16 ms；音频解码中 40 ms；空闲 80 ms。

## 3. 数据模型

### 3.1 顶层结构

```rust
Project {
    version: u32,                 // 当前为 2
    name: String,
    bpm: f64,
    time_sig_num: u8,
    time_sig_den: u8,
    tracks: Vec<Track>,
    master_volume: f32,
    master_controllers: ControllerLanes,
    master_effect: Option<PluginRef>,
    loop_enabled: bool,
    loop_start: f64,
    loop_end: f64,
    length_beats: f64,
    output_layout: ChannelLayout,   // 立体声 / 5.1 / 7.1
}
```

`output_layout` 放在结构末尾并带 `#[serde(default)]`：`.sfsd` 清单使用 MessagePack 位置编码，新增字段只能追加在末尾，旧工程才能按默认立体声解码。

时间单位统一为 **beat**（四分音符）。小节长度：

```text
beats_per_bar = time_sig_num * 4 / time_sig_den
```

常量：

- `MASTER_TRACK_ID`：主输出伪轨道，真实轨道 id 从 1 开始；具体值见 [关键常量.md](./关键常量.md)。
- `CURRENT_PROJECT_VERSION`：当前工程清单版本；具体值见 [关键常量.md](./关键常量.md)。

### 3.2 轨道

```rust
Track {
    id: TrackId,                 // u64
    name, color: [u8; 3],
    kind: TrackKind,             // Midi | Audio（仅默认角色）
    instrument: InstrumentRef,   // Synth | Drums | Native | Plugin
    effects: Vec<EffectRef>,     // 插件效果或内置原生效果
    controllers: ControllerLanes,
    visible_controllers: Vec<ControllerKind>,
    clips: Vec<Clip>,
    volume, pan, muted, solo,
    expanded: bool,
    output_pair: u8,             // 输出通道对：0 前 L/R、1 中置/LFE、2 环绕 L/R、3 后 L/R
    revision: u64,               // 参与音符事件签名，不持久化
}
```

- `output_pair` 追加在结构末尾并带 `#[serde(default)]`；超出工程布局通道对数量时由引擎夹取到最后一对。
- 立体声工程只有 0 号通道对有效；切换为 5.1 / 7.1 后检查器显示通道对下拉框。

轨道类型规则集中在 `core/model/track.rs`：

- `is_audio_lane()`：有片段时由片段实际类型决定；空轨道才看 `kind`。
- `accepts_clip()`：音频片段不能进入已有 MIDI 片段的轨道，反之亦然。
- `supports_controller()`：力度、延音只对 MIDI 内容有效；音量、声像、弯音对音频也有效。

### 3.3 片段

```rust
Clip {
    id: u64,
    name: String,
    start: f64,        // 工程 beat
    length: f64,
    notes: Vec<Note>,
    audio: Option<AudioSource>,
    color: Option<u8>, // 256 色调色板
    revision: u64,     // 参与音符事件签名，不持久化
}
```

- MIDI 片段：`notes` 有效。
- 音频片段：`audio = Some(AudioSource { path, name, length_seconds, offset_seconds })`，音符为空。
- `offset_seconds` 表示从源文件内部开始播放的位置，默认 `0.0`；导入 SoundBug 工程时用它保留同一 WAV 的多个区段。

### 3.4 控制器与自动化

`ControllerKind`：`Volume`、`Pan`、`Velocity`、`Sustain`、`PitchBend`。

- 可添加到轨道子轨的控制器为 `Volume`、`Pan`、`Sustain`、`PitchBend` 四类（`ControllerKind::ALL`）；`Velocity` 变体仅为兼容旧工程保留，不再出现在子轨菜单、检查器与控制器卷帘中，力度改由钢琴卷帘底部的力度控制器按音符编辑。
- 自动化点为 `(beat, value 0..1)`，线性插值；延音向下取整为 0/1（阶梯）。
- 默认值：音量 `0.5`（=100%），声像/弯音 `0.5`（居中），延音 `0.0`（OFF）。
- 弯音范围：MIDI 为 ±2 半音；音频播放速率倍率为 `2^(((bend*2-1)*2)/12)`。
- 主输出音量自动化：`value * 1.5`，否则使用静态 `master_volume`。

### 3.5 插件引用与效果链引用

效果链位置使用 `EffectRef`：

```rust
enum EffectRef {
    Native(NativeEffect),  // kind + enabled + 归一化参数
    Plugin(PluginRef),
}
```

- `#[serde(untagged)]`：旧工程中的 `PluginRef` 数组自动落为 `EffectRef::Plugin`，无需递增工程版本。
- `EffectRef::key` 用于运行时复用：内置效果为 `native:<kind>`，插件沿用 `格式:uid:路径`。
- 内置效果的启用开关与插件一致，只控制是否处理音频，不销毁 DSP 状态。

```rust
PluginRef {
    format: Vst3 | Vst2,
    path: PathBuf,
    name: String,
    uid: String,       // VST3 class id
    state: Vec<u8>,    // VST3 状态块
    params: Vec<f32>,  // VST2 参数快照 / VST3 回退
    enabled: bool,     // 效果器是否生效；关闭时旁路但保留实例
}
```

`enabled` 带 `#[serde(default = "default_enabled")]`（默认 `true`），旧工程加载后效果器仍全部生效；关闭只影响实时/离线渲染是否跳过该效果器，不卸载实例。

保存工程前调用 `Engine::capture_plugin_states` 把运行时状态写回 `Project`。

### 3.6 音符事件表

实时渲染不再按 block 扫描全部片段与音符，而是在工程同步阶段把每条轨道展开成按 beat 排序的事件表：

```text
NoteEvent { beat, pitch, velocity, on }
```

- 每个音符产生两条事件：`start` 处的 Note On 与 `min(start + length, clip.end())` 处的 Note Off。
- 同一 beat 上先 Note Off 后 Note On，保证同音高重叠时正确重触发。
- 事件表归属于 `TrackEngine`，音频回调只维护 `event_cursor` 顺序推进；定位、循环回绕与播放开始时用二分查找重新定位游标。
- 事件表的重建由片段签名决定：每个片段的 `id/revision/start/length/notes.len()`。签名不变（例如只改音量、声像或插件参数）时不会重新排序。
- 同步阶段还会缓存 `any_solo` 与 `auto_stop_at`，避免每个 block 重新扫描全部轨道和片段。

## 4. 音频引擎

### 4.1 单一实时渲染路径

`Engine::process` 直接调用 `render.rs` 的实时渲染器，不再存在缓存/直通分派：

| 路径 | 用途 | 行为 |
| --- | --- | --- |
| `Engine::process` | 应用播放、试听与离线导出 | 推进走带；按块运行乐器、效果器与主总线 |

应用启动时创建 `Engine::new(48_000.0)`；离线导出复用同一渲染器，但关闭循环与自动停止。

### 4.2 每块处理流程

```text
for each track:
    if muted 或 (有 solo 且本轨未 solo): 关闭挂音、跳过事件、衰减电平, continue
    应用控制器状态（延音/弯音 → 乐器）
    从事件游标取出本块 Note On / Off
    合并实时试听事件并按力度自动化缩放 velocity
    乐器渲染 → track_l / track_r
    音频片段按弯音速率流式混入 → track_l / track_r
    依次通过插入效果器（wet 缓冲交换）
    应用音量/声像自动化与静态音量 → 按 output_pair 累加到主总线通道对
主效果器（仅前左/前右通道对）→ master_l / master_r
主音量（所有声道）+ soft_clip（所有声道；实时 GPU 开启时由 GPU 在 1 ms 内限幅，否则 CPU）
→ 按设备声道数映射（相同直通、较少下混、较多补零）→ 输出
```

关键实现细节：

- `TrackEngine::collect_events` 只顺序读取本块内的事件（`event_cursor`），不再每个 block 扫描全部片段与音符。
- `apply_controller_state` 只在延音/弯音值变化时向乐器发送 CC64 / Pitch Bend，避免重复事件。
- `self.tracks` 在 `sync_project` 中按 `Project::tracks` 的顺序重建，因此实时回调可以直接按索引访问 `self.tracks[track_index]`，不再每个 block 按 id 做线性查找（原实现的 O(n²) 热点）。
- 所有 scratch buffer（track / wet / master / audio）在 `Engine` 内复用，音频回调中不做堆分配（除首次扩容）。
- `any_solo`、自动停止位置、`has_audio_clips`、音符事件表均在同步阶段预计算。
- 轨道被静音时把事件游标推到块尾，取消静音不会补发旧音符。
- 主总线按 `Project::output_layout` 预分配 2 / 6 / 8 个声道缓冲；每轨按 `output_pair` 写入对应通道对，布局切换时 `sync_project` 调整缓冲数量。
- `Engine::process_output(&mut [Vec<f32>])` 是设备输出的唯一入口：布局声道数与设备声道数一致时直通，设备为立体声/单声道时按 ITU 系数下混，设备更多时多余声道补零。`Engine::process(out_l, out_r)` 只是两声道便捷包装。
- 主效果器固定 2 in / 2 out，环绕声布局下只挂在前左/前右，避免同一实例逐对复用产生串扰；其余通道直通后仍经过主音量与限幅。
- 实时 GPU 限幅器（`GpuRealtimeLimiter`）在启用时持有常驻设备与管线：每块把主总线交错样本提交给 GPU，最多等待 `GPU_REALTIME_TIMEOUT`（1 ms）；超时/失败立即对整块执行 CPU `soft_clip` 并丢弃该实例，状态栏提示一次。

### 4.3 播放、定位与循环

- `play()` 从当前播放头定位所有轨道的事件游标，并关闭全部挂音；播放立即开始，不需要任何预渲染。
- `seek()` 更新播放头、清空音频片段源游标，并把事件游标定位到目标 beat。
- 循环回绕时把播放头移到 `loop_start`，清空音频游标并重新定位事件游标，避免跨循环挂音。
- 自动停止与循环互斥：循环终点超过自动停止点时，该循环视为无效。
- 音频片段按源文件样本位置实时流式读取，因此弯音可以连续改变播放速率；定位或循环回绕后按时间轴重新计算源游标。

### 4.4 软限幅与自动停止

```rust
soft_clip(x):
    |x| <= 0.95 → x
    否则 → sign * (0.95 + 0.05 * (1 - exp(-(|x|-0.95)/0.05)))
```

- 0.95 以下完全线性，不改变正常素材音色。
- 自动停止：`auto_stop_beat = content_end + 2 小节`；实时播放时启用，离线导出时关闭；循环区间若超过自动停止点则视为无效循环。
- 循环回绕时会关闭全部挂音并重新定位事件游标，防止跨循环的挂音。

### 4.5 内置乐器

**PolySynth**（`audio/synth/poly.rs`）：

- 24 个 voice。
- 每个 voice 两个失谐振荡器（相位差 0.37），支持正弦、锯齿、方波、三角；锯齿/方波使用 PolyBLEP 抗混叠。
- ADSR：attack / decay / sustain / release，按采样率换算步进。
- Cytomic 风格状态变量低通滤波器（cutoff + resonance）。
- 支持延音踏板与 ±24 半音的内部弯音（引擎实际传入 ±2 半音）。
- 输出 `tanh` 软饱和。

**DrumKit**（`audio/synth/drums.rs`）：

- 16 个 voice，按 MIDI 音高映射：底鼓 35/36、军鼓 37/38/40、闭镲 42/44、开镲 46、拍手 39、通鼓 41/43/45/47/48/50。
- 音色按 808/909 的合成方式重建：底鼓用约 150 Hz → 50 Hz 的连续相位扫频正弦并叠加极短高频点击与软饱和；军鼓为约 185/330 Hz 双音调模式 + 高通噪声；踩镲为六个非整数比方波相加后高通；拍手为三段快速噪声爆发 + 尾音；通鼓为连续相位扫频。
- 每个 voice 有独立噪声种子、高通状态与振荡器相位；扫频使用相位累加而不是 `t × f`，避免相位跳变。
- 支持延音踏板（延长闭镲衰减）与弯音（在触发时改变音调类鼓件频率）。

**ModeledInstrument**（`audio/synth/modeled.rs`）：

- `NativeInstrumentKind`：钢琴、木吉他、电吉他、失真电吉他、贝斯、小提琴、弦乐断奏、弦乐拨奏、弦乐联奏。
- 24 个 voice，每个 voice 预分配 8192 采样延迟线；音频回调内不再分配。
- 拨弦类（木/电/失真吉他、贝斯、弦乐拨奏）使用 Karplus-Strong 延迟线：
  - 噪声激励经过拨弦位置梳状相减（靠近琴桥更亮、靠近琴颈更暖）；
  - 环路低通截止随音高上移，并从延迟长度中扣除低通相位延迟以保持音准；
  - T60 按乐器类型设定（贝斯 3.8 s、木吉他 4.5 s、电吉他 5.2 s、失真吉他 6.0 s、拨奏 0.8 s），环路衰减按基频换算为“每周衰减”而不是“每采样衰减”；
  - 琴箱/拾音器共振用二阶共振器叠加（木吉他 105/205/410 Hz，电吉他 160/900/2800 Hz，失真吉他 110/700/3200 Hz，贝斯 62/125/400 Hz），共振峰按峰值增益归一化；
  - 拨片/指甲瞬态与电吉他 `tanh` 驱动、失真吉他三次谐波整形。
- 钢琴使用 6 个非谐分音，非谐系数随音高从约 3e-4 增长到 3e-2（文献值范围）；包含击弦噪声、同音群拍频、低阶音板共振与高次分音超过奈奎斯特时的静音保护。
- 弓弦类（小提琴、弦乐断奏、弦乐联奏）使用 3 个轻微失谐锯齿振荡器 + ADSR + 一阶低通 + 5.2 Hz 颤音（0.35 s 渐入），并叠加体腔共振（小提琴 300/700/1600 Hz）、弓毛摩擦噪声与低通；三种奏法通过起音、延音、释放与失谐宽度区分。
- 延音踏板：Note Off 在踏板踩下时挂起，抬起踏板后进入释放；弯音按采样连续改变频率。
- 力度、音量、声像仍由引擎统一处理（力度自动化缩放 Note On，音量/声像在轨道总线）。

音色建模参考（网络资料）：

- 钢琴非谐性 B 值范围：<https://arxiv.org/html/1203.5101v2>、<https://forum.modartt.com/viewtopic.php?pid=1006230>。
- 808 底鼓扫频与点击、909 军鼓/踩镲合成方式：<https://www.audioscene.org/article/secrets-to-creating-authentic-80s-drum-machine-patterns/>、<https://www.audioscene.org/article/designing-percussive-sounds-using-synthesis-techniques/>。
- 项目不内置第三方采样库：受许可证与仓库体积限制，原生乐器采用可实时运行、无外部依赖的物理建模/合成实现；用户仍可通过 VST 乐器加载商业采样库。

### 4.6 内置原生效果器

`audio/fx/native.rs` 提供与插件效果器并列的 `NativeEffectProcessor`，效果链可混排 VST 与内置效果：

| 效果器 | DSP 要点 |
| --- | --- |
| 过载 | `tanh` 软饱和 + 音色低通 + 干湿混合 |
| 失真 | 高增益软削波，输出更硬 |
| 法兹 | 非对称偏置削波，产生偶次谐波 |
| 合唱 | 调制延迟（9~25 ms），左右声道 LFO 相差 90° |
| 相位 | 四级全通滤波 + 反馈 + LFO 扫频 |
| 延时 | 40~900 ms 反馈延时，反馈路径高频阻尼 |
| 混响 | 4 梳状 + 2 全通（Schroeder）立体声混响 |
| 压缩 | 立体声联动峰值包络、阈值/比率/起音/释放与补偿增益 |

- 所有延迟线/梳状滤波器在同步阶段一次性分配；渲染函数只推进状态。
- 参数以 0..1 归一化保存在工程中，UI 按参数类型显示 ms / Hz / dB / 百分比。
- 内置效果没有插件实例与编辑器，效果器卷帘直接在卡片内绘制参数；启用开关与插件效果一致（旁路保留状态）。
- 新增效果时按 `EffectRef::key` 复用/重建运行时；参数变化只更新 `set_settings`，不重建实例。

### 4.7 插件乐器/效果器处理

`PluginRuntime::process` 统一接收：

- `sample_rate`、`frames`
- `input: Option<(&[f32], &[f32])>`
- `gates: &[SynthEvent]`（含 frame 偏移）
- `out_l/out_r`

VST3：

- 每个 gate 转为 `NoteOn/NoteOff`，通过 `send_midi_event_at(event, frame)` 注入。
- 音频缓冲固定 2 in / 2 out（`AudioBuffers::new(2, 2, frames, sample_rate)`）。
- 单声道输出插件会把第一路复制到右声道。

VST2：

- 手工构造 `VstEvents` 内联结构（最多 64 个事件），避免额外分配。
- 按 `info.inputs/outputs` 创建 HostBuffer；单声道输出同样复制到右声道。
- 弯音通过 `0xE0 LSB MSB`，延音通过 CC64。

### 4.8 离线渲染与导出

`Engine::render_offline_options(project, options)` 是导出与兼容入口共用的离线渲染路径：

1. `OfflineRenderOptions` 提供采样率、输出布局、范围（整个工程 / 循环区间）、尾长与可选 GPU 配置；
2. 复制工程并写入目标布局、关闭循环；整个工程模式渲染 `0 .. 内容末尾 + tail`，循环模式渲染 `loop_start .. loop_end`；
3. 创建独立 `Engine::new`，关闭自动停止；启用 GPU 时设置 `defer_master_clip`，主总线只乘主音量，软限幅留到整段渲染结束；
4. 按 512 帧逐块 `process_output`，输出交错多声道样本（2 / 6 / 8 声道）；
5. 若提供 `GpuRenderConfig`，调用 `GpuRuntime::apply_master_limiter` 在所选 GPU 上分块执行 WGSL 软限幅并回读；失败时对整段样本执行 CPU `soft_clip` 并把原因写入 `OfflineRender::warning`。

`Engine::render_offline_with`（工程布局、2 beat 尾长、无范围覆盖）与 `Engine::render_offline`（强制立体声）是兼容包装。

导出由音频 I/O 运行时完成：应用层调用 `AudioRuntime::export_project_with_options`；框架按目标扩展名选择可写后端，WAV 支持 16/24-bit PCM 与 32-bit 浮点，AIFF 支持 16/24-bit PCM（浮点回退 24-bit）。样本先 clamp 到 [-1, 1] 再按位深量化。

GPU 路径的约束：

- 离线导出使用一次性提交；实时播放使用常驻的 `GpuRealtimeLimiter`，回调内最多等待 `GPU_REALTIME_TIMEOUT`（1 ms），超时立即回退 CPU。任何 GPU 调用都不得无限期阻塞音频线程。
- 设备与驱动来自 `audio/gpu` 后端枚举（wgpu 的 DX12 / Vulkan / OpenGL 适配器），CPU 适配器被过滤；同一块显卡在不同 API 下各出现一次，UI 用去掉 `/PCIe/SSE2` 等后缀的名称归组。
- 离线缓冲按 `CHUNK_SAMPLES`（约 4 MiB）分块；实时缓冲固定为 8 声道 × 4096 帧（32768 样本）。
- 着色器与 CPU 的 `soft_clip` 使用同一公式（拐点 `0.95`），保证开关 GPU 不影响导出听感。

### 4.9 音频系统、ASIO 与设备选择

`audio/backend.rs` 统一描述音频系统与输出设备，`audio/asio.rs` 提供 Windows 下的原生 ASIO 后端：

- **音频系统**：`AudioSystem::{System, Wasapi, Asio}`。`System` / `Wasapi` 走 cpal 宿主；`Asio` 走专用后端，不经过 cpal。
- **设备枚举**：`audio_systems` / `output_devices` / `input_devices` 只读宿主能力与注册表；设置窗口缓存枚举结果，手动“刷新设备”时重建。
- **启动选项**：`AudioOptions { system, output_device, sample_rate, buffer_frames, output_channels }` 来自全局设置；启动失败时 `SharedServices` 回退到系统默认设备并把原因写入音频状态文本。`output_channels` 为 `None` 时使用设备默认声道数；指定 2 / 6 / 8 时优先选择声明该声道数的 F32 配置，设备不支持则退回任意 >= 2 声道的配置。
- **ASIO 发现**：枚举 `HKLM\SOFTWARE\ASIO` 下的驱动子键，读取 `CLSID` 与 `Description`，用 `CoCreateInstance` 以驱动 CLSID 同时作为接口 IID 创建 `IASIO`。
- **ASIO 协商**：`getChannels` → `get/setSampleRate` → `getBufferSize`（按驱动粒度取整）→ `getChannelInfo`（接受 Int16LSB / Int24LSB / Int32LSB / Float32LSB / Float64LSB 与 32 位容器左对齐的 Int32LSB16/18/20/24）→ `createBuffers` → `start`。驱动拒绝请求采样率时沿用其当前速率；启动后再次读取采样率并写回 `AudioRouter`。
- **ASIO 实时路径**：驱动调用 `bufferSwitch(index)` 或 ASIO 2.x 的 `bufferSwitchTimeInfo`（两者都指向同一渲染入口），宿主通过全局原子指针取得回调上下文，渲染当前激活引擎（与 cpal 相同的 2 ms 自旋锁与断流淡出），再把左右声道按驱动采样格式写入 `buffers[index]`。
- **cpal 实时路径**：回调按设备声道数维护等长 `Vec<f32>` 缓冲并调用 `Engine::process_output`，由引擎完成布局映射；断流淡出/淡入对每个声道分别执行，写回时按采样格式转换。
- **ASIO 生命周期**：回调表 `AsioCallbacks` 存放在堆上的回调上下文里，与输出流同生命周期（部分驱动保存该指针并在 `start()` 返回后继续调用）；`AsioStream` 析构时先 `stop`（返回后驱动保证不再回调），再清空上下文、`disposeBuffers`、`release`；设置变更时 `SharedServices::restart_audio` 先释放旧流再打开新流。
- **启用设备**：音频页的“输出设备 / 输入设备”与控制器页的 MIDI 输入/输出端口都会持久化到设置；音频输入设备当前仅记录启用状态，MIDI 输入端口会立即重连。

## 5. 实时渲染管线与性能

### 5.1 同步阶段

`Engine::sync_project` 每次工程变化后执行：

1. 克隆工程快照，缓存 `any_solo`、`auto_stop_at`；
2. 按 `Project::tracks` 顺序重建/复用 `TrackEngine`；
3. 对每条轨道计算音符签名，签名变化时重建并排序 `NoteEvent` 列表，随后把游标定位到当前播放头；
4. 收集音频片段路径，交给后台线程解码；保留仍被引用的音频源与源游标。

效果链按插件键**增量复用**：新增/删除一个效果器时只加载/释放那一个实例，不再重建整条链（实测播放中新增 Pro-Q 45 ms、新增 Auto-Tune 55 ms；旧实现会重载该轨道全部效果器）。

### 5.2 回调阶段

```text
Engine::process(out_l, out_r)
  ├─ 未播放：试听中 → render_live；否则衰减电平并返回
  └─ 播放中：
       ├─ 按 block_size 切分回调缓冲
       ├─ 处理循环回绕 / 自动停止
       └─ render_chunk(advance = true)
            ├─ 每轨：控制器状态 → 事件游标 → 乐器 → 音频片段 → 效果链 → 音量/声像
            ├─ 主效果器
            └─ 主音量 + soft_clip
```

### 5.3 效率要点

- **事件驱动**：每个 block 只处理本块内触发的事件；轨道静音时游标直接推进到块尾。
- **零预渲染**：不存在后台渲染任务、分块位图、等待项或缓存安装，播放与编辑之间没有中间层。
- **按需重建**：控制器、插件参数与混音设置的修改不会触发音符事件排序。
- **scratch 复用**：track / wet / master / gates 缓冲在回调间复用；音符事件直接写入复用的门限缓冲。
- **单次同步**：播放中工程同步按 60 ms 节流，避免拖动时音频回调反复错过 block。

## 6. 插件宿主

### 6.1 统一抽象

插件采用「运行时框架 + 格式后端」结构：

```text
PluginHost（框架）
  ├─ PluginBackend（VST3 / VST2）
  ├─ load_plugin  → 加载并返回 PluginRuntime
  └─ scan_plugin_format / scan_plugins → 扫描结果
```

```rust
enum PluginRuntime {
    Vst3(Vst3Runtime),
    Vst2(Vst2Runtime),
    Failed(String),
}
```

对引擎暴露的能力：参数列表、设置参数、捕获/恢复状态、MIDI 音符/CC/弯音、处理音频、打开/关闭编辑器、编辑器尺寸/可缩放性、失败信息。

应用层与引擎只调用 `PluginHost`；VST3 / VST2 仅在 `plugin/backends/` 中实现加载与扫描。

### 6.2 加载

- 所有加载经 `PluginHost::load_plugin` 按 `PluginFormat` 分派；具体格式由 `Vst3Backend` / `Vst2Backend` 实现。
- VST3：`Vst3Host::builder()` 设置采样率、block、2 in/2 out、BPM、拍号；优先按 `uid` 加载 class，失败则回退到默认 class。
- VST2：`PluginLoader::load` → `instance()`，随后 `init / set_sample_rate / set_block_size / resume`。
- 加载完成后读取名称、分类、参数、输出通道数，并 `start_processing()`（VST3）。

### 6.3 扫描

- 扫描经 `PluginHost::scan_plugin_format` / `scan_plugins` 分派到对应后端；`plugin/scan.rs` 只提供共享扫描工具。
- **VST3**：只读 bundle 内的 `Contents/moduleinfo.json`；部分厂商（如 Serum 2）放在 `Contents/Resources/moduleinfo.json`，两处都会尝试。解析 `Classes`、`SubCategories`（兼容 `Sub Categories` 写法）与 `CID`；不实例化插件，避免授权代码导致宿主崩溃。
- 无 `moduleinfo.json` 的 bundle 与 Windows 单文件 `.vst3` DLL 在**快速扫描**阶段只按文件名/目录记为“未知”，不加载模块；插件列表可以立即显示。
- 扫描完成后，应用层对“未知”的 VST3 启动后台识别：`PluginHost::probe_plugin_metadata` → `read_factory_classes`（只读 `IPluginFactory` / `Factory2` / `Factory3` 的类列表，不创建组件、控制器或编辑器），结果通过 mpsc 逐个回传并替换缓存记录。浏览器在此期间显示“正在识别插件类型…”。
- 重新扫描时会保留已识别的类型、名称、厂商与 CID，避免重复加载插件。
- **VST2**：扫描 64 位 `.dll`，短暂实例化读取名称与分类（`Category::Synth/Generator` 视为乐器）。
- 去重键为路径小写；结果按名称、厂商排序。
- 浏览器类型筛选严格匹配：乐器只列 `Instrument`、效果器只列 `Effect`，无法识别的插件单独归入“未知”，不会同时出现在乐器与效果器列表中。
- 扫描在后台线程执行，UI 通过 mpsc 接收结果。
- **启动增量扫描**：每次启动在后台执行 `ScanMode::Incremental`。`list_plugin_files(custom_paths)` 只枚举标准目录与设置中的自定义目录（不读元数据、不实例化），用「修改时间秒 + 字节数」指纹与缓存比对；指纹未变化的记录直接复用，新增或变化的 VST3 用 `scan_vst3_paths` 只读 `moduleinfo.json`，新增或变化的 VST2 只重新扫描其所在目录。
- **插件缓存**：扫描结果与指纹写入 `%LOCALAPPDATA%\SurfingStudio\plugin-cache.json`（`PLUGIN_CACHE_VERSION = 1`；不可写时依次回退 `%APPDATA%` 与系统临时目录）；`SurfingApp::new` 先读取缓存再启动增量扫描，分类探测与插件加载得到的类型也会立即写回，避免下次启动重复识别。
- **内置插件资料库**：`plugin/catalog.rs` 维护常见厂商/插件名称到厂商、分类、乐器/效果器角色的离线映射。扫描记录缺少厂商、分类为泛化的 `VST3` / `VST / VST2` 或类型为“未知”时用它补全；不覆盖 `moduleinfo.json` 提供的可信元数据，也不访问网络。

### 6.4 参数

- VST3：`get_parameters()` + `format_parameter()` 生成显示文本。
- VST2：`PluginParameters::get_parameter / get_parameter_text`。
- 参数修改后立即写回插件；UI 侧缓存 200 ms，避免每帧持锁克隆。
- 检测 GUI 内修改：
  - VST3：优先消费 `take_parameter_edits()` 手势日志；停止播放时每秒做一次全量对比作为兜底。
  - VST2：没有编辑通知，按参数逐个比较，只刷新变化的显示文本。
- 轮询与编辑器尺寸查询都使用非阻塞 `try_lock`；插件正被音频线程处理时跳过本轮，绝不阻塞 UI。
- `restore_state` 恢复 VST3 状态后立即刷新参数快照，避免加载完成后的首次全量扫描把恢复值误判为用户编辑。
- 实时渲染下参数改动直接作用于正在发声的实例，不需要停播或重新渲染；检测结果只用于刷新界面与保存状态。

### 6.5 状态持久化

- VST3：`save_state()` / `load_state()` 保存完整状态块。
- VST2：保存全部归一化参数，恢复时逐个 `set_parameter` 后刷新显示。
- 保存工程、导出 WAV 前都会先抓取运行时状态。

### 6.6 编辑器窗口

VST3 有两条 GUI 路径：

**独立窗口**（`vst3_host::PluginWindow`）：

- 创建原生 Win32 窗口，标题为 `插件名 - VST3`；窗口样式为 `WS_OVERLAPPEDWINDOW | WS_CLIPCHILDREN | WS_CLIPSIBLINGS`，既保留可拖动边框，也避免父窗口擦除插件子窗口导致画面停滞或闪烁。
- 打开后立即 `SetForegroundWindow` / `SetFocus` 激活编辑器：FabFilter 等插件只在窗口激活时运行动画与定时器。
- 用户拖动窗口边框时，`WM_SIZE` 只记录新的客户区尺寸；`service_platform_events` 在消息回调返回后调用 `IPlugView::checkSizeConstraint` / `onSize`（`Plugin::resize_editor`）转发给插件，插件接受尺寸与请求不一致时再调整原生窗口。固定尺寸编辑器忽略该请求，保留插件自报尺寸。
- 宿主每帧（编辑器打开期间 16 ms）调用 `service_platform_events`，持续处理插件发起的 resize、待转发的窗口尺寸与 DPI 记录。
- `WM_CLOSE` 不直接销毁窗口，而是记录关闭请求，由宿主按「先 detach 编辑器、再销毁窗口」的顺序处理。
- 打开前按显示器 DPI 设置内容缩放；插件附加后，如果它报告的尺寸远大于打开前声明的默认尺寸（例如 Serum 2 的 399% GUI 缩放），则：
  1. 计算 `ratio = min(默认宽/实际宽, 默认高/实际高)`；
  2. 若 `ratio < 0.999`，设置内容缩放 `host_scale * ratio`（只缩小、不放大）；
  3. 读取插件接受的新尺寸并调整原生窗口；
  4. 丢弃插件在附加时排队的「膨胀尺寸」resize 请求。
- `WM_DPICHANGED` 不直接应用建议矩形，避免在未通知插件的情况下改变客户区；挂起的 DPI 缩放也会被忽略。
- 关闭窗口时先 `close_editor()`，再 `DestroyWindow`。

实测：Serum 2 打开前 `getSize = 1190×740`，附加后为 `4748×2952`；归一化后窗口与视图均为 `1189×739`。

**VST1/VST2 独立窗口**（`plugin::Vst2EditorWindow`）：

- VST2 后端通过 `PluginInstance::get_editor` 取出编辑器对象，创建一个 Win32 顶层窗口并 `editor.open(hwnd)`；打开后同样立即激活窗口。
- 关闭按钮只记录关闭请求：`service` 先 `editor.close()` 再销毁窗口；编辑器对象保留在窗口中，可再次 `open`，避免重复实例化插件。
- 每帧调用 `editor.idle()` 驱动插件界面刷新；窗口使用 Win32 窗口类 `SurfingStudioVst2Editor`。
- 应用退出、加载工程、撤销或更换插件前先关闭这些窗口，保证编辑器不会晚于插件实例释放。

**VST1/VST2 编辑器子窗口**：编辑器附加到一个填满窗口客户区的 `STATIC` 子窗口，而不是直接附加到顶层窗口。VST1 插件通常只在子父窗口内绘制，直接挂到顶层会显示空白；宿主窗口缩放时通过 `WM_SIZE` 同步子窗口尺寸。

**效果器卡片界面**（`ui/effects.rs`）：

- 卡片主体**只显示插件原生界面**，不再显示参数滑块：底部卷帘为每个 VST3 效果器自动创建内嵌编辑器（`EditorWindow::Vst3Inline`）。
- 卡片头部右上角有启用开关（`PluginRef::enabled`）：关闭时渲染路径跳过该效果器（实时与离线导出一致），内嵌界面不再摆放并在帧末隐藏，卡片显示“效果器已停用”；实例、参数与状态保留，重新启用后立即恢复处理。开关状态随工程保存。
- 每帧最多创建一个内嵌编辑器（`created_inline`）：Auto-Tune 这类大界面插件附加视图约需 200 ms，一次创建多个会让界面长时间无响应。
- **线程约束**：VST3 的编辑器视图必须与插件实例在同一线程创建。`apply_plugin` 在 UI 线程同步创建实例；打开工程时，后台同步线程通过 `sync_project_with(.., defer_plugin_instruments = true)` **不创建 VST 乐器实例**，同步结束后 `poll_engine_sync` 在 UI 线程补载乐器（加载提示仍在显示，音频尚未开始）。后台线程创建的效果器实例会在首次打开 GUI 前由 `ensure_ui_thread_instance` 把状态写回工程、`invalidate_plugin_slot` 只丢弃该槽位的运行时并在 UI 线程重建（`background_synced` 记录这些槽位）；播放前 `prepare_playback_plugins` 会预先重建全部后台效果器实例，避免播放中打开 GUI 触发阻塞式重建。否则 Auto-Tune 等插件会在 UI 线程 `createView` 时死锁，VOCALOID 等插件会在错误的线程创建/析构 WPF 窗口。
- 打开失败的槽位记录在 `inline_failed`，避免每帧重试；卡片显示“无法内嵌界面，双击标题可在独立窗口打开”。
- 双击卡片标题 → 用独立窗口打开原生界面（`open_editor`）；独立窗口与该槽位的内嵌编辑器互斥。卡片头部不设额外按钮（悬停提示会说明双击行为）。
- 内嵌窗口是所属工程窗口拥有的**无边框顶层窗口**（`PluginWindow::open_embedded`，`WS_POPUP | WS_EX_TOOLWINDOW`）：
  1. 不能使用 `WS_CHILD` 子窗口：主窗口通过 OpenGL 交换缓冲绘制，父窗口的缓冲区会把子窗口整块擦掉（实测截图中插件区域只剩父窗口背景色）；
  2. 顶层附属窗口由 DWM 单独合成，稳定显示在卡片位置上方；不使用 `WS_CHILD` 后也不需要父窗口重绘配合；
  3. 宿主每帧按卡片主体矩形摆放（`set_embedded_bounds`）：`egui` 逻辑点 × `pixels_per_point` 得到宿主客户区物理像素，再用 `ClientToScreen` 换算为屏幕坐标后 `SetWindowPos`；
  4. 用 `SetWindowRgn`（`set_embedded_clip`）把窗口裁剪到卷帘可见区域，卡片滚出视野时整窗隐藏；
  5. 窗口创建时不带 `WS_VISIBLE`，首帧摆放后才 `ShowWindow(SW_SHOWNOACTIVATE)`，避免闪现在窗口左上角。
- 每帧末尾 `finish_inline_layout` 隐藏本帧没有被摆放的内嵌编辑器（卷帘关闭、切换视图、卡片滚出视野），避免窗口留在旧位置。
- **默认缩放比契合卡片**（`PluginWindow::fit_embedded`）：
  1. 附加视图后记录插件在缩放 1.0 时的逻辑尺寸（`attached_editor_size / host_scale`）；
  2. 每帧按卡片主体可用物理像素计算 `fit = min(可用宽/逻辑宽, 可用高/逻辑高, 宿主 DPI 缩放)`；
  3. 变化超过 0.01 时调用 `IPlugViewContentScaleSupport::setContentScaleFactor`，插件支持时视图等比缩放并在卡片内居中（Auto-Tune 430×240 → 403×240，耗时 < 1 ms）；
  4. 不支持内容缩放的插件（如 Pro-Q）退回 `WM_SIZE` → `resize_editor` → `onSize`，由插件自己贴合卡片尺寸；
  5. 支持内容缩放时不再回灌 `onSize`，避免把物理像素当成逻辑像素二次放大。
- 内嵌模式的几何由宿主决定：`PluginWindow::resize_native_window` 忽略插件发起的 resize。
- 浮动卷帘（独立视口）不内嵌：两个视口客户区坐标不同；卡片显示提示，双击标题打开独立窗口。
- 独立窗口路径保留：VST1/VST2、没有主窗口句柄、或内嵌创建失败时可通过双击标题打开独立窗口。
- 编辑器（内嵌或独立）打开期间，`SurfingApp::service_editors` 每帧调用 `service_editor_feedback`，把处理器输出的参数反馈转发给 `IEditController`，保证分析器与电平表持续刷新；该服务与效果器卷帘是否可见无关。反馈每条插件每帧最多格式化 `MAX_EDITOR_FEEDBACK_UPDATES`（64）条，避免电平/分析器参数成百上千条时长时间占用引擎锁。
- **音频线程绝不等待插件锁**：`PluginRuntime::process` / `panic` / `send_cc` / `send_pitch_bend` 使用 `try_lock`，GUI 初始化或参数轮询持锁时该块直接输出静音而不是阻塞整个音频流（旧实现会在打开 Kontakt 8 GUI 时让输出流停住，听感为“没有声音”）。
- **编辑器重绘限流**：强制重绘（`RedrawWindow(RDW_INVALIDATE | RDW_ALLCHILDREN)`）只用于**不在前台**的编辑器，且间隔 `EDITOR_REPAINT_BACKGROUND_INTERVAL`（200 ms）；前台编辑器由插件自身绘制循环刷新，宿主每帧重绘会与 Kontakt 8 的 Qt Quick 绘制互相拖住。
- **参数全量比对有上限**：`PluginRuntime::poll_parameters_changed` 仅在参数数不超过 `MAX_FULL_SCAN_PARAMS`（512）时做一次全量比对，并用 `HashMap` 建立索引（O(n)）而不是逐个 `find`（O(n²)）。Kontakt 等数千参数的插件只依赖 `take_parameter_edits` 的编辑手势日志，避免一次扫描卡住 UI 数秒并长期占用引擎锁。
- 删除/重排效果器、加载或新建工程、撤销/重做时关闭对应的编辑器窗口；切换工程时先暂停音频、重置播放状态，再 detach 编辑器，最后才替换工程与插件实例，避免编辑器晚于插件释放导致闪退。
- 正常关闭工程窗口时调用 `close_all_editors` 走插件生命周期（`IPlugView::removed` → `setFrame(null)` → `DestroyWindow`），**不再**用「只销毁窗口、忘记插件窗口」的退出路径；否则插件实例稍后释放时，VOCALOID 6 等 WPF 编辑器会在 `OnClosing` 访问已失效对象并抛出 `NullReferenceException`。仅强制关闭/进程退出保留 `destroy_for_exit` 的跳过逻辑。
- 实时渲染下插入效果器始终运行，打开 GUI 的效果器会自然获得音频，无需额外的“监控槽位”。

### 6.7 本地 patch

`Cargo.toml` 通过 `[patch.crates-io]` 指向 `vendor/vst3-host`，主要修改：

- 编辑器窗口创建时使用正确的宿主内容缩放；
- 打开后对「自放大」编辑器做尺寸归一化；
- 忽略重复的 DPI 缩放回调，防止窗口尺寸被再次放大；
- 丢弃附加阶段的过期 resize 请求；
- 原生子窗口矩形未变化时不再 `SetWindowPos`，避免每帧重定位打断插件内的鼠标拖动；
- 新增 `PluginWindow::refresh_repaint`：对编辑器窗口及其子窗口调用 `RedrawWindow(RDW_INVALIDATE | RDW_ALLCHILDREN)`，让独立插件 GUI 在主窗口聚焦时仍持续刷新。
- 编辑器窗口增加 `WS_CLIPCHILDREN` / `WS_CLIPSIBLINGS`，父窗口重绘不再覆盖插件子窗口；打开后主动激活窗口。
- 新增内嵌模式 `PluginWindow::open_embedded(parent)`：以 `WS_POPUP | WS_CLIPCHILDREN | WS_CLIPSIBLINGS` + `WS_EX_TOOLWINDOW` 创建 main 窗口拥有的无边框顶层窗口并附加插件视图；配套 `set_embedded_bounds`（客户区坐标 → `ClientToScreen` → `SetWindowPos`）、`set_embedded_clip`（`SetWindowRgn`）、`set_embedded_visible`（`ShowWindow`）、`fit_embedded`（按卡片大小做内容缩放并返回窗口尺寸）。内嵌时 `resize_native_window` 为空操作，几何完全由宿主卡片决定。
- `open_embedded` 先用占位尺寸（400×300）创建窗口，不再在创建前调用 `get_editor_size`：后者会额外创建一个临时视图，Auto-Tune Pro 实测需 87 ms。
- `WM_SIZE` 只记录客户区尺寸，由 `service_platform_events` 调用 `IPlugView::onSize`，修复 FabFilter 等插件拖动窗口边框后 GUI 不跟随缩放的问题。
- 插件加载阶段不再调用 `IEditController::createView` 探测 GUI：编辑器只在 UI 线程创建并附加一次。跨线程创建视图会让部分 VSTGUI 插件的定时器/窗口绑定到错误线程，表现为闪烁、挂起或崩溃；GUI 能力按“存在 controller”乐观判断。
- 新增 `read_factory_classes`：只加载模块并枚举 `IPluginFactory` / `Factory2` / `Factory3` 的类元数据，不调用 `createInstance`；扫描单文件 VST3 时用它补齐名称、CID 与分类，避免触发插件启动窗口或授权代码。
- `ConnectionProxy` 不再丢弃处理器线程发来的 `IConnectionPoint::notify`：消息按引用计数复制进有界队列（`MAX_PENDING_CONNECTION_MESSAGES = 256`），由 UI 线程每帧调用 `Plugin::service_connection_messages` 送达控制器。电平/波形类插件不再因为跨线程通知被丢弃而冻结。
- `get_parameter_changes` 在返回处理器输出参数的同时，把它们回写到 `IEditController::setParamNormalized`。这是 VST3 的规定路径：分析器频谱、增益衰减表等数据由处理器写入 `outputParameterChanges`，宿主不回写控制器时插件 GUI 会保持静止。
- 兼容映射改为按需查询：`moduleinfo.json` 缺失（典型情况：Windows 单文件 `.vst3`）且需要按类 ID 加载时，才实例化工厂的 `IPluginCompatibility` 并读取兼容 JSON。`getCompatibilityJSON` 只把负数返回码视为错误（Kontakt 8 返回 `0x1`、空流都按“没有兼容映射”处理）；查询失败时降级为空映射并写 `log::warn!`，不再因为可选的兼容元数据拒绝整个插件。
- 编辑器打开顺序改为「创建视图 → 记录 attach 前尺寸（失败也继续）→ setFrame → attached → 再查询尺寸」：Kontakt 8 在 `attached()` 之前拒绝 `getSize`，旧实现因此卡住约 26 秒后报 `Failed to get view size`。attach 前尺寸仅用于 Serum 2 这类「附加后自放大」的归一化，取不到就跳过归一化；窗口在 `attached()` 之后按插件报告的尺寸调整，两个尺寸都拿不到时保留占位尺寸。
- `PluginWindow::open` 不再先调用 `get_editor_size()` 预创建临时视图：窗口以 `800 × 600` 占位尺寸创建，显示前按上述尺寸调整。重型插件（Kontakt 8）因此少创建一次 GUI，打开耗时约减半。
- 新增 `PluginInternal::shutdown_component` 与公开的 `Plugin::shutdown_component`：按「close_editor → stop_processing → shutdown_data_exchange → setActive(false) → terminate_component」终止组件但保留 Rust 对象，并把内部 `terminated` 置位，使后续 `Drop` 直接返回；宿主据此在关闭工程时释放 VOCALOID / ACE Bridge 拉起的外部应用窗口，同时不在 UI 线程执行插件析构。
- 新增 `PluginWindow::is_foreground`：`GetForegroundWindow` 判断编辑器是否前台，供宿主决定是否强制重绘（前台插件自行刷新）。
- 新增 `PluginWindow::open_with_owner` / `Vst2EditorWindow::new_with_owner`：独立编辑器窗口以宿主主窗口为所有者创建。主窗口销毁时 Windows 会连带销毁这些窗口，插件 GUI 不会在关闭工程后残留；`declared_editor_size()` 返回 attach 前声明的尺寸（查询不创建视图）。
- 插件在 attach 期间通过 `IPlugFrame::resizeView` 请求的尺寸会被采纳为窗口尺寸（只有 Serum 2 归一化生效时才丢弃其放大后的请求）；打开失败时先 `close_editor()` 让插件清理可能已创建的部分视图，再销毁父窗口，避免 Qt 插件（Kontakt 8 的 `ni::qt::QuickWindow`）收到外部 `WM_DESTROY`。`plugin.editor.open` 日志新增 `size` 字段，便于区分“尺寸不对”与“渲染卡死”。

## 7. UI 架构

### 7.1 面板布局与多窗口

应用采用「外壳 + 每窗口一个 `SurfingApp`」的结构：

- 根视口由 `WindowHost`（`app/shell.rs`）绘制，且**始终可见**：它显示主页，或显示最近打开的一个工程。这样 egui 的立即视口始终由可见的根窗口驱动，不会被 eframe 对隐藏窗口的重绘节流拖慢。
- 每个工程逻辑上都是一个独立窗口：第一个工程接管根窗口（主页窗口随之关闭），其余工程由 `ctx.show_viewport_immediate` 创建，窗口 id 为 `("project_window", window_id)`。工程窗口无系统标题栏，复用自绘应用栏、工具栏、检查器与底部卷帘。
- 根窗口显示工程时，点击应用栏图标或 `文件 → 主页` 会以立即视口打开独立的主页窗口（窗口 id `home_window`），工程窗口保持打开与播放。
- 工程窗口之间互不影响：各自持有 `Project`、`Engine`、插件实例、撤销栈与编辑器窗口；共享服务（设置、插件缓存、MIDI、音频输出）由 `SharedServices` 统一持有。
- 同一路径只保留一个工程窗口：主页点击项目、`Ctrl+O`、项目栏“打开项目”都会先按小写路径查找根工程与其余窗口，存在则仅置前。
- 关闭根工程窗口时，若主页已作为独立窗口打开且仍有其它工程，则由最近使用的工程接管根窗口（不切回项目列表）；否则根窗口回到主页，并保留主页已有状态（含设置窗口）。关闭主页根窗口且仍有工程窗口时，把一个工程提升到根窗口，避免整个应用退出；关闭最后一个工程窗口回到主页。
- 关闭工程窗口时，`SurfingApp::drop` 先从音频路由移除该引擎、暂停传输、停止后台同步与恢复线程并销毁编辑器；**若工程仍持有插件实例（乐器或效果器），引擎与插件实例不析构，保留至进程结束**。原因是 VOCALOID VSTi / ACE Bridge 等插件会在析构中等待 UI 消息循环，在 UI 线程直接析构会永久卡死，换线程析构又可能触发 `0xC0000005`。纯内置乐器的工程仍正常析构。每个析构阶段都会写 `app.window/window.drop` 日志（含 `phase` 与线程 id），卡死时最后一条 `phase` 即现场。
- 真正退出整个应用的唯一路径是“根是主页且没有任何工程窗口”时关闭根窗口。`WindowHost::ui` 识别到该路径后不再依赖 eframe 的退出链：先写入 `window.exit` 与 `process.exit` 日志记录、写日志尾帧，再直接调用 `TerminateProcess` 结束进程，跳过整条析构链（`SharedServices` → cpal 流 `join` 音频线程 → 音频回调闭包缓存的工程引擎析构插件实例 → 插件 DLL `DllMain(DETACH)` 等待已停止的 UI 消息循环）。若走正常析构，`join` 可能永不返回、`run_native` 永不返回，放在其后的终止逻辑永远执行不到，表现为“关闭软件卡死”或“窗口消失但进程残留”。`WindowHost::on_exit`（eframe 在 drop 应用前调用）与 `main` 中 `run_native` 返回后的调用保留为同一条确定性退出入口的兜底；诊断看门狗再为退出超时兜底一次。

`WindowHost::ui` 每帧：

```text
1. 记录 UI 帧心跳（diag::note_frame）并安装 UI 线程空格钩子
2. 处理根窗口关闭请求：根是工程 → 关闭该工程（主页独立窗口已打开时由其它工程接管根窗口，不切回项目列表）；根是主页且有工程 → 提升一个工程到根窗口；根是主页且无工程 → 写日志并直接终止进程
3. 更新主页的“继续当前工程”可用状态
4. update_window_titles()：为根工程与每个工程视口生成唯一标题，并同步根窗口标题
5. draw_root()：绘制根窗口当前内容（home 或 root 工程）
6. 执行根窗口产生的动作：显示主页 / 打开工程文件窗口 / 新建空白或模板工程窗口 / 回到最近工程
7. draw_home_viewport()：根是工程且主页可见时，绘制独立主页窗口
8. draw_projects()：逐个 show_viewport_immediate 绘制其余工程窗口并收集关闭请求
9. 执行工程视口的动作、移除已关闭窗口、必要时轮询主页后台任务
10. 更新插件心跳开关，并按窗口状态安排下一次重绘（有工程时 16 ms）
11. 记录本帧耗时（超过阈值写 ui.frame.slow）

退出（根是主页且无工程窗口时关闭）：WindowHost::ui → diag::request_exit("home_closed") → 写尾帧 → TerminateProcess
```

`SurfingApp::ui_frame` 每帧：

```text
1. 同步共享设置/插件缓存（按 generation）、解析本窗口原生句柄、更新焦点归属
2. 处理指针手势、编辑器/扫描/MIDI/加载线程
   （service_editors：维护插件编辑器窗口 + 转发处理器参数反馈；hotkeys/heartbeat：独立窗口空格与 UI 心跳）
3. flush_pending_auditions()：把上一帧因引擎锁被占用而暂存的试听事件按顺序补发
4. refresh_engine_snapshot()：一次 try_lock，填充播放头/电平/CPU/自动停止
5. 处理插件参数变化、按 60 ms 节流同步工程
6. 绘制：
   应用栏（自绘窗口按钮、隐藏下拉栏、主菜单、项目栏；主页改用欢迎语）
   工作室视图：工具栏（走带/BPM/拍号/循环/鼠标工具）
   状态栏（状态、CPU、音频设备、MIDI、未保存标记；两种视图共用）
   主页视图：左栏菜单 + 右侧项目/模板/插件/提示页（WorkspaceView::Home）
   工作室视图：底部编辑卷帘（可调整高度，依赖 bottom_open）
   工作室视图：右侧检查器（轨道/乐器/效果器/子轨/通道/主输出）
   工作室视图：中央编曲区
   工作室视图：浮动卷帘窗口（多 viewport，id 含窗口编号）
   插件浏览器 / 乐器窗口 / 效果器窗口 / 帮助 / 粘贴确认 / 加载提示
   独立设置窗口（仅在主页窗口，多 viewport）
   finish_inline_layout：隐藏本帧没有被摆放的内嵌插件编辑器
7. 提交/结束撤销手势，并根据播放/解码/编辑器状态安排下一次重绘
```

空格键有两条来源：应用窗口内由 egui 输入处理，只有最近获得焦点的工程窗口消费；插件编辑器与浮动卷帘等独立窗口由 UI 线程的 `WH_GETMESSAGE` 消息钩子观察（`app/hotkeys.rs`），钩子会忽略已登记的应用窗口，因此不会与 egui 重复处理。钩子只观察、不拦截，插件仍能收到该按键。

浮动卷帘有自己的 egui 视口输入，因此空格只由卷帘视口里的 `handle_keyboard` 处理：窗口获得焦点时会把本工程记为「最近焦点」，钩子捕获的标志位在父工程帧中被消费但不触发切换，避免同一次空格被父窗口与卷帘各切换一次。插件编辑器窗口没有 egui 输入，仍完全依赖钩子。

插件编辑器打开期间，`app/heartbeat.rs` 的后台线程每 16 ms 调用 `egui::Context::request_repaint` 并向 UI 线程投递 `WM_NULL`。原因是 Win32 的 `WM_TIMER` 属于低优先级消息：主窗口被编辑器覆盖或宿主进入空闲等待时，仅靠 `MsgWaitForMultipleObjectsEx` 不会主动处理插件定时器，分析器会停在最后一帧；心跳保证消息循环始终被唤醒并持续渲染插件 GUI。工程窗口在编辑器打开时还会对本视口调用 `request_repaint_after(16 ms)`，即使窗口未获得焦点也持续执行 `service_editors`；独立 VST3 编辑器每帧调用 `PluginWindow::refresh_repaint`（`RedrawWindow` + `RDW_ALLCHILDREN`），防止主窗口聚焦时插件被系统当作不活跃而停帧。

窗口不显示系统标题栏（`ViewportBuilder::with_decorations(false)`）。应用栏负责窗口拖动与双击最大化；窗口最大化时拖动应用栏会先按指针位置把窗口还原到原尺寸，再交给系统拖动（`begin_window_drag`）。`remember_window_rect` 在正常状态持续记录外框，供最大化还原与拖动还原使用。`window_resize_edges` 在窗口四周创建不可见热区并通过 `ViewportCommand::BeginResize` 补回缩放能力；最小化/最大化/关闭按钮同样通过 `ViewportCommand` 驱动，因此窗口外观与交互完全由 egui 绘制。Windows 下最大化由 `app/window_chrome.rs` 读取显示器工作区后手动设置位置与尺寸，避免 DWM 把无边框最大化窗口向外扩 8 像素、导致应用栏与窗口按钮被屏幕边缘裁切。

应用栏与工具栏采用 IDEA New UI 风格（中性灰底、扁平按钮、圆角悬停、右对齐快捷键），编曲区、卷帘、检查器、效果器链、插件浏览器、帮助与各类对话框共用同一套全局主题（见 7.9）。展开“隐藏下拉栏”后左上角保留软件图标，依次显示主页 / 文件 / 编辑 / VST 插件 / 帮助 / 设置：主页与设置是独立入口（分别显示主页窗口、打开设置窗口），不再藏在下拉菜单中；下拉按钮与项目栏隐藏。点击菜单以外的任意区域（含右侧窗口按钮与编辑区）或按 `Esc` 都会收起菜单栏。应用栏整条高度参与垂直居中（`horizontal_centered`），避免左侧控件贴顶。主页视图不显示下拉栏与项目栏，改为小字「欢迎使用SurfingStudio（系统用户名）」（`USERNAME`，其他平台回退 `USER`）。

`SurfingApp` 的实现按职责拆分在 `app/*` 子模块中；它们都通过 `impl SurfingApp` 追加方法，因此状态仍由单一结构体持有，没有跨模块的共享可变状态。面板只读 `ui_*` 快照，写操作通过 `mark_dirty` / `bump_*_revision` 统一进入同步流程。

底部卷帘有三种视图（`BottomView`）：

- `PianoRoll`
- `Controller { track_id, kind }`
- `Effects { track_id }`

主输出使用 `MASTER_TRACK_ID = 0`，可打开主音量控制器卷帘与主效果器链。

交互：

- 触摸屏双指捏合：以捏合中心为锚点横向缩放时间轴（`visible_beats` 仍限制在 8~64 beat）；捏合期间暂停单指拖动，避免第一根手指已开始的拖动继续移动片段或框选。
- 标尺：拖动定位播放头；拖动「起/止」小旗修改循环。
- 片段：拖动移动、拖边缘缩放、`Draw` 工具拖出新片段、`Cut` 工具切割、空白处框选。
- 单片段可垂直拖到其他轨道；目标轨道通过 `accepts_clip` 检查类型冲突。
- 删除/插入音符时，片段前边缘裁剪会同步平移内部音符，保持音乐内容不动。
- 拖入音频文件：落在主轨 → 创建音频片段；落在空白 → 新建音频轨道。
- 主输出：双击主音量子轨打开控制器卷帘；`+` 添加主效果器；底部边缘拖动改高度。
- 轨道列表末尾固定一行「+ 添加 MIDI 轨道」，点击后直接创建默认 MIDI 合成器轨道（不再弹出类型菜单）；工具栏不提供加轨按钮。该行计入 `total_height`，随轨道滚动。
- 单击轨道头部的乐器名称（主轨副标题）打开乐器窗口（见 7.11）；双击主轨其余区域仍进入钢琴卷帘。

### 7.3 钢琴卷帘

- 键盘宽 64 px，标尺高 20 px。
- 水平缩放 1~16（`visible = content_end / zoom`），垂直音高范围自动跟随视口。
- 音阶高亮支持 13 种调式（大调、自然/和声/旋律小调、多利亚、弗里几亚等）。
- 网格吸附：1/4、1/2、1、2 beat 或关闭。
- 工具：选择、绘制、切割；按住 `Shift` 临时切换为绘制。
- 音符操作：移动（可多选）、左右边缘缩放、框选、切割、删除、量化、力度滑块。
- 顶部小节标尺：点击或拖动直接切换播放位置（`seek`），与编曲区标尺行为一致。
- 触摸屏双指捏合：以捏合中心为锚点横向缩放（`piano_zoom` 1~16），捏合期间暂停单指拖动（移动/缩放/框选/标尺定位）。
- 工具条提供量化、力度显示开关、调式与网格；「删除音符」按钮已移除，删除音符统一使用 Delete / Backspace 快捷键。
- 底部力度控制器：工具条右上角「力度」开关控制显示；显示时占卷帘底部最多 84 点（面板高度不足 200 点或高度不足时自动隐藏）。每根竖线对应一个音符起始位置，圆点高度即力度，圆点右侧再画一条与音符等长的横线（`VELOCITY_BAR_H` 线宽），在力度视图里也能直接看出时值；左侧栏显示「力度」与悬停/选中音符的力度读数及参考线；在控制器内按下或拖动会命中最近的音符并按其纵坐标改写力度（1~127），与编辑手势共享撤销。
- 关闭力度控制器后主网格占满整个卷帘；键盘、标尺、网格、片段与音符的命中区域都同步收缩到力度控制器上方。
- `add_note_at` 规则：
  1. 落在现有片段内 → 加入该片段；
  2. 在片段后一小时内 → 向前扩展该片段；
  3. 在片段前一小时内 → 向前扩展并平移内部音符；
  4. 都不满足 → 新建一小节片段。
- 每个轨道保存 `PianoViewState { zoom, view_beat, top_pitch, note_h }`；打开/切换轨道不改变其他已打开卷帘。
- 播放时不再自动把视角拉回播放头，用户可以自由平移。

### 7.4 控制器卷帘

- 可用控制器：音量、声像、延音、弯音四类；力度控制器已移除，改由钢琴卷帘底部的力度控制器编辑。
- 工具：画笔、直线、平滑、擦除。
- 选择模式空白拖拽 → 框选；点击 → 定位播放头。
- 延音按 0/1 阶梯绘制，其他控制器线性连线。
- 主输出音量卷帘值显示为 `value * 150%`。
- 网格吸附与编曲区共享 `snap_beats`。

### 7.5 效果器链卷帘

- 横向卡片布局，默认宽 430，最小 300，可拖右边缘调整（最大 1600）。
- 卡片头部：拖拽排序、双击打开独立窗口、启用开关、关闭按钮、格式徽章（不再放独立窗口按钮）。
- 双击卡片顶部栏任意位置（启用开关与关闭按钮除外）都打开独立编辑器窗口，不要求命中标题文字。
- 滚轮与 `Shift+滚轮` 都左右滑动卡片链；滚动判断改为「指针是否位于卷帘矩形内」，因此指针停在卡片顶部栏时同样生效（内嵌原生窗口覆盖的区域由插件自身处理滚轮）。
- 工具栏右上角不再提供「添加效果器」按钮；点击末尾「+」卡片直接打开效果器选择窗口，内置与 VST 效果器在同一窗口中选择。
- 启用开关位于头部右上角（关闭按钮左侧）：关闭时跳过该效果器的处理，卡片变暗并显示“效果器已停用”，内嵌原生界面隐藏；重新启用后立即恢复。
- 卡片主体：只显示插件原生 GUI（自动内嵌、等比缩放到卡片大小）；VST2 / 无界面 / 内嵌失败时显示提示文本。
- VST3 原生界面内嵌在卡片主体（`EditorWindow::Vst3Inline`）；浮动卷帘不内嵌，双击标题打开独立窗口；两种模式下都持续转发处理器参数反馈，分析器/电平显示正常。
- 卡片宽度固定从 `MIN_CARD_W` 起，不再跟随插件声明的界面尺寸；底部面板高度也不按插件高度撑开。
- 末尾有「+ 添加效果器」卡片。
- 与主输出共享同一套逻辑（`SlotKind::Master`）。

### 7.6 浮动卷帘窗口

- 每个轨道最多一个浮动卷帘：`roll_windows: Vec<RollWindow>`。
- 一个轨道再次请求编辑 → 复用已有窗口、切换内容并置顶（`bring_to_front`）。
- 视口 id 为 `("roll_window", window_id, track_id)` 的哈希；包含所属工程窗口编号，因此多个工程窗口可以同时打开同一轨道号的卷帘。`show_viewport_immediate` 创建真正的 OS 子窗口。
- 窗口启用关闭/最小化/最大化；置顶时先取消最小化再 `Focus`。
- 拖出方式：
  1. **工具条拖拽**：在工具条空白处按下（排除按钮/滑块/下拉框/标题手柄），移动超过 8 px 后创建窗口，并通过 `OuterPosition` 每帧跟随鼠标；
  2. **长按拖拽**：在卷帘画布空白处按住 ≥ 0.45 s 且移动 ≥ 36 px。
- 浮动窗口内隐藏「关闭卷帘」「拖出」等只属于底部面板的控件。
- 独立窗口内容带 `DETACHED_ROLL_MARGIN = 8` 点外边距（工具条标题、卷帘圆角与键盘不再贴住窗口边缘），窗口获得焦点时把本工程设为「最近焦点」，空格由卷帘视口的 `handle_keyboard` 处理。
- 浮动视口的客户区坐标与主窗口不同，因此不在浮动卷帘中内嵌 VST3 GUI；卡片显示提示，双击标题打开独立窗口。

### 7.7 选择语义与剪贴板

- 单击主轨/子轨/片段：只选中，不打开编辑器。
- 双击片段/子轨：打开对应卷帘。
- 双击空白轨道：创建 MIDI 片段并进入编辑。
- 粘贴规则：
  - 片段粘贴回原轨道（保留跨轨复制的空间关系）；
  - 控制器子轨/效果器链若目标已有内容 → 弹出覆盖确认；
  - 音符粘贴到当前片段并限制在片段范围内；
  - 粘贴位置默认在播放头，若与源完全重叠则自动后移一小节。

### 7.8 撤销 / 重做

- 快照式：保存完整 `Project` 克隆。
- 指针手势：按下时记录 `pending_undo`，手势结束且 `edit_seq` 变化才入栈。
- 键盘编辑（Delete 等）直接 `push_undo_now()`。
- 最多 64 步；180 ms 内不重复入栈，避免拖动时产生大量中间状态。
- 撤销/重做后关闭所有插件编辑器、重置播放状态，并校正选择。

### 7.11 乐器窗口

`ui/instrument_picker.rs` 提供按种类浏览并加载乐器的窗口，从轨道头部的乐器名称单击打开。

- 状态：`InstrumentPicker { track_id, category, search }` 存在 `SurfingApp` 中；左侧种类为全部、收藏、钢琴、木吉他、电吉他、弦乐、桥接器、其他。

### 7.13 快捷键

`app/shortcuts.rs` 是快捷键的唯一事实来源：

- `ShortcutAction` 列出全部可绑定动作（传输、文件与编辑、视图、工具与画笔、滑动），每个动作有稳定 id、中文名称、分组与默认绑定（可多组，例如重做为 `Ctrl+Shift+Z` / `Ctrl+Y`）。
- `Binding` 表示“按键 + Ctrl/Shift/Alt”。显示文本使用中文键名（空格、方向箭头），持久化文本使用英文键名并与 `parse` 可无损往返；修饰键必须完全一致才算命中，避免 `1` 与 `Ctrl+1` 混淆。
- `AppSettings::shortcut_bindings` / `shortcut_label` / `shortcut_pressed` / `set_shortcut` / `reset_shortcut` / `reset_all_shortcuts` / `shortcut_conflict` 负责读取、匹配、写入与冲突检测；缺失记录时回退默认值，空字符串表示未绑定。

- 默认新增的控制器画笔动作：`4` 循环切换画笔 → 直线 → 平滑 → 擦除，`Ctrl+1` ~ `Ctrl+4` 直接选择；与顶部鼠标工具（`1` / `2` / `3`）互不影响。
- 主菜单、工具栏提示与帮助窗口都读取 `AppSettings::shortcut_label`，修改后立即同步到所有窗口。

## 8. 音频文件与波形

音频文件采用「音频 I/O 运行时 + 编解码后端」结构，当前注册 `WavCodec` → `SymphoniaCodec` → `AiffCodec`：

- `AudioRuntime::import_audio` 按扩展名分派：WAV 走专用后端；MP3、FLAC、AAC/M4A、OGG Vorbis、AIFF、CAF、ALAC 以及 MKV/WebM 容器中的音频轨走 Symphonia；未知扩展名返回可用格式列表。
- `WavCodec` 支持 WAV 16/24/32-bit int 与 32-bit float；`SymphoniaCodec` 覆盖主流压缩/容器格式并跳过单个损坏包。
- 解码后统一保存为 `left` / `right` 两个 `Vec<f32>`，并生成 512 个 bin 的绝对峰值包络；多声道素材按电影标准系数（中置/环绕 -3 dB、后环绕/LFE -6 dB）下混为立体声。
- 峰值包络随工程保存；加载时先直接恢复峰值用于绘制波形，音频样本由后台线程解码。
- `AudioRuntime::audio_duration_seconds` 优先读容器帧数与采样率；缺少帧数时才完整解码统计。
- 波形在编曲区绘制为镜像峰值线；未加载时显示「音频（未加载）」。
- 导出由 `AudioRuntime::export_with_options` 完成：WAV 支持 16/24-bit PCM 与 32-bit 浮点，AIFF 支持 16/24-bit PCM，均按请求的采样率与声道数写头。`AudioRuntime::supports_import` / `accepts_audio_file` 供拖放与界面判断。

音频片段播放：

- 按源采样率与工程 BPM 计算 `samples_per_beat`。
- 每块根据弯音速率推进源游标；游标连续，弯音变化不会导致跳变。
- 源游标从 `AudioSource::offset_seconds` 起始，因此同一 WAV 可以被多个片段引用不同区段。
- 跳跃/循环回绕时游标按时间轴重新定位。
- 音频片段经过该轨插入效果器，再进入音量/声像与主总线。

## 9. 工程持久化与导出

### 9.1 保存

- 扩展名 `.sfsd`，内容为 SFS2 分块容器：32 字节文件头 + 数据块 + 尾部目录表（TOC）。对话框返回的路径不是 `.sfsd` 时会自动替换为该扩展名，保证只写软件自有格式。
- 数据块：
  - `PLUG`：每个插件状态一块原始字节（不进入清单，避免文本编码膨胀）；
  - `META`：zstd 压缩的 MessagePack 工程清单；
  - `PEAK`：zstd 压缩的波形峰值表（仅保留工程实际引用的音频路径）。
- 每块带 CRC32；TOC 最后写入并校验文件总大小，写入中断不会留下可被误读的半个工程。
- 保存前 `capture_plugin_states` 把 VST3 状态块 / VST2 参数写回工程。
- 序列化与写盘在后台线程完成，先写同目录 `.tmp` 再原子替换；UI 线程只做快照与插件状态抓取。
- 写盘前若开启自动备份，后台线程把现有工程复制到同目录 `Backups/<工程名>-YYYYMMDD-HHmmss.sfsd`（两次备份至少间隔 300 秒），再按设置中的保留数量删除最旧版本。
- 若工程没有路径，弹出保存对话框（起始目录为设置中的默认存储地址）；否则直接覆盖。

自动保存：

- 工程已有路径且存在未保存修改时，UI 线程每隔设置中的 `autosave_seconds` 触发一次与手动保存相同的后台流程（不弹对话框），成功后清除未保存标记，状态栏显示「已自动保存」；`0` 表示关闭。
- 自动保存不重复写入项目列表；没有路径的工程不做文件自动保存，改由崩溃恢复线程写临时文件。
- 关闭确认对话框打开、插件同步进行中、已有保存在进行或正在加载工程时跳过本轮自动保存。

关闭时未保存确认：

- 窗口收到关闭请求时，若 `dirty` 为真（或确认框已打开），发送 `CancelClose` 并绘制模态确认框：保存并关闭 / 不保存 / 取消。
- 「保存并关闭」沿用 `save_project`；保存成功且期间没有新的编辑时，下一帧发送 `ViewportCommand::Close` 完成关闭；保存失败则保留确认框并显示错误。
- 「不保存」清除未保存标记并删除崩溃恢复文件后关闭；点击遮罩或按 Esc 等同于取消。
- 根窗口由 `WindowHost` 先判断：根工程有未保存修改时取消系统关闭，交由工程窗口绘制确认框。

加载/插件同步期间关闭：

- `SurfingApp::can_close_now` 在工程解析或插件同步尚未结束时为 `false`；根窗口与工程视口都先发送 `CancelClose`，再调用 `request_close_when_ready`。
- 尚未应用/尚未开始的加载直接放弃（丢弃 `load_rx`、`loaded_project`，清除 `needs_sync` / `defer_sync`），窗口立即关闭。
- 后台同步已经开始时不能取消：保留“正在停止加载…”提示，等 `engine_sync_rx` 收到结果后由 `ui_frame` 发送 `ViewportCommand::Close`。这样插件不会在初始化中途被析构（VOCALOID 的 `MainWindow.OnClosing` 会在对象未初始化完成时抛 `NullReferenceException`），也不会留下卡死的进程。
- 若后台同步超过 `CLOSE_SYNC_TIMEOUT`（5 秒）仍未结束，窗口强制关闭并设置 `abandon_engine`：`Drop` 泄漏一个引擎强引用，挂起的后台线程之后即使释放自己的引用也不会析构未初始化完成的插件；代价是一次插件实例泄漏，而不是窗口永久卡死。
- 插件实例最终在 UI 线程析构（见 2.2“引擎所有权”）；应用整体退出仍由 `WindowHost::on_exit` 的 `TerminateProcess` 跳过析构链。`main` 另外安装 `SetUnhandledExceptionFilter`：插件抛出的未处理异常直接终止进程，避免 Windows 错误报告把进程留在崩溃对话框里导致外部 `taskkill` 返回“拒绝访问”。

崩溃恢复：

- 每个工程窗口拥有一个常驻恢复线程，UI 线程按 `RECOVERY_SNAPSHOT_INTERVAL`（且编辑序号或工程代次变化时）把 `Project` 快照、波形峰值与目标路径送入 mpsc。
- 线程只保留最后一份快照，并按 `RECOVERY_SAVE_INTERVAL` 写盘；内容未变化时跳过。写入同样经过 `ProjectRuntime`（`.tmp` + 原子替换）。
- 目标路径：已保存工程为同目录 `<名称>.autosave.sfsd`；从未保存的工程为系统临时目录 `SurfingStudio/<工程名>-<窗口编号>.sfsd`。临时文件写入后状态栏提示一次。
- 恢复快照不额外抓取插件运行时状态（避免在 UI 线程频繁阻塞引擎锁），插件状态以最近一次保存时写回的值为准。
- 保存成功且没有新编辑时删除恢复文件；用户选择「不保存」也删除。工程替换时删除旧恢复文件并重置推送标记。

### 9.2 加载

- 原生文件对话框在独立线程运行，以主窗口为 parent。
- 应用层只调用工程运行时框架 `ProjectRuntime::open_project`；框架按扩展名把 `.sfsd` / `.sndp` 分派给对应后端，未知扩展名时依次探测全部可读后端。
- 读取、解压、反序列化与插件状态填充都在后台线程完成；结果先放入 `loaded_project`，下一帧才应用，确保「正在加载工程…」提示至少绘制一帧。
- 应用工程后，插件运行时构建（可能耗时数秒）在**常驻后台同步线程**执行；UI 继续绘制加载提示，绘制路径对引擎使用 `try_lock`，不会冻结。
- 后台同步只创建**效果器**实例（`sync_project_with(.., defer_plugin_instruments = true)`）；VST 乐器实例在后台同步结束后由 UI 线程补载，仍在加载提示期间完成。这样乐器的创建、GUI 与析构始终在同一线程，VOCALOID 等插件不会因跨线程重建窗口而崩溃，播放中打开乐器 GUI 也不会触发阻塞式重建。
- 乐器补载按时间片分帧执行（`Engine::sync_project_slice`，每帧最多 `INSTRUMENT_LOAD_SLICE` = 120 ms，且至少创建一个插件）：`SurfingApp::step_instrument_load` 在 `ui_frame` 中每帧推进一次，加载提示显示「正在加载插件…（已完成/总数）」。这样 20+ 个重型插件（Kontakt、Serum、VOCALOID）也不会出现一次同步阻塞十余秒导致的“未响应”；全部就绪后由 `finish_instrument_load` 收尾并写 `engine.sync.instruments` 日志。关闭加载中的窗口时，分批补载没有进行中的插件初始化，可以直接放弃剩余乐器（`request_close_when_ready`）。
- 同步线程使用 STA COM 并持续泵送消息：插件 GUI 的定时器、Pro-Q 动态界面等依赖该线程存活；线程只持引擎弱引用，工程窗口关闭后不会延长引擎寿命。
- 文件头/TOC/数据块均做 CRC 与长度校验，版本号必须与当前 `CURRENT_PROJECT_VERSION` 一致。
- 应用时：
  - 关闭编辑器、浮动卷帘；
  - 先调用 `close_plugin_owned_windows`：向本进程内由插件创建的可见顶层窗口（VOCALOID6 Editor 等，排除宿主窗口与宿主持有的插件编辑器）发送 `WM_CLOSE`，并泵消息最多 3 秒等待其关闭；这是插件的正常关闭路径，不会触发 WPF `OnClosing` 空引用异常；
  - 窗口全部关闭后再调用 `Engine::shutdown_plugins`（`IComponent::terminate`）并清空身份键；若插件窗口拒绝关闭，则**跳过终止**并记录 `phase=plugin_windows_still_open`，避免 UI 线程被插件模态对话框永久卡住，实例泄漏至进程结束；
  - 旧工程在独立线程析构；
  - 重置播放状态、清空撤销栈；
  - 先用 `PEAK` 块恢复编曲区波形；
  - 若有插件，先显示「正在加载插件…」，再执行同步；
  - 音频 WAV 由后台线程解码，解码完成前对应片段静音，不阻塞界面。

### 9.3 SoundBug 工程导入

实现位于 `core/project_runtime/soundbug/`，作为只读后端 `SoundBugCodec` 接入工程运行时框架。SoundBug 工程由 `.sndp` 清单与 `comp.dat` 两部分组成，导入过程只读原始文件：

1. `.sndp`：魔数 `SNDP` 后跟属性表（工程名等）与媒体表（名称、类型、相对路径、时长），媒体路径相对 `.sndp` 目录解析。
2. `comp.dat`：zlib 压缩的 `EDIT` 树。节点编码为「属性数量 + 属性 + 子节点数量 + 子节点」，数量前缀为 `00` / `01 u8` / `02 u16` / `03 u32`；属性值支持 `01`（短值）、`02`（长值）与 `03`（NUL 结尾状态块）。
3. 值类型：`1` = i32、`2` = bool、`4` = f64、`5` = UTF-8 字符串、`6` = UID、`8` = 嵌套结构；导入使用 `1/2/4/5`，`6/8` 仅跳过。
4. 转换规则：
   - `TEMPOSEQUENCE` 提供 BPM 与拍号；`MASTERVOLUME` 提供主音量。
   - `TRACK` 转为 MIDI 轨道，第一个 VST 插件作为乐器，后续启用的 VST 作为插入效果器；`WAVETRACK` 转为音频轨道。
   - `MIDICLIP` 的 `start` / `length` 为秒，`NOTE.b` / `NOTE.l` 为 beat；`AUDIOCLIP` 的 `start` / `length` / `offset` 为秒，`offset` 写入 `AudioSource::offset_seconds`。
   - 插件状态块会导入并随工程保存；SoundBug 专属的 `reverb` / `level` 等内置效果器不导入；插件路径不存在时回退到内置乐器并记录警告。
5. 插件状态：`PLUGIN.state` 可能是二进制块（tag 3）或带 `.` 分隔的 Base64 文本；导入时解码并写入 `PluginRef::state`，保存为 `.sfsd` 时进入独立 `PLUG` 块。VST3 插件会在加载后调用 `load_state` 恢复；VST2 暂只保留状态数据。
6. 导入完成后 `project_path` 置空，保存时必须另存为 `.sfsd`。

### 9.4 导出

- `Ctrl+E` / 文件菜单 → 打开独立「导出音频」窗口（`app/export.rs` + `ui/export.rs`）；桌面为独立视口，单窗口平台为模态面板。
- 界面采用与设置页一致的卡片布局：顶部摘要卡片（工程名、容器 / 采样率 / 位深 / 布局摘要、输出时长），下方依次为「格式与质量」「声道布局」「渲染范围」「渲染选项」「导出到」分区卡片；底部固定操作栏显示状态、进度条与开始 / 取消 / 关闭按钮。声道与范围使用可点击选项卡片，选中项用强调色描边。
- 窗口参数：容器（WAV / AIFF）、位深（16/24-bit PCM、32-bit 浮点；AIFF 浮点回退 24-bit）、采样率（44.1k ~ 192k）、声道布局（跟随工程 / 2.0 / 5.1 / 7.1）、范围（整个工程 / 循环区间）、尾长（0 ~ 16 beat）、是否使用 GPU、目标路径。
- 点击「开始导出」后：暂停播放 → 抓取插件状态 → 关闭全部插件编辑器 → `Engine::begin_offline_render` 复用**实时引擎与已加载插件实例**开始会话（保存工程 / 走带 / 采样率，应用导出布局，关闭循环与自动停止，定位并 `play`）。会话期间实时回调只输出静音，由界面线程逐帧调用 `Engine::render_offline_step` 推进走带，因此不会在后台线程重新实例化 Kontakt / VOCALOID 等插件（旧实现正是因此崩溃）。
- 每次 `poll_export` 推进 1~64 个 512 帧块，块数按上一帧耗时自适应（> 40 ms 减半，< 10 ms 加倍），重插件下界面仍可刷新。完成后 `Engine::finish_offline_render` 对整段样本做 GPU / CPU 主总线限幅并恢复原工程、走带与采样率，再把样本交给后台线程调用 `AudioRuntime::export_with_options` 写盘；结果通过 mpsc 回传，`poll_export` 更新窗口与状态栏。
- 渲染阶段关闭导出口（标题栏、Esc、底部关闭）或关闭工程窗口时，先 `cancel_export` 恢复实时引擎；写盘阶段不可取消，后台线程写完即丢弃结果。
- 导出不再固定 48 kHz / 16-bit / 立体声；默认路径为工程目录（否则设置中的默认存储地址 / 平台工程目录），切换格式时自动同步扩展名。
- 渲染长度为所选范围；整个工程模式为内容末尾 + 尾长，循环模式为 `loop_start .. loop_end`，循环本身关闭。

### 9.5 工程运行时框架（类 JVM 结构）

工程格式不再由应用层直接处理，而是由 `core/project_runtime` 提供类似 JVM 的运行时：

```text
app::files
  └─ ProjectRuntime（框架）
       ├─ open_project    → 解码任意受支持格式为 ProjectSession
       ├─ save_project    → 把规范工程编码为目标格式
       ├─ translate_project → 解码 → 规范工程 → 编码
       ├─ SfsdCodec       → core/project_runtime/sfsd/（读写）
       └─ SoundBugCodec   → core/project_runtime/soundbug/（只读转译）
```

- **规范表示（IR）**：`core::model::Project` 是框架内部唯一的工程表示；所有后端只负责把外部字节转译成它，或从它编码回去。
- **转译接口**：`ProjectCodec` 提供 `info` / `matches` / `decode` / `encode`；`CodecInfo` 声明格式标识、扩展名以及是否支持读写。
- **运行时**：`ProjectRuntime` 持有后端注册表，默认注册顺序为 `SfsdCodec` → `SoundBugCodec`；`open` 按扩展名分派，未知扩展名时依次探测，`save` 选择可写后端，`translate` 串联解码与编码。
- **会话**：`ProjectSession` 统一承载 `origin`、`project`、`peaks`、`warnings` 与 `ProjectSource`；`ProjectSource::Imported` 表示工程来自外部转译，必须另存为 `.sfsd`。
- **应用层边界**：`app/files.rs` 只调用 `ProjectRuntime::open_project` / `save_project`，**禁止**直接引用 `sfsd` / `soundbug` 后端模块。
- **扩展方式**：新增工程格式时，新增一个实现 `ProjectCodec` 的后端文件夹，并在 `ProjectRuntime::standard` 中注册；应用层无需修改。

### 12.2 已知限制

- 音频导入支持 WAV / MP3 / FLAC / AAC·M4A / OGG Vorbis / AIFF / CAF / ALAC 与 MKV/WebM 音频轨；WMA、APE、Opus 等未接入。导入的多声道素材下混为立体声片段。
- VST1/VST2 提供独立原生窗口；VST3 可在效果器链卡片内嵌（Windows）。
- 工程支持立体声 / 5.1 / 7.1 与每轨通道对路由，但没有侧链与逐声道独立效果链；主效果器固定 2 in / 2 out，只处理前左/前右。设备声道数不足时按 ITU 系数下混。
- ASIO 仅支持 Windows；驱动采样格式支持 16/24/32 位整数、32/64 位浮点与 32 位容器左对齐（Int32LSB16/18/20/24），其它格式仍会回退系统默认设备；ASIO 回调仍按左右声道写出，未映射环绕布局；ASIO 输入通道未接入录音，音频输入设备只记录启用状态。
- 插件参数尚未映射为可编辑的 DAW 自动化轨。
- GPU 音频加速覆盖离线导出与实时主总线终段；实时路径每块最多等待 1 ms，超时回退 CPU，且只处理主总线软限幅（乐器与效果器仍由 CPU 渲染）。GPU 设备不可用、着色器校验失败或驱动丢失时自动回退 CPU。
- GPU 界面渲染（wgpu / DirectX 12 / Vulkan）为实验性路径，需要重启软件后生效；驱动缺失时启动阶段会留在 OpenGL，wgpu 初始化失败还会回退一次 glow。
- 主要验证平台是 Windows；macOS/Linux 需要额外验证音频设备、插件窗口与字体。
- 工程格式为 SFS2 分块容器；插件状态与波形峰值不再以文本形式存储，但超大工程仍受插件实例化与音频解码时间影响。
- SoundBug 导入会保留插件状态块（VST3 可恢复），但不还原 SoundBug 专属内置效果器；插件缺失时使用内置乐器替代。

## 13. 诊断日志

### 13.1 目标与位置

诊断日志用于回答“做了什么、每一步花了多久、卡死/崩溃时停在哪一步”。格式、事件目录与判读方法见 [日志规范](./日志规范.md)。

- 模块：`diag`（`src/diag/mod.rs` 记录与生命周期，`src/diag/format.rs` 编码原语，`src/diag/decode.rs` 解码器）。
- 依赖方向：`diag` 只依赖标准库与 Win32 时间/内存/终止 API；`app` / `audio` / `plugin` 可以调用它，`diag` 不反向依赖任何业务层。
- 文件：`%LOCALAPPDATA%\SurfingStudio\logs\surfing-YYYYMMDD-HHmmss-p<PID>.sflog`，保留最近 20 个。
- 格式：`.sflog` **v2 二进制**——24 字节文件头前缀 + UTF-8 头文本 + 记录序列；每条记录 32 字节头（类型/级别/序号/线程 id/相对时间/UI 帧号/负载长度/CRC32）+ 变长负载。整数小端，字符串为 varint 长度前缀。
- 日志是里程碑级：正常的逐帧绘制、音频回调与逐样本处理**不写日志**；播放中的工程同步只在超过阈值时记录；帧耗时以 600 帧为窗口聚合。

### 13.2 写入模型

- 单一全局 `Mutex<Option<LogSink>>`；每条记录一次 `write_all` 写出“头部 + 负载”，不缓冲——崩溃或强制终止也能保留已写记录。
- 事件负载：`scope`、`event`、`dur_us`（`u64::MAX` 表示无）与键值字段；字段值当前统一为 UTF-8 字符串。
- 文件头写格式版本、启动 Unix 微秒、PID、版本、平台与构建类型；正常退出写 FOOTER 记录（`reason`）。**没有 FOOTER 即非正常退出**。
- 资源记录（每 5 秒一次）：工作集、峰值工作集、私有字节、累计 CPU（100 ns）、句柄数、线程数。
- `Span` 提供耗时区间：`start_logged` 立即写 `phase=begin`（卡死时最后一条 begin 即现场），`end` / `end_slow` 写 `phase=end` 与 `dur_us`。
- `write_record` 先检查 `finished`：写完尾帧后不再追加任何记录。
- 读取：`diag::decode_log_file` / `export_text`（`surfing-studio.exe --decode-log <文件>` 生成同名 `.txt`），校验魔数、版本与每条记录的 CRC32。

### 13.3 监控与崩溃路径

| 机制 | 触发条件 | 记录 |
| --- | --- | --- |
| 慢帧 | 单帧绘制 ≥ 120 ms（1 秒最多一条） | `WARN app.ui ui.frame.slow`，带 `dur_ms` 与当前 `phase` |
| 帧聚合 | 每 600 帧 | `INFO app.ui ui.frames`，带 `frames` / `avg_us` / `max_us` |
| 卡死 | UI 线程 ≥ 3 s 没有新帧（15 秒内不重复） | `WARN app.ui ui.stall`；恢复时 `INFO ui.resume` |
| 资源占用 | 每 5 秒 + 卡死上报时 | RESOURCE 记录（内存/CPU/句柄/线程） |
| panic 钩子 | 任意线程 panic | `FATAL app.panic panic`，带 `message` 与 `location`，再交给原钩子 |
| 未处理异常 | Windows 顶层异常过滤器 | `FATAL app.crash unhandled_exception`，带 `exception_code`，随后终止进程 |
| 退出超时 | 已请求退出但 3 s 后仍存活 | `FATAL app.exit process.exit.timeout`，看门狗再次终止进程 |

`phase` 由 `diag::set_activity` 在 UI 各阶段写入（`ui.frame` / `ui.poll` / `ui.paint` / `plugin.editors` / `plugin.editor` / `engine.sync` / `project.export`），用于把卡死定位到具体步骤。写入使用 `try_lock` 或短锁，不会成为卡死的放大因素。资源采样通过 `psapi` / `tlhelp32` 读取当前进程指标，失败时整条记录跳过。

### 13.4 确定性退出

`diag::request_exit(reason)` 是进程级退出入口：写 `process.exit` 记录与尾帧，然后 `TerminateProcess`。它在以下位置被调用：

1. `WindowHost::ui`：根是主页且没有工程窗口时收到关闭请求（正常退出主路径）；
2. `WindowHost::on_exit`：eframe 在 drop 应用前回调（兜底）；
3. `main`：`run_native` 返回后（兜底）。

调用前会把退出截止时间写入看门狗（3 s）；即使终止调用本身被驱动或插件阻塞，看门狗仍会补一次强制结束。插件与音频设备一律不走析构链，由操作系统回收。

关闭**单个工程窗口**（应用继续运行）不经过 `request_exit`，而是 `SurfingApp::drop`：它也会写阶段日志（`app.window/window.drop`）。当工程含插件实例时，引擎（含插件实例）被保留而不是析构——这是为了绕开插件析构死锁/崩溃；日志中对应 `phase=engine_retained`。
