## 1. 架构与依赖方向

### 1.1 分层结构

```text
main.rs                 薄二进制入口：只创建 eframe 窗口
  └─ lib.rs             库根：声明模块，re-export SurfingApp
       ├─ core          纯数据模型、工程容器、导出、MIDI 输入
       ├─ platform      平台运行时（类 JVM）：统一内部 API + 各系统后端（叶子模块）
       ├─ plugin        VST3 / VST2 宿主封装与扫描
       ├─ audio         实时音频引擎（含实时渲染与离线导出）、内置乐器、cpal 输出、WAV 解码
       ├─ diag          进程级诊断日志、耗时区间、卡死/崩溃监控与确定性退出（叶子模块）
       ├─ app           SurfingApp 状态机、命令、撤销、文件与插件编排
       └─ ui            egui 视图：编曲区、钢琴卷帘、控制器、效果器、检查器、浏览器
```

### 1.2 各层职责

| 层 | 职责 | 典型文件 |
| --- | --- | --- |
| `core` | 只描述工程数据与纯规则，不依赖音频/GUI/插件运行时 | `core/model/*`、`core/project_runtime/*` |
| `platform` | 平台运行时框架：存储目录、文件对话框、能力位与确定性退出；只按目标系统选择后端 | `platform/mod.rs`、`platform/backend.rs`、`platform/backends/*` |
| `plugin` | 插件运行时框架：后端注册、加载/扫描分派、统一运行时、独立编辑器窗口 | `plugin/backend.rs`、`plugin/host.rs`、`plugin/runtime.rs`、`plugin/editor.rs`、`plugin/backends/*` |
| `audio` | 实时回调、音符事件表、内置乐器、音频 I/O 运行时、离线导出、系统输出 | `audio/engine/*`、`audio/synth/*`、`audio/io/*`、`audio/backend.rs` |
| `diag` | 进程级诊断日志、耗时区间、UI 卡死/慢帧看门狗、panic/崩溃记录、确定性退出 | `diag/mod.rs`、`diag/format.rs` |
| `app` | 每窗口 `SurfingApp` 状态、多窗口外壳 `WindowHost`、共享服务、编辑命令、撤销、文件/插件流程 | `app/mod.rs`、`app/shell.rs`、`app/shared.rs` 及同层子模块 |
| `ui` | 立即模式绘制与交互，把用户意图转成 `SurfingApp` 方法调用 | `ui/**` |

### 1.3 依赖规则（必须）

1. `core` **禁止** `use crate::audio`、`crate::plugin`、`crate::app`、`crate::ui`。
2. `plugin` **禁止** 依赖 `crate::audio::engine`、`crate::app`、`crate::ui`；只允许使用 `core::model` 与 `audio::synth` 的事件类型。
3. `audio` **禁止** 引入 `app` / `ui`；实时渲染与离线导出都留在 `audio/engine/` 内。
4. `app` 是唯一编排层。加载工程、保存、播放、插件加载、后台任务、撤销等跨层流程只能放在 `app`。
5. `ui` 可以引用底层类型（如 `core::model`、`audio::SlotKind`、`plugin::ParamView`），但 **禁止** 在 UI 文件中实现工程 IO、插件加载、实时渲染调度或音频处理。
6. `main.rs` **禁止** 承载业务逻辑；所有可测试逻辑必须放在库中。
7. `app` / `ui` 只能通过对应运行时框架使用外部格式：工程格式用 `core::project_runtime::ProjectRuntime`，插件格式用 `plugin::PluginHost`，音频文件用 `audio::io::AudioRuntime`；**禁止**直接 `use` 任何后端模块。
8. 实时音频回调内 **禁止** 通过 `dyn` 后端分派、分配内存或加载插件；实时 DSP 使用封闭枚举（如 `InstrumentRuntime`），后端选择必须在同步阶段完成。
9. 不新增循环依赖。若确实需要跨层引用，先修改 [技术文档](./技术文档.md) 的架构章节，再写代码。
10. `diag` 是叶子模块：**禁止**依赖 `core` / `plugin` / `audio` / `app` / `ui`；各层只能单向调用它写日志。实时音频回调内 **禁止**调用 `diag`。
11. `platform` 是叶子模块：**禁止**依赖 `core` / `plugin` / `audio` / `app` / `ui`（含 `diag`）；`app` / `ui` / `diag` / `main` 只能通过 `PlatformRuntime`（或同文件内的模块级快捷函数）访问平台能力，**禁止**直接 `use platform::backends::*`，也**禁止**在业务代码里散落 `cfg(target_os = "android")` 来区分行为——平台差异必须表达为 `PlatformCaps` 能力位或后端实现。

### 1.4 “这段代码放哪”判定表

| 想做的事 | 正确位置 |
| --- | --- |
| 新增工程字段、轨道规则、片段规则 | `core/model/` |
| 新增工程文件格式/序列化 | `core/project_runtime/`（实现 `ProjectCodec` 并在 `ProjectRuntime` 注册） |
| 新增插件格式 | `plugin/backends/`（实现 `PluginBackend` 并在 `PluginHost` 注册） |
| 新增音频文件格式 | `audio/io/`（实现 `AudioCodec` 并在 `AudioRuntime` 注册） |
| 新增 WAV 导出策略 | `audio/io/wav/`（实现 `AudioCodec::encode`） |
| 新增内置乐器/鼓机 | `audio/synth/` |
| 修改实时混音、门限、总线 | `audio/engine/render.rs` |
| 修改音符事件表、事件游标、离线导出 | `audio/engine/render.rs` |
| 修改插件参数/编辑器 API | `audio/engine/plugins.rs` 或 `plugin/runtime.rs` |
| 新增用户命令、快捷键、文件流程 | `app/edit.rs`、`app/input.rs`、`app/files.rs`、`app/transport.rs` |
| 新增面板/卷帘/绘制 | `ui/` |
| 新增应用级状态字段 | `app/mod.rs` + `app/state.rs`（仅 UI 状态类型） |
| 新增日志事件、耗时区间或日志格式 | `diag/mod.rs`（记录与生命周期）、`diag/format.rs`（编码原语）；格式变更还必须同步 `diag/decode.rs` 与 `FORMAT_VERSION`，调用点只在对应业务层 |
| 新增进程退出路径 | `diag::request_exit`（写尾帧 + 终止进程），**禁止**自行调用 `std::process::exit` |
| 新增平台差异（目录、对话框、窗口能力、退出方式） | `platform/`（新增能力位放 `PlatformCaps`，新增系统实现放 `platform/backends/`） |
| 新增/修改安卓打包（清单、ABI、SDK 版本） | `platforms/android/`（`AndroidManifest.xml`、`build.ps1`、入口 `src/lib.rs`） |

### 1.5 统一模块框架规范（运行时 + 后端）

所有存在多种实现或文件格式的领域 **必须** 采用同一结构，禁止在应用层写格式分支：

| 角色 | 命名 | 职责 |
| --- | --- | --- |
| 运行时 | `XxxRuntime` / `XxxHost` | 持有后端注册表，暴露唯一上层入口 |
| 后端接口 | `XxxBackend` / `XxxCodec` | 能力描述 + 解码/编码、加载/扫描 |
| 能力描述 | `XxxInfo` | 标识、名称、扩展名/格式、读写能力 |
| 会话/结果 | `XxxSession` / `XxxFile` / `XxxRuntime` | 后端返回的统一数据契约 |
| 后端实现 | `backends/` 或格式文件夹 | 只负责单一格式，不感知 UI |

**强制规则**

1. 应用层只调用运行时；**禁止**直接 `use` 任一后端模块。
2. 运行时按扩展名/格式分派；扩展名未知时可按注册顺序探测。
3. 后端导入路径只读源文件；不得直接修改 `SurfingApp`、UI 或编辑器状态。
4. 后端统一返回 `Result<_, String>`，错误文本使用中文并包含格式上下文。
5. 新增实现只需新增后端并在运行时注册，应用层代码零修改。
6. 只有单一实现的基础设施（cpal 输出、midir 输入）可以保留单一入口函数，但同样不得依赖 `app` / `ui`。
7. **实时例外**：音频回调内禁止 `dyn` 后端分派、堆分配或插件加载；实时 DSP 使用封闭枚举（如 `InstrumentRuntime`），后端选择必须在同步阶段完成。

**当前模块映射**

| 领域 | 运行时 | 后端 | 会话/结果 |
| --- | --- | --- | --- |
| 工程格式 | `ProjectRuntime` | `ProjectCodec`（sfsd / soundbug） | `ProjectSession` |
| 平台能力 | `PlatformRuntime` | `PlatformBackend`（desktop / android） | `PlatformInfo` / `PlatformCaps` / `FileRequest` |
| 插件格式 | `PluginHost` | `PluginBackend`（vst3 / vst2） | `PluginRuntime` |
| 音频文件 | `AudioRuntime` | `AudioCodec`（wav） | `AudioFile` |
| 实时乐器 | `InstrumentRuntime`（封闭枚举） | `PolySynth` / `DrumKit` / `PluginRuntime` | 音频缓冲 |
| 系统输出 / MIDI | `start_output` / `MidiInputManager` | cpal / midir | `AudioOutput` / 事件队列 |
| 数据 / 状态 / UI | `core::model` / `SurfingApp` / `ui` | 无后端 | `Project` / UI 快照 |

## 2. 文件与模块组织

### 2.1 基本规则

- 每个 `.rs` 文件 **必须** 以 `//!` 模块文档开头，一句话说明职责；多职责时用列表补充（见 `audio/engine/mod.rs`、`plugin/mod.rs`）。
- 文件名使用 `snake_case`，按“领域职责”命名，不按“技术手段”命名。
- 一个文件只承担一个主要职责；当一个文件出现第二类职责（例如同时做数据解析与 UI 布局）时，应拆分。
- 文件接近 600~800 行且仍在增长时，**应当** 评估拆分；拆分依据是职责边界，而不是行数。
- **禁止**在 `src/` 根目录新增临时脚本、备份文件、实验文件；调试代码放临时目录或 `target/`，不得提交。

### 2.2 `mod.rs` 规范

`mod.rs` 只做三件事：声明子模块、re-export 对外类型、放极少量跨子模块共享的枚举/常量。

```rust
//! 模块职责说明。

mod clip;
mod controller;
mod project;
mod track;

pub use clip::{Clip, Note};
pub use controller::{ControllerKind, ControllerLanes};
pub use project::Project;
pub use track::Track;

pub const CURRENT_PROJECT_VERSION: u32 = 2;
```

- 实现代码放子文件，**不要**在 `mod.rs` 堆积大段逻辑。
- 对外只 `pub use` 真正需要跨模块使用的类型；其余保持私有。
- 子模块内部共享给父模块的辅助函数/常量使用 `pub(super)`，不要为了省事全部 `pub`。

### 2.3 子模块拆分模式

- `app/`：按状态机职责拆分，每个文件通过 `impl SurfingApp` 追加方法，**不引入第二个应用状态结构体**。
- `ui/`：一个视图一个文件；`mod.rs` 只放共享的视图类型（`BottomView`、`MouseMode`、`Drag` 状态等）。
- `audio/engine/`：按职责拆分（`mod` 状态/同步、`plugins` 插件 API、`render` 实时渲染与离线导出）。
- `ui/arrangement/`、`ui/piano_roll/`：`mod.rs` 放交互，`layout.rs` / `helpers.rs` 放几何、常量与纯函数。
- `helpers.rs` 只放该领域专属的纯函数与常量；**禁止**建立跨领域的 `utils.rs` 垃圾桶。

### 2.4 可见性

- 默认私有；只有 UI、测试或同层模块确实需要时才提升。
- `pub(crate)` 优先于 `pub`；仅库对外 API 使用 `pub`。
- 不保留“以后可能有用”的未使用类型/函数；确认无用后直接删除，不用 `#[allow(dead_code)]` 掩盖。

## 3. 命名规范

### 3.1 通用 Rust 命名

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| 模块/文件/函数/变量 | `snake_case` | `render_chunk`、`audio_cursors` |
| 类型/枚举/特征 | `PascalCase` | `TrackEngine`、`PluginRuntime` |
| 枚举变体 | `PascalCase` | `PluginRuntime::Failed` |
| 常量/静态 | `SCREAMING_SNAKE_CASE` | `CURRENT_PROJECT_VERSION`、`MASTER_TRACK_ID` |
| 生命周期/泛型 | 短小大写 | `'a`、`T` |

- 不随意缩写；已确立的领域缩写可以沿用：`bpm`、`ppb`（points per beat）、`ppp`（pixels per point）、`uid`、`vst`。
- 索引变量使用完整名：`track_index`、`clip_index`、`note_index`，不要用 `i`/`idx` 表示业务索引（循环计数器除外）。
- 布尔值以 `is_`、`has_`、`can_`、`supports_`、`accepts_`、`uses_` 开头。

### 3.2 方法与函数前缀

| 前缀 | 语义 | 示例 |
| --- | --- | --- |
| `ui_` | 绘制/交互入口 | `ui_arrangement`、`ui_piano_roll_for` |
| `poll_` | 轮询后台结果（非阻塞） | `poll_load_project`、`poll_scan` |
| `handle_` | 处理输入事件 | `handle_keyboard` |
| `service_` | 维护外部对象生命周期 | `service_editors` |
| `begin_` / `end_` | 长任务或手势的起止 | `begin_edit_gesture`、`begin_engine_load` |
| `open_` / `close_` | 打开/关闭窗口、编辑器、面板 | `open_editor`、`close_all_editors` |
| `toggle_` | 二态切换 | `toggle_play` |
| `apply_` / `remove_` / `add_` | 对模型或运行时执行确定修改 | `apply_plugin`、`remove_effect_at` |
| `ensure_` | 保证运行时对象与模型一致，必要时重建 | `ensure_instrument`、`ensure_effects` |
| `sync_` | 把模型状态推送到运行时 | `sync_project`、`sync_engine` |
| `refresh_` | 刷新缓存/快照 | `refresh_engine_snapshot` |
| `invalidate_` | 使缓存失效 | `invalidate_plugin_params` |
| `cached_` | 返回带缓存的数据 | `cached_plugin_params` |
| `bump_` | 递增 revision/序号 | `bump_clip_revision` |
| `mark_` | 标记状态位 | `mark_dirty` |
| `validate_` | 修正非法状态 | `validate_selection` |
| `format_` | 生成展示文本 | `format_position` |
| `render_` | 渲染 | `render_chunk`、`render_offline` |
| `install_` / `fail_` | 发布后台结果 | `install_audio_file`、`fail_audio_file` |
| `take_` | 取走并清空内部数据 | `take_audio_requests` |
| `clear_` | 清空集合/缓存 | `clear_history`、`clear_audio_cursors` |

### 3.3 单位后缀（必须）

音频与时间代码最容易出错，字段/变量/参数 **必须** 带单位：

| 单位 | 后缀/命名 | 类型 |
| --- | --- | --- |
| 拍（四分音符） | `_beats`、`start_beat`、`end_beat`、`view_beat` | `f64` |
| 秒 | `_seconds`、`length_seconds` | `f64` |
| 采样率 | `sample_rate` | `f64` |
| 块大小/帧数 | `block_size`、`frames` | `usize` |
| 增益/归一化值 | `level`、`volume`、`pan`、`value` | `f32` |
| egui 逻辑点 | `_w`、`_h`、`_x`、`_y`、`_pos` | `f32` |
| 物理像素 | 仅在 DPI 转换处出现，变量名带 `px` 或注释说明 | `f32` |

- 新增时间字段禁止使用含糊的 `start`、`length`、`pos`；必须说明是 beat 还是 seconds。
- 常量同样带单位：`RULER_H`、`MASTER_MIN_H`、`RENDER_TAIL_SECONDS`、`SCAN_INTERVAL`。

### 3.4 状态字段命名

- UI 只读快照：`ui_playhead`、`ui_playing`、`ui_levels`、`ui_waiting` 等，统一 `ui_` 前缀。
- 待处理/跨帧状态：`pending_play`、`pending_undo`、`pending_undo_seq`。
- 时间戳：`last_engine_sync`、`last_undo_at`、`plugin_param_cache_at`。
- 实时线程复用缓冲：`*_scratch_l` / `*_scratch_r`。
- 缓存容器：`*_cache`、`*_keys`、`*_requests`，并在字段上注释失效条件。

## 4. 数据模型与工程持久化

### 4.1 数据模型保持“纯”

- `core/model/*` 只包含数据、派生规则和小型纯函数（如 `Clip::end`、`Track::accepts_clip`、`Project::auto_stop_beat`）。
- **禁止**在模型层引入 `egui`、`cpal`、`vst3-host`、文件 IO 或线程。
- 模型派生规则只写一次：UI/引擎需要判断轨道类型、控制器有效性时，调用 `Track::is_audio_lane`、`supports_controller`、`accepts_clip`，**禁止**在 UI 里复制同一套判断。

### 4.2 时间与数值类型

- 工程内时间统一为 **beat**；秒只出现在音频文件、渲染尾音、超时与 UI 提示中。
- `f64` 用于 beat、秒、采样率；`f32` 用于采样、增益、归一化参数；`u8` 用于 pitch/velocity；`u64` 用于 ID。
- 浮点比较使用显式 epsilon（如 `1e-6`、`1e-9`），不要直接 `==`。

### 4.3 ID

- `TrackId = u64`；真实轨道从 1 开始；`MASTER_TRACK_ID` 是主输出伪轨道（具体值见 [关键常量](./关键常量.md)）。
- 新 ID 统一使用 `max + 1`（`Project::next_track_id` / `next_clip_id`），**禁止**使用随机数或时间戳。
- UI 选择使用索引，引擎/运行时时序使用 `(TrackId, clip_id)`。跨边界时必须显式转换，并在结构变更后调用选择校验。

### 4.4 revision 与实时更新

- `Track::revision` / `Clip::revision` 表示“听感内容版本”，**必须**在乐器、效果器、控制器、音符、片段内容变化时递增。
- 优先调用 `bump_track_revision` / `bump_clip_revision` / `bump_revision()`，不要手写 `revision += 1`。
- `revision` 不持久化：`#[serde(skip, default = "default_revision")]`。
- `Clip::revision` 参与音符事件签名：音符或片段时间变化后必须 bump，否则实时事件表不会重建；`Track::revision` 只表示轨道听感版本，不参与事件签名。
- 仅改变 UI 展示（颜色、展开状态、名称）不需要 bump；改变声音必须 bump。

### 4.5 serde 兼容（必须）

新增 `Project` / `Track` / `Clip` 字段时：

1. 加 `#[serde(default)]` 或 `#[serde(default = "default_xxx")]`，保证旧工程可读。
2. 同步更新 `Default` 实现与必要的示例工程。
3. 运行时字段（缓存、revision、编辑器句柄）使用 `#[serde(skip, default = "...")]`。
4. 不重命名已持久化字段；确需重命名时提供 `#[serde(alias = "旧名")]` 或迁移逻辑。
5. 新增字段后补一个序列化往返测试。

```rust
#[serde(default = "default_time_sig_num")]
pub time_sig_num: u8,

#[serde(skip, default = "default_revision")]
pub revision: u64,
```

### 4.6 工程格式版本

- `CURRENT_PROJECT_VERSION` 表示清单结构版本；容器格式版本为 `core/project_runtime/sfsd/container.rs` 的 `FORMAT_VERSION`（具体值见 [关键常量](./关键常量.md)）。
- 发生不兼容变更时必须同时递增对应版本，并在加载时拒绝未知版本，不做“猜测式兼容”。
- 插件状态（`PluginRef::state`）以独立 `PLUG` 块存储，禁止以内联数组写进清单；保存前必须先抓取运行时状态。

## 5. 实时音频线程规范

### 5.1 线程分工

| 线程 | 允许做的事 | 禁止做的事 |
| --- | --- | --- |
| 主线程/UI | 绘制、编辑工程、插件 GUI、工程同步 | 长时间持引擎锁、同步解码大文件 |
| cpal 回调 | `Engine::process`、实时渲染、软限幅 | 分配、阻塞、加锁等待、文件 IO、日志、UI 调用 |
| 扫描/加载线程 | 插件扫描、工程解析、WAV 解码 | 直接修改 UI 状态（必须回传主线程） |

### 5.2 实时回调硬性规则（必须）

1. 使用 `try_lock`，**禁止**在回调中 `lock()` 等待。
2. 回调中 **禁止** 堆分配、`format!`、`println!/eprintln!`、文件/网络 IO、插件扫描、创建插件实例。
3. 所有可能扩容的缓冲必须在 `sync_project` 或首次调用前准备好，回调内只复用 `*_scratch_*`。
4. 每个 block 的扫描必须基于同步阶段预计算的结果：音符事件表、`any_solo`、`auto_stop_at`、`has_audio_clips`。
5. 轨道运行时按 `Project::tracks` 顺序对齐，回调内用索引访问，禁止按 id 线性查找。
6. **禁止** `unwrap()` / `expect()` / `panic!`；出现异常状态时静音或跳过该轨，而不是让音频线程崩溃。
7. 处理函数必须可重入且状态自洽：循环回绕要关闭挂音并重置事件游标；停止/定位要清理活动音符。

### 5.3 实时渲染规则

- 所有 MIDI 片段都在音频回调中实时渲染，**禁止**重新引入片段预渲染缓存或后台渲染线程。
- 音符事件在 `sync_project` 中预计算，回调内只推进 `event_cursor`；派生签名使用确定性 FNV-1a，**禁止**加入指针、时间戳或随机数。
- 音频片段始终实时流式读取，**不得**进入任何缓存。
- 主效果器、主音量与软限幅只在播放输出阶段应用一次，不得在其他路径重复饱和。
- 渲染相关阈值见 [关键常量](./关键常量.md)；变更时同步更新技术文档与框架工作流。

### 5.4 新增音频行为

- 新增内置乐器：在 `audio/synth/` 实现 voice/note 逻辑，并在 `InstrumentRef` 与检查器 UI 接入；不要直接塞进 `render.rs`。
- 新增效果处理：通过 `PluginRuntime` 或 synth 模块完成；引擎只负责串联与缓冲交换。
- 修改混音顺序时保持现有链路：乐器 → 插入效果器 → 音量/声像 → 主效果器 → 主音量 → soft clip。
- 主输出软限幅拐点以下必须完全线性（拐点值见 [关键常量](./关键常量.md)），不得引入额外饱和。

## 6. `SurfingApp` 状态与同步

### 6.1 单一所有权

- 每个窗口只有一个 `SurfingApp`（主页窗口一个，每个工程窗口一个）；`app/*` 与 `ui/*` 通过 `impl SurfingApp` 追加方法。
- 跨窗口数据只能放在 `SharedServices`（`app/shared.rs`）：全局设置、插件缓存、MIDI 输入、唯一音频输出与 `AudioRouter`。**禁止**再新建其他全局应用状态或跨模块共享可变静态变量。
- 窗口生命周期只由 `WindowHost`（`app/shell.rs`）管理；窗口之间的通信使用 `WindowAction` 队列，**禁止**让一个窗口直接持有另一个窗口的引用。
- 新字段加在 `app/mod.rs`，并写一行注释说明生命周期/失效条件；同时更新 `build()` 初始化。
- 仅 UI 使用的临时状态类型放 `app/state.rs`；会被保存的工程数据放 `core/model`。

### 6.2 每帧编排顺序（不得随意插队）

`WindowHost::ui` 负责窗口级编排，`SurfingApp::ui_frame` 负责单个窗口：

`WindowHost::ui`：

1. 安装 UI 线程空格钩子，处理根窗口关闭请求（根是工程则关闭该工程回到主页；根是主页且有工程则提升一个工程到根）。
2. 更新主页的“继续当前工程”状态与根/工程窗口标题。
3. 绘制根窗口：根工程或主页。
4. 执行根窗口的动作，再绘制独立主页视口与其余工程视口，并收集关闭请求。
5. 执行工程视口动作、移除已关闭窗口，并在主页未绘制时轮询其后台任务。
6. 更新插件心跳开关并安排下一次重绘。

`SurfingApp::ui_frame` 的顺序是正确性的一部分：

1. 同步共享设置/插件缓存（按 generation）。
2. 更新窗口句柄与焦点归属，首次帧应用主题。
3. 指针按下 → `begin_edit_gesture()`。
4. `service_editors` / `poll_scan` / `poll_midi` / `poll_load_project` / `poll_save_project`。
5. `refresh_engine_snapshot()`：每帧只做一次引擎 `try_lock`，填充全部 `ui_*` 字段。
6. `handle_keyboard`、`validate_selection`、`update_roll_drag`。
7. 处理插件参数变化与会话状态。
8. 按需 `sync_engine()`（播放中按关键常量中的同步间隔节流）。
9. 处理自动停止状态。
10. 绘制面板与窗口。
11. 提交/结束撤销手势，并按播放状态请求重绘。

新增的每帧逻辑必须插入到语义对应的位置；**禁止**在绘制函数内部做后台轮询或长时间同步。

### 6.3 修改工程数据的唯一入口

- 任何会改变工程内容的写操作，结束后必须调用 `mark_dirty()`。
- 改变听感内容时，调用 `bump_track_revision` / `bump_clip_revision`（内部已处理 `dirty` 与 `needs_sync`）。
- **禁止**在业务代码中手写 `self.needs_sync = true`（加载/新建/撤销等内部流程除外）。
- 不要在面板里各自实现同步节流；统一由 `ui()` 中的同步节流逻辑处理（间隔见 [关键常量](./关键常量.md)）。

### 6.4 UI 快照与锁

- 绘制期间只读 `ui_*` 快照，**禁止**在每个面板里 `engine.lock()` 读播放头/电平/CPU。
- 必须读引擎数据时：
  1. 克隆需要的数据；
  2. 立即 `drop(guard)`；
  3. 再进入 UI 闭包。
- 插件参数列表统一走 `cached_plugin_params`（缓存间隔见 [关键常量](./关键常量.md)），不要每帧从引擎克隆。
- 工程同步只在 `sync_engine` 中短时持锁；音频回调不等待任何后台渲染任务。

### 6.5 后台任务

- 所有耗时任务（文件对话框、工程加载、保存、WAV 解码、插件扫描）走后台线程 + `mpsc`，主线程通过 `poll_*` 非阻塞接收。
- 后台线程**禁止**直接修改 `SurfingApp`；只能回传数据。
- 结果需要延后一帧应用时，使用现有 `loaded_project` / `loading_until` 模式，保证提示可见。
- 保存使用 `project_epoch` 防止迟到的写回覆盖新工程。
- 大对象（旧工程、撤销栈）在独立线程析构，避免卡帧。

### 6.6 选择与撤销

- 选择状态使用索引；结构变化后必须 `validate_selection()`，必要时关闭失效卷帘。
- 指针手势统一 `begin_edit_gesture` → `commit_edit_gesture` / `end_edit_gesture`；键盘编辑使用 `push_undo_now()`。
- 撤销栈深度与合并窗口见 [关键常量](./关键常量.md)；不要在具体命令里重复实现历史逻辑。
- 撤销/重做后必须清理编辑器、重置播放状态与失效选择（复用 `after_history_apply`）。
- 选中语义保持：单击只选中，双击才打开编辑器。

## 7. UI 规范

### 7.1 结构

- 每个视图一个 `impl SurfingApp` 方法，命名 `ui_<view>`；浮动/嵌入变体用后缀区分（`ui_piano_roll_for(..., detached)`）。
- 纯几何计算、常量、绘制小函数放同目录 `layout.rs` / `helpers.rs`，用 `pub(super)` 暴露给 `mod.rs`。
- 绘制函数只负责“读状态 → 计算矩形 → 交互 → 发意图”；业务规则调用 `app`/模型方法。
- 不在 UI 文件里写文件 IO、插件加载、线程创建、音符事件表或渲染调度。

### 7.2 视觉与常量

- 颜色**必须**来自 `ui/theme.rs`（`ACCENT`、`TEXT_DIM`、`PANEL` 等）；局部透明色使用 `theme::with_alpha`。具体配色、表面层级与交互状态见 7.6“IDEA New UI 视觉规范”。
- 布局常量定义在文件顶部，`SCREAMING_SNAKE_CASE` 且带单位：`DEFAULT_CARD_W`、`HEADER_H`、`KEYBOARD_W`。
- 字体、全局缩放与控件高度只在 `theme::setup/apply_style` 设置（具体值见 [关键常量](./关键常量.md)）；**禁止**在面板里另设字体或 `set_zoom_factor`。
- 新增可复用绘制（电平表、按钮样式等）放 `theme.rs`，不要在多个视图复制。

### 7.3 借用与事件收集

立即模式 UI 中避免“持借用再可变调用”：

- 需要修改数据时，先克隆小对象（单个 `Clip`、`Vec<ParamView>`）或收集意图；
- 在闭包内用局部 `Option` / `Vec` 记录动作，闭包结束后统一执行（参考 `ui/inspector.rs` 的 `track_changed`、`open_editor`、`param_changes`）；
- 不要在 UI 闭包内长期持有 `self.engine.lock()` 的 guard。

### 7.4 交互与文案

- 单击选中，双击打开/进入编辑；按住 `Shift` 临时切换绘制工具；工具切换保持 1/2/3。
- 图标按钮必须提供 `.on_hover_text(...)`；危险操作（删除、覆盖）要有明确提示或确认。
- 所有面向用户的文案使用简体中文；技术品牌/格式名保留原文（VST3、BPM、WAV）。
- 空状态、加载中、失败态都要有可见反馈，不允许“看起来能点但无反应”。
- 不新增与现有快捷键冲突的组合；快捷键统一注册在 `app/shortcuts.rs`，新增时必须同步更新帮助窗口、`doc/关键常量.md` 与 `doc/项目简介.md`。

### 7.5 坐标系与 DPI（必须）

- egui 内部统一使用逻辑点；行高、间距、卡片宽度均为逻辑点。
- 插件编辑器使用 `EditorRect` 时必须区分平台坐标系：Windows / X11 原生子窗口使用物理像素，`EditorRect` 由逻辑点乘 `pixels_per_point` 得到；macOS 使用点数，保持 1.0。插件返回的接受尺寸同样是物理像素，换算回卡片点时除以缩放系数。
- 窗口尺寸/位置使用 monitor 空间时，明确注释坐标系（参考 `RollDragState`、`vst3-host` 窗口逻辑）。

### 7.6 IDEA New UI 视觉规范（必须）

全局视觉统一参考 IntelliJ IDEA New UI：中性灰表面、扁平控件、单一蓝色强调色、细边框与克制的圆角。新增或修改任何面板、控件、弹出层时**必须**遵守本节。

#### 7.6.1 表面层级

从深到浅共五级，上层只允许比下层更浅，禁止反向：

| 层级 | 常量 | 用途 |
| --- | --- | --- |
| 最底层 | `BG_DEEP` | 卷帘画布、输入框深底、滚动条槽 |
| 编辑区 | `BG` | 中央编曲区、底部编辑卷帘背景 |
| 面板 | `PANEL` | 检查器、工具栏、应用栏、状态栏、对话框 |
| 行/卡片 | `PANEL_2` | 卡片、列表行、输入控件、按钮默认底 |
| 悬停/选中 | `PANEL_3` | 悬停表面、选中行、滚动条悬停 |

- 分隔线、边框与网格统一使用 `LINE`；应用栏/工具栏的分隔线使用更深的 `APP_BAR_LINE`。
- **禁止**用纯黑或纯白作为大面积背景；`Color32::WHITE` 只允许用于图标、选中文本与覆盖层高光。

#### 7.6.2 颜色

| 常量 | 值 | 用途 |

| `BG_DEEP` | `(24, 25, 28)` | 画布底色 |
| `BG` | `(30, 31, 34)` | 编辑区 |
| `PANEL` | `(43, 45, 48)` | 面板/工具栏 |
| `PANEL_2` | `(49, 51, 54)` | 卡片/输入 |

| `TEXT_FAINT` | `(122, 126, 133)` | 最弱文本 |

| 项目 | 值 |

#### 7.6.4 字体

- 字体族与全局缩放只在 `theme::setup` 设置；正文 `12.5`、按钮 `12`、小字 `10.5`、等宽 `13`、标题 `16`。
- 控件文字优先使用主题字号；确需强调时用 `RichText::strong()`，不要靠放大字号堆层级。
- 用户可见文案仍为简体中文；数字读数使用等宽字体。

#### 7.6.5 交互状态

| 状态 | 表现 |
| --- | --- |
| 默认 | `PANEL_2` 填充或透明，无边框 |

| 展开（ComboBox/菜单） | `PANEL_3` 填充 + `ACCENT` 描边 |
| 禁用 | 降低文字到 `TEXT_FAINT`，不改变背景色 |

- 选中文本使用 `ACCENT_DARK` 背景 + 白色文字。
- 焦点/选中描边只用 `ACCENT`，不要用其他颜色。
- 禁止使用渐变、发光、投影按钮或大面积高饱和色块；对话框阴影使用 egui 默认即可。

#### 7.6.6 应用栏与弹出层

- 窗口顶部由自绘应用栏 + 工具栏两层组成，背景统一 `APP_BAR`（等同 `PANEL`），中间用 `APP_BAR_LINE` 发丝线分隔。
- 应用栏左侧控件、右侧窗口按钮必须垂直居中；应用栏整条高度参与布局（`horizontal_centered`）。
- 窗口最大化时拖动应用栏必须还原到指针下方再进入拖动，不能只允许“先点还原再拖动”。

## 8. 插件层规范

### 8.1 统一抽象

- 引擎与 UI **禁止**直接调用 `vst` / `vst3-host` 的加载与处理 API；加载必须经过 `PluginHost`，处理必须经过 `PluginRuntime`。UI 仅可以使用运行时暴露的编辑器类型（`vst3-host` 的 `PluginWindow`、`EmbeddedEditor`、`EditorRect`，以及 `plugin::Vst2EditorWindow`）。
- 应用层与引擎 **禁止**直接引用 `plugin/backends/*`；格式差异只允许出现在后端实现中。
- 新格式接入必须同时修改：
  1. `PluginFormat` 枚举；
  2. `PluginRuntime` 变体；
  3. 在 `plugin/backends/` 实现 `PluginBackend`（`info` / `load` / `scan`）；
  4. 在 `PluginHost::standard` 注册后端；
  5. `PluginRef::key()` 的身份字符串；
  6. `process` / `params` / `set_param` / `save_state` / `restore_state` / `has_editor`；
  7. 后端扫描与分类。
- `PluginRuntime::Failed(String)` 是合法的失败态：加载失败必须降级为 `Failed` 并回传状态栏，**禁止** panic。

### 8.2 生命周期

- 加载完成后再读取名称、参数、通道数；VST3 需要 `start_processing()`。
- 保存工程/导出 WAV 前必须调用 `capture_plugin_states` 抓取运行时状态。
- 插件 GUI 参数变化通过轮询检测；实时渲染下参数立即作用于实例，只需刷新界面与保存状态，不需要停播或重新渲染。
- VST3 扫描优先只读 `moduleinfo.json`（`Contents` 或 `Contents/Resources`）；缺少元数据的插件在快速扫描中只标记为未知，由应用层后台调用 `PluginHost::probe_plugin_metadata`（内部 `read_factory_classes`，不调用 `createInstance`）补齐分类，不得把实例化作为常规扫描路径（授权代码可能导致宿主崩溃或弹出启动窗口）。
- 插件实例与编辑器视图必须在**同一线程**创建：`apply_plugin` 在 UI 线程加载实例；打开工程时后台线程创建的实例，首次打开 GUI 前必须经 `ensure_ui_thread_instance`（状态写回 → `invalidate_track_plugins` → UI 线程同步）重建。跨线程 `createView` 会让 Auto-Tune 等插件死锁。
- 编辑器窗口关闭顺序：先 detach 编辑器，再销毁窗口；切换工程时先暂停音频并重置播放状态，再关闭全部编辑器，最后替换工程与插件实例。
- 关闭单个工程窗口时，若工程仍持有插件实例（乐器或效果器），**禁止**在 UI 线程析构这些实例：VOCALOID VSTi / ACE Bridge 等插件会在析构中等待 UI 消息循环，导致永久卡死或 `0xC0000005`。正确做法是先 `AudioRouter::unregister`，再保留引擎（`std::mem::forget` 一个强引用）直到进程结束；只有纯内置乐器的工程才走正常析构（`SurfingApp::drop` 已实现该策略，并写 `window.drop` 阶段日志）。
- 应用退出时不要走正常的 CRT/DLL 卸载：插件 DLL 的 `DllMain(DETACH)` 可能等待已停止的 UI 线程。`Drop` 先隐藏并销毁编辑器原生窗口（跳过 `removed()`）；真正退出整个应用时由 `WindowHost::on_exit`（eframe 在 drop 应用之前调用）直接 `TerminateProcess` 结束进程，`main` 中 `run_native` 返回后的 `TerminateProcess` 仅作为兜底。禁止把耗时或可能阻塞的清理放在 `on_exit` 之后的析构链里。
- 效果链同步必须按插件键增量复用运行时，禁止在新增/删除单个效果器时重建整条链。
- 效果器卡片主体只显示插件原生 GUI：底部卷帘每帧最多自动创建一个内嵌编辑器（`open_inline_editor`），失败槽位记入 `inline_failed`，不得每帧重试。
- VST3 内嵌在效果器卡片（`EditorWindow::Vst3Inline`，主窗口拥有的无边框顶层 `WS_POPUP` 窗口），VST1/VST2、浮动卷帘或内嵌失败时用独立编辑器窗口（双击标题）。内嵌窗口的几何只能由 `ui/effects.rs` 在绘制时通过 `place_inline_editor` 给出（先 `fit_embedded` 等比缩放，客户区坐标转屏幕坐标），帧末由 `finish_inline_layout` 隐藏未摆放的窗口；不得在内嵌模式下按插件请求自由改变窗口尺寸。不得改回 `WS_CHILD`：OpenGL 主窗口会覆盖子窗口。

## 9. 错误处理与提示

- 跨边界（IO、插件、解码、序列化）统一返回 `Result<T, String>`；错误文本使用中文并包含上下文：

```rust
.map_err(|e| format!("创建 WAV 文件失败: {e}"))?
```

- 不引入 `anyhow` / `thiserror` 作为新依赖；保持现有轻量风格。
- **禁止**对用户数据、文件内容、插件返回值 `unwrap()`；仅在测试或已证明的内部不变量处使用 `expect`。
- 互斥锁中毒：
  - 可以继续使用时：`lock().unwrap_or_else(|p| p.into_inner())`；
  - 无法继续时：`if let Ok(...)` / `let Ok(...) else` 后安全返回。
- 实时线程不处理错误：失败就静音/跳过，错误通过同步阶段或状态字段回传。
- 后台错误统一写入 `status` 或 `warnings`，由状态栏展示；`eprintln!` 仅允许用于音频设备错误与测试诊断。
- 不向用户暴露内部实现细节堆栈；保留可操作的原因描述。

## 10. 注释、文档与联动更新

### 10.1 总则（必须）

- **所有注释统一使用中英双语：先中文，后英文。** 适用于 `//!`、`///` 和 `//`。
- `//!` / `///` 的中文块与英文块之间空一行；行内 `//` 注释连续两行即可。中英文必须语义一致，不得只翻译一半。
- 面向用户的字符串（按钮、状态栏、错误提示）仍然只使用中文，不受双语规则约束。
- 注释格式统一、字段齐全、严格执行；新增或修改函数时，必须同时补齐或更新函数头。
- 注释必须与代码同步。修改行为后不更新注释，视为代码缺陷。
- 规范生效后：新建文件必须完全符合；修改存量文件时，至少补齐该文件头与本次改动涉及函数的函数头。
- 涉及实时安全、DPI、事件表重建、线程生命周期的代码，必须用双语写明约束。
- **禁止**保留被注释掉的旧实现；需要历史请用版本控制。
- **禁止**写“显而易见”的复述式注释；注释解释“为什么、约束、副作用”，不是重复代码字面。

### 10.2 文件头格式（必须）

每个 `.rs` 文件开头必须按行声明：**所属功能模块、文件用途、函数清单**。函数清单必须覆盖该文件全部非测试函数；私有 getter/setter 可按职责合并为一行，但函数名必须出现。

```rust
//! 所属模块：app / 文件操作
//! 文件用途：
//! - 新建、加载、保存工程与 WAV 导出。
//! - 轮询后台加载/保存线程的结果。
//! 函数清单：
//! - `new_project`：重置为空白工程并清理编辑状态。
//! - `open_project_dialog`：在后台线程打开原生文件对话框。
//! - `poll_load_project`：接收加载结果并在下一帧应用。
//! - `save_project` / `save_project_as`：抓取插件状态并后台写入 `.sfsd`。
//!
//! Module: app / file operations
//! Purpose:
//! - Create, load and save projects; export WAV.
//! - Poll background load/save workers.
//! Functions:
//! - `new_project`: reset to an empty project and clear editing state.
//! - `open_project_dialog`: open the native file dialog on a worker thread.
//! - `poll_load_project`: receive and apply the loaded project one frame later.
//! - `save_project` / `save_project_as`: capture plugin state and write `.sfsd` in the background.
```

- `mod.rs` 也必须声明所属模块、用途与导出项/函数清单。
- 文件用途变化、增删函数、函数职责变化时，必须同步更新文件头。

### 10.3 函数头格式（必须）

每个函数（含私有函数、关联函数、trait 实现）开头必须有函数头，至少包含以下字段：

```rust
/// 所属模块：audio::engine / 实时渲染
/// 功能：渲染单个 block：事件游标 → 乐器 → 音频片段 → 效果链 → 主总线。
/// 输入：
/// - `out_l`：左声道输出缓冲，长度为本块帧数。
/// - `out_r`：右声道输出缓冲，长度与 `out_l` 相同。
/// - `advance`：是否推进走带与时间轴事件（试听时为 `false`）。
/// 输出/副作用：写入 `out_l`、`out_r`；`advance` 时推进 `position_beats`；更新电平峰值。
/// 复杂度：时间 O(frames × 轨道数 + 本块事件数)，空间 O(1)，复用 scratch 缓冲。
///
/// Module: audio::engine / realtime render
/// Purpose: Render one block: event cursor → instruments → audio clips → effect chain → master bus.
/// Inputs:
/// - `out_l`: left output buffer, length = frames in this block.
/// - `out_r`: right output buffer, same length as `out_l`.
/// - `advance`: whether to advance the transport and timeline events (`false` for audition).
/// Outputs / side effects: writes `out_l` and `out_r`; advances `position_beats` when
/// `advance` is true; updates peak levels.
/// Complexity: O(frames × tracks + events in block) time, O(1) space using scratch buffers.
```

字段规则：

| 字段 | 要求 |
| --- | --- |
| 所属模块 | 写到具体子模块，如 `app / 文件操作`、`render / 调度`，不能只写 `app` |
| 功能 | 一句话说明“做什么 + 为什么/约束” |
| 输入 | 逐个列出参数名、类型含义、单位、合法范围；无参数写“无” |
| 输出/副作用 | 返回值；写入了哪些缓冲/字段；是否修改工程、缓存、UI 状态；无则写“无” |
| 复杂度 | 计算函数必须写；非计算函数写 `O(1)` 或 `不适用` |

- 简单 getter/setter 可使用紧凑形式，但五个字段仍必须齐全：

```rust
/// 所属模块：audio::engine / 状态查询
/// 功能：返回当前播放位置。
/// 输入：`self`。
/// 输出/副作用：播放位置，单位 beat；不修改状态。
/// 复杂度：时间 O(1)，空间 O(1)。
///
/// Module: audio::engine / state query
/// Purpose: Return the current playhead.
/// Inputs: `self`.
/// Outputs / side effects: playhead in beats; no state change.
/// Complexity: O(1) time, O(1) space.
```

- 测试函数使用一行双语注释说明覆盖行为，可省略复杂度：

```rust
/// 覆盖：音符编辑 bump revision 后事件表必须重建。
/// Covers: the note event table must rebuild after a note edit bumps the revision.
#[test]
fn note_events_rebuild_when_a_note_edit_bumps_revision() { ... }
```

### 10.4 复杂度标注（计算函数必须）

- 适用对象：音频混音、自动化求值、音符事件、渲染、扫描、布局计算、序列化、文件解析等。
- 必须定义复杂度中的变量含义（如 `n` = 自动化点数量、`frames` = 本块帧数），不能只写 `O(n)`。
- 格式：中文 `复杂度：时间 O(...)，空间 O(...)`；英文 `Complexity: O(...) time, O(...) space`。
- 需要说明最坏情况/均摊情况时明确标注，例如 `均摊 O(1)`、`最坏 O(n)`。
- UI 绘制函数按每帧可见元素计：`复杂度：每帧 O(可见轨道数 + 可见片段数)`。
- 文件/插件扫描按文件数计：`O(目录项数 × 目录深度)`。

常用复杂度标注参考：

| 函数类型 | 标注示例 |
| --- | --- |
| `note_signature` | 时间 O(片段数)，空间 O(1) |
| `evaluate_automation` | 时间 O(n)，空间 O(1)，`n` = 自动化点数量 |
| `render_chunk` | 时间 O(frames × 轨道数 + 本块事件数)，空间 O(1) |
| `refresh_events` | 时间 O(n log n)，空间 O(n)，`n` = 本轨音符数 |
| `collect_events` | 时间 O(本块事件数)，空间 O(本块事件数) |
| `sync_project` | 时间 O(轨道数 + 片段数 + 音符数 log 音符数)，插件实例化另计 |
| `scan_vst3` / `scan_legacy_vst` | 时间 O(目录项数 × 最大递归深度) |

### 10.5 行内注释

- 行内注释同样先中文、后英文，各占一行：


## 11. 测试规范

- 单元测试放在同文件底部：

```rust
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn cache_key_changes_when_a_note_edit_bumps_revision() {
        // arrange / act / assert
    }
}
```

- 测试名使用 `snake_case`，描述“行为 + 条件”，不要 `test1`、`works`。
- 一个测试只验证一个行为；失败信息要能定位原因（`assert!(..., "peak={peak}")`）。
- 新增/修改以下内容时**应当**补测试：
  - `Project` / 容器格式字段（序列化往返、旧版本拒绝/兼容）；
  - 音符事件表与 revision 重建；
  - 播放/定位/循环/自动停止；
  - 音量/声像/弯音等会影响声音的规则；
  - WAV 导出与音频解码边界。
- 依赖本机插件或硬件的测试必须 `#[ignore = "原因"]`，并在运行时检测缺失资源后直接返回，不得让 `cargo test` 失败。
- 测试不得依赖网络、真实用户目录或固定时间；临时文件用 `std::env::temp_dir()` 并在结束时删除。
- 不引入 GUI 截图测试；UI 逻辑尽量下沉为可单测的纯函数。

## 13. 常见扩展操作手册

### 13.1 新增工程字段

1. 在对应模型结构体加字段，并加 `#[serde(default)]`。
2. 更新 `Default`（若需要非零默认值，写 `default_xxx` 函数）。
3. 若影响声音，确保相关编辑路径调用 `bump_track_revision` / `bump_clip_revision`。
4. 若参与音符事件，更新 `note_signature` 并补测试。
5. 若格式不兼容，递增 `CURRENT_PROJECT_VERSION`。
6. 补序列化往返测试，并更新技术文档的数据模型章节、关键常量与框架工作流。

### 13.2 新增控制器类型

1. `core/model/controller.rs`：新增 `ControllerKind` 变体、`ALL`、`label`、`center`、`display_value`。
2. `ControllerLanes`：新增字段、`get` / `get_mut` 分支，保持 serde 默认。
3. 引擎：在 `apply_controller_state` 或混音路径消费该控制器。
4. UI：控制器卷帘、检查器、轨道子轨显示自动复用枚举列表。
5. 补插值与事件表重建测试。

### 13.3 新增内置乐器

1. 在 `audio/synth/` 新建 voice 模块，导出类型并在 `synth/mod.rs` 注册。
2. 在 `core/model/instrument.rs` 增加设置结构体与 `InstrumentRef` 变体、`label`、`key`。
3. `audio/engine/mod.rs` 的 `InstrumentRuntime` 与 `ensure_instrument` 接入。
4. 检查器 UI 增加设置控件。
5. 保证 `all_notes_off` / 参数更新 / 采样率变化路径完整。

### 13.4 新增 UI 面板或卷帘

1. 新文件放 `ui/`，方法命名 `ui_xxx`，通过 `impl SurfingApp` 实现。
2. 共享类型放 `ui/mod.rs`；几何/常量放同目录 `layout.rs` 或 `helpers.rs`。
3. 只读 `ui_*` 快照；需要写工程时调用 `app` 方法并 `mark_dirty`。
4. 若进入底部卷帘，扩展 `BottomView` 与 `app/panels.rs` 的切换逻辑。
5. 若需要独立窗口，复用现有视口模式：工程窗口由 `WindowHost` 创建，浮动卷帘用 `RollWindow` + `show_viewport_immediate`；不新建并行窗口体系。

### 13.5 新增命令或快捷键

1. 命令实现放 `app/edit.rs`、`app/files.rs`、`app/transport.rs` 等对应文件。
2. 快捷键不再写死在 `app/input.rs`：在 `app/shortcuts.rs` 的 `ShortcutAction` 增加动作、稳定 id、中文名称、分组与默认绑定，再在 `handle_keyboard` 中调用 `self.settings.shortcut_pressed(ctx, ShortcutAction::Xxx)`。
3. 绑定统一由 `AppSettings::shortcuts` 持久化；禁止在帮助窗口、菜单或工具栏另写一份快捷键文本，统一读取 `AppSettings::shortcut_label`。
4. 输入框获得焦点时（`egui_wants_keyboard_input()`）必须跳过快捷键；默认绑定不得与已有动作冲突（`shortcut_conflict` 与默认值测试会检查）。
5. 改变工程时按手势/键盘规则处理撤销。
6. 更新帮助窗口、`doc/关键常量.md` 的快捷键行与项目简介。

### 13.6 新增后台任务

1. 使用 `std::sync::mpsc::channel`，`Receiver` 存 `SurfingApp` 字段。
2. 线程只回传 `Result` 数据，不接触 UI。
3. 在 `ui()` 前段调用 `poll_xxx`，非阻塞 `try_recv`。
4. 需要“至少显示一帧提示”时，复用 `loading_until` 模式。
5. 任务结果应用前校验 epoch/路径，避免覆盖新状态。

### 13.7 新增工程格式后端

工程格式采用「运行时框架 + 转译后端」，新增格式时**禁止**在 `app/files.rs` 增加格式分支，也**禁止**后端直接操作应用状态：

1. 在 `core/project_runtime/` 下新建后端文件夹（如 `myformat/`）。
2. 实现 `ProjectCodec`：`info` 返回 `CodecInfo`（标识、名称、扩展名、读写能力）；`decode` 把外部格式转译为 `ProjectSession`；可写格式再实现 `encode`。
3. `decode` 必须只读源文件；外部格式在会话中设置 `ProjectSource::Imported { format }`，保证只能另存为 `.sfsd`。
4. 在 `ProjectRuntime::standard` 注册后端；注册顺序即未知扩展名的探测顺序。
5. 应用层只调用 `ProjectRuntime::open_project` / `save_project` / `translate_project`，不得直接引用该后端模块。
6. 为后端补单元测试：成功解码、损坏文件拒绝、扩展名分派、可写格式的往返。
7. 更新 [技术文档](./技术文档.md) 9.5、[框架工作流](./框架工作流.md) 模块地图与文件索引、[关键常量](./关键常量.md)（如有新阈值）。

### 13.8 新增插件格式后端

1. 在 `core/model/plugin.rs` 增加 `PluginFormat` 变体。
2. 在 `plugin/runtime.rs` 增加对应的 `PluginRuntime` 变体（或复用统一运行时），实现参数、状态、MIDI 与处理。
3. 在 `plugin/backends/` 新建后端文件，实现 `PluginBackend`：`info` 返回 `PluginBackendInfo`，`load` 返回 `PluginRuntime`，`scan` 返回 `ScannedPlugin`。
4. 在 `plugin/host.rs` 的 `PluginHost::standard` 注册后端。
5. 应用层与引擎只调用 `PluginHost::load_plugin` / `scan_plugin_format` / `scan_plugins`。
6. 补测试：加载失败降级、扫描分类、格式分派；依赖真实插件的测试必须 `#[ignore]`。

### 13.9 新增音频文件格式后端

1. 在 `audio/io/` 下新建格式文件夹（如 `flac/`）。
2. 实现 `AudioCodec`：`info` 返回 `AudioCodecInfo`；只读格式实现 `decode` 与 `duration_seconds`；可写格式再实现 `encode`。
3. 解码结果统一为 `AudioFile`（左右声道 + 峰值包络）；不得直接修改 UI 或工程状态。
4. 在 `AudioRuntime::standard` 注册后端。
5. 应用层只调用 `AudioRuntime::import_audio` / `audio_duration_seconds` / `export_audio` / `export_project`。
6. 补测试：解码、损坏文件拒绝、时长读取、可写格式的导出。

### 13.10 新增平台后端

1. 在 `src/platform/backends/` 新建 `<系统>.rs`，实现 `PlatformBackend` 的十个方法（`info` / `caps` / 五个存储目录 / 三个对话框 / `import_file` / `export_copy` / `exit_process`）；平台没有对应能力时用 `PlatformBackend` 的默认实现或返回 `None`。
2. 在 `platform/backends/mod.rs` 用 `#[cfg(target_os = "...")]` 声明并注册到 `selected()`。
3. 能力差异写成 `PlatformCaps` 字段（`multi_window`、`window_drag`、`native_file_dialog`、`plugin_hosting`、`native_plugin_editor`、`system_audio_systems`、`gpu_ui_render`、`crash_trap`），**禁止**让业务层自己判断系统。
4. 需要平台专属初始化（如安卓的应用私有目录、`JavaVM`/`Activity`）时，提供 `install_*` 函数，由该平台的二进制入口在创建窗口前调用。
5. 若平台无法支持多窗口，`WindowHost` / `app/rolls.rs` / `app/settings.rs` 会按 `multi_window` 走单窗口路径，无需再改 UI。
6. 新增可执行入口时放到 `platforms/<系统>/`（独立 crate + 打包脚本），不要往 `src/main.rs` 堆平台分支。
7. 更新 [技术文档](./技术文档.md) 1.4、[关键常量](./关键常量.md) 第 11 节、[框架工作流](./框架工作流.md) 模块地图。

JNI 桥（安卓 SAF 为范例）的额外约束：

1. **阻塞等待只能在业务线程**：UI 线程就是 Android 主线程，阻塞它会导致 `onActivityResult` 永远回不来。
2. **回调入口用全局引用**：Rust 只持有 `JavaVM` + `GlobalRef`，跨线程调用前 `attach_current_thread`；不要缓存 `JNIEnv`。
3. **必须清理挂起的 Java 异常**：jni-rs 把异常变成 `Err` 但不清除，失败分支统一调用 `clear_exception`，否则下一次 JNI 调用或线程 detach 会 abort 进程。
4. **字节复制走文件描述符**：用 `ParcelFileDescriptor.detachFd` 交给 `File::from_raw_fd`，禁止逐字节过 JNI。
5. **Java 子类必须显式加载库**：NativeActivity 只 `dlopen`，需要在静态初始化里 `System.loadLibrary(<lib_name>)` 才能解析原生方法，库名与清单 `android.app.lib_name` 保持一致。
6. **排障埋点用 `__android_log_write`**（tag 固定、级别 INFO），不要依赖 `println!`。
7. **失败要能降级**：平台桥不可用时返回中文原因或 `None`，由业务层回退到沙箱路径，不要 panic。
